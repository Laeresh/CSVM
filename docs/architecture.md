# Godot project — per-module implementation notes

Deep implementation notes for `CrimsonSkies/src`, moved from CLAUDE.md on 2026-07-18: what each module does, why the implementation is the way it is, verified diagnoses, TUNE constants, and dead ends not worth re-chasing. **Read a module's bullet before modifying it, and update the bullet in the same turn as a code change.** The compact module index, build/run commands, and CLI flags reference live in CLAUDE.md.

- `src/Mech3/GameZ.cs` — loads a mech3ax GameZ extraction (ZIP or unpacked dir): nodes.json / meshes.json / materials.json into plain C# objects. Parses World partition refs, per-corner vertex colors, per-mesh `lights` arrays (point-sprite lights: the night sky's stars, nav/tower beacons), and the per-polygon **draw priority** (v0.6.1 JSON key `unk04`; upstream mech3ax has since renamed it `priority` — both keys accepted). Each GameZNode records its flat `Index` in nodes.json (= the original's draw order, used as the cross-node layering tie-break). For the **World** node it also parses the map's `area` ground-plane bounds (`{left=xMin, right=xMax, top=zMin, bottom=zMax}` in Godot world coords → `HasArea`/`AreaLeft/Top/Right/Bottom`) and the partition grid dimensions (`PartitionCols`/`PartitionRows`) — WorldBuilder's map-edge continuation uses these to size and place the mirrored border terrain.
- `src/Mech3/TextureArchive.cs` — texture lookup over an unzbd texture ZIP **or an unpacked directory** of those PNGs, handles the two name quirks below. Exposes `LastHadAlpha` and `LastAlphaIsSoft` — the latter classifies the alpha channel from the pixels: "soft" means a 0.5-threshold scissor cutout would erase the texture or shred it (max alpha < ~140/255, or partial alpha dominating with few near-opaque texels). True for the original's translucent overlays: baked shadow decals (`bldgshadow`/`abld_shadow`/`lkshad*` peak at ~125/255 — fully invisible under scissor; `thin_shadow` at 155 became solid-black wedges), clouds, prop blur, waterfalls, smoke. **Missing-texture logging (Run-2 item 1):** each unresolved name is reported **once** (a `_reportedMissing` HashSet) as a plain `GD.Print` line — never `GD.PushWarning`, which in Godot .NET prints a full managed stack trace per call and buries real errors; `MissingTextures` exposes the deduped set for PlaneViewer's one-line end-of-build summary. A static `KnownAbsentFromGameData` set (`pir_spinner` — a pirate-zeppelin spinner disc referenced by every chapter's gamez; `barngrill` — C5; both verified absent from the whole extraction, so the original engine tolerated them too) is surfaced via `IsKnownAbsent`: SceneBuilder renders those as neutral gray (0.5) instead of the debug **magenta**, which now flags only genuine name-resolution failures (our bug), not data gaps.
- `src/Mech3/SceneBuilder.cs` — shared GameZ-subtree → Node3D/MeshInstance3D builder: n-gon triangulation, material+mesh caches, keeps only nearest LOD, takes a skip predicate. **Draw-order replication → depth bias (the z-fighting fix):** the original layers coplanar geometry by (1) per-polygon priority, then (2) draw order — polygon list order within a mesh, node order across meshes (nodes.json is a DFS serialization = draw order; later wins under DX7 LESSEQUAL). All three are mapped to a scale-invariant polygon offset: every non-billboard surface uses a generated ShaderMaterial whose vertex shader scales the view-space position toward the eye by `depth_bias + node_bias` — identical projected position, nearer depth. Meshes are split into one surface per (material, priority) in first-occurrence order; `depth_bias` = priority × `DepthBiasPerLevel` (2e-4, TUNE) + surfaceRank × `SurfaceRankBias` (2e-6, capped at rank 5 — the within-mesh tie-break: gyro canopy lattice over fuselage skin, tile roads over tile grass); `node_bias` (an `instance uniform`, set per MeshInstance3D — needs Forward+) = GameZNode.Index × `NodeOrderBias` (5e-8 — the cross-node tie-break: airfield apron detail over base tile, road decals over rail decals). **Instance-uniform buffer (Run-2 item 2):** Godot allocates 16 vec4 slots per instance carrying any instance uniform, so the default 65536-slot global-shader-variable buffer caps at ~4096 mesh instances — C4 (4234) and C5 (4746) overflowed it, flooding "Too many instances" errors *and silently dropping `node_bias`* on the overflow (decals z-fight again). `project.godot` now sets `rendering/limits/global_shader_variables/buffer_size=262144` (~16384 instance slots, a 4 MB GPU buffer); C1 (3481) always fit. Negative priorities push away (skydome −49, zeppelin gasbags −10, pilot body −1). The shader mirrors StandardMaterial3D's look (vertex-color × texture albedo sampled `filter_linear_mipmap_anisotropic` — 16× via `project.godot`'s `textures/default_filters/anisotropic_filtering_level=4`, the Run-2 item-2 fix for grazing-angle ground blur; cull disabled, unshaded when fullbright, Burley/GGX + roughness 0.85/metallic 0/specular 0.5 when shaded; opaque/scissor/blend fragment variants) and is cached per feature combo; materials cache per (material, priority, cappedRank). **Billboard (cloud-sprite) materials** are a separate `ShaderMaterial` (`GetBillboardShader`, cached per blend/scissor in `_billboardShaderCache`): the same hand-rolled keep-scale billboard as CloudPuffs (`MODELVIEW_MATRIX` rebuilt from `INV_VIEW_MATRIX` columns + `MODEL_MATRIX[3]`), `COLOR × albedo`, `blend_mix`/`depth_draw_never` for the soft-alpha clouds — **no depth bias** (free-floating sprites have nothing coplanar to fight) but **carrying the same cylindrical fog term** as the world shader, so distant sprites fade into the fog wall instead of punching through as crisp white (Run-2 item 4). It declares **no** `csky_fog_on` instance uniform (clouds always fog, and omitting it keeps the sprites off the instance-uniform buffer — see item 2). This replaced the old fog-immune `StandardMaterial3D` billboard. **Sidedness:** `cullBackfaces: true` (used by PlaneBuilder) additionally splits surfaces by the per-polygon SHOW_BACKFACE flag (`unk2` in v0.6.1) and backface-culls the single-sided ones — `cull_front`, because the source's visible side is where the vertex loop runs counter-clockwise (right-handed) while Godot front faces are clockwise. This is what hides the autogyro's inward-facing interior frame lattice (`agyro_cock1` bulkheads in the `tail` mesh) so its aft fuselage shows yellow skin with openings, like the original. No plane node has a mirrored (negative-determinant) transform, so the blanket cull direction is safe. The world builder still renders everything double-sided (cull-disable) — switching it to per-polygon culling is a candidate cleanup, unvalidated. Known accepted limit: the tie-break hierarchy is approximate for extreme node-index spans (a prio-0 node >~4000 indices later can out-bias a prio-1 overlay; no such pair observed in C1), and cross-node deltas of ±2 indices sit at interpolation-noise level (one 6-poly rail/transition patch NE of the C1 bridges). **Alpha handling:** textures whose alpha is "soft" (see TextureArchive.LastAlphaIsSoft) alpha-blend automatically — this is what renders the baked shadow decals correctly (they were invisible or solid black under scissor) — in addition to the caller's explicit `blendTexture` predicate; other alpha textures scissor (hard cutout — fences, trees, railings). `fullbright: true` renders unshaded (texture × baked vertex color — the original engine's world look). `generateCollision: true` attaches a static trimesh collider (`StaticBody3D` + `ConcavePolygonShape3D`, cached per mesh, `BackfaceCollision = true` because the source winding is inconsistent) to each mesh; a `collisionSkip` predicate exempts subtrees (renders but not solid). The explicit `blendTexture(name)` predicate still promotes chosen alpha textures to `Alpha` blending on top of the automatic soft-alpha rule (WorldBuilder passes it for the clouds, PlaneBuilder for the `*blur*` discs — both are also caught by the classifier, so the predicates are now belt-and-braces). Only consulted for textures that actually carry alpha, so opaque cloud/sky (`cloudlayer`/`sky*`) is unaffected. A second optional predicate `billboardTexture(name)` renders the matching meshes as camera-facing billboards (the cloud *sprites* — flat 2D cards in the source): the material gets `BillboardMode.Enabled` and the mesh is recentered on its own quad centroid (offset stored per mesh, re-applied as each instance's local position) so the billboard pivots at the quad center, not the node origin — the source sprite quads sit up to ~650 units off their origin, so without recentering they would swing around as the camera turns. Recentering also tightens transparent sorting (each sprite sorts by its true center). Meshes with `lights` additionally get a POINTS-primitive instance rendered by a dedicated point-sprite shader (reworked 2026-07-18 on user feedback — the original's lamps are camera-oriented soft glow sprites, star-like and clearly brighter than the old fixed 3 px dots): additive soft radial glow (gaussian core, no hard cutoff, ×1.6 gain TUNE), distance-sized from a ~6 m world diameter (TUNE) clamped to [3 px, `MaxSizePx`]; per-light **decoded** params drive it — light `unk08` = size scale (0 default / 1 / 2 / 5 = the lighthouse), `unk64` = max sprite px (30), `unk68`/`unk52` = visibility range in metres (1500/2500/4000), the range applied as a smoothstep distance fade which also stops in-map beacons punching through the fog from kilometres outside (the old item-7 nit). One POINTS surface per (size, range) group per mesh, materials cached per param set; an `instance uniform csky_light_fade` opts the camera-anchored skydome's stars out of the range fade (they sit ~22 km out; `WorldBuilder.DisableLightRangeFade`) — verified: harbor lamps/blue pier lights/lighthouse render as bright soft glows, stars + moon intact above the deck, `--fly` clean. Never collidable/shadowed; black effect-prototype lights add nothing and stay invisible. **Glow flare sprites (same day, the user's real complaint):** the visible lamps are not mesh-lights but **single-quad flare MESHES** (`refinery_flare` 16 m + `gen_flare_yellow` 4 m on `oil_liteflare.tif`, `docklight_flare` 9.6 m blue on `dock_liteflare.tif`, lighthouse `litehsflare` 19.2 m on `poleflare.tif` — full soft-alpha ramps on black) that the original camera-billboards; world-fixed they render edge-on/skewed (the user's crop: a squashed quad with the texture's ray tips at its corners). A `glowTexture` predicate (WorldBuilder passes `IsFlareTexture` = name contains "flare") routes them to the billboard shader with a `glow` variant bit: always alpha-blend (scissor would cut the soft ramp into a hard star), fog term kept, **no `csky_world_light` night dim** (a lamp is a light source). **Scoped per-MESH via `IsGlowSpriteMesh` — single-polygon all-flare meshes ONLY** (and the collision exemption mirrors it): the C1-C5 scan found the same flare textures on polys INSIDE regular geometry (C4 world Brigand wing meshes carry an `oil_liteflare` poly; the shared 76-poly effects-atlas mesh has flare polys) where whole-mesh recenter/billboard would distort the geometry, and 6-poly `flare_green` STRINGS 22–72 m long that would swing around a common centroid — both keep static rendering (per-poly billboard pivots are the faithful upgrade, backlog). Verified: refinery lamps/pier lights render as camera-facing star sprites matching the user's original-game crop; C1 colliders 2670→2566 (flare quads no longer solid); C1/C4/C5 fly-smokes clean. **Distance fog:** the original's fog volume is a vertical **cylinder** around the camera, not a sphere (user-diagnosed 2026-07-17): the generated shader mixes ALBEDO toward the fog color by **horizontal** (x/z) camera distance, scaled by an altitude fade — full fog below `FOG_ALTITUDE`[0], none above [1] — so the overcast deck/sky overhead stays clear instead of graying out (zone1's altitudes 970→1047 = exactly cloud-band bottom → whiteout-band centre; zone2's 4000→5000 > flight ceiling = night fog at every flyable altitude). Implemented per-fragment: `INV_VIEW_MATRIX` lifts the view-space VERTEX back to world space for `distance(world.xz, CAMERA_POSITION_WORLD.xz)` and the fragment-altitude fade. Driven by three **global** shader params `csky_fog_color`/`csky_fog_range` (near/far)/`csky_fog_alt` (full-below/none-above) that PlaneViewer registers + sets once per flight from weather.json (no-op range when not flying, so static viewing is unfogged), plus a per-instance `csky_fog_on` (default 1) so the caller can opt a subtree out — WorldBuilder sets it 0 on the camera-anchored skydome, whose below-horizon skirt would otherwise fog solid gray at ~22 km. The aircraft shares the term but is a no-op at chase distance (always within the near range). **Fullbright world brightness (Run-2 item 6, 2026-07-18):** two coupled fidelity fixes on the `!shaded` branch only (shaded/plane surfaces keep raw COLOR + full brightness). (1) **Gamma-space vertex modulate** — the original is a DX7 fixed-function engine whose `D3DTOP_MODULATE` multiplied texture × baked vertex colour in *gamma* (sRGB) space; we render in linear space, so our `linear_texture × COLOR` came out too bright/desaturated wherever the baked colour is < 1 (baked shadow/AO — 30% of the C1 world's corners, min 0). The fragment now linearises COLOR before the multiply (`csky_srgb_to_linear`, the shared `SrgbToLinearFn` const, Godot's exact sRGB EOTF), reproducing the gamma-space product — fixes the terrain's washed-yellow → saturated-green (measured greenness G−R +3.6 → +16.9 vs the original's +18…+23). (2) **SUNLIGHT dimming** — a global `csky_world_light` scalar (default 1.0, declared only when `!shaded`) multiplies ALBEDO **before** the fog mix (so FOG_COLOR is unaffected); PlaneViewer sets it per-flight from `WeatherState.WorldLight` (the mission's SUNLIGHT), fed already-linearised so this linear-space multiply lands the dimming in gamma space too (a raw linear ×0.80 only reaches 210→190; gamma-space lands the deck 210→169, matching the reference). Together: deck/sky 168 vs 169, terrain mean 59 vs ~57, fog 170 vs 176. The same two fixes are duplicated in the cloud-billboard shader and Clutter's tree shader (all three emulate the original's unshaded world pass); the cloud deck (`cloudlayer`, 100% white vertex colours) is unchanged by the modulate and rides only the SUNLIGHT dim.
- `src/Mech3/PlaneBuilder.cs` — thin wrapper: builds one aircraft, skips cockpit/destroyed/shadow subtrees, plus every plane's `*_hook` skyhook subtree (`blood_hook`, `kest_hook`, `gyro_hook`, … — retracted by default: each `*_hook.json` anim's RESET_STATE deactivates the group + its arm/door nodes; `player_hook.json`'s `player_extend_hook` extends it only for zeppelin docking). Shaded (dynamic lighting). Builds its SceneBuilder with `cullBackfaces: true` (see SceneBuilder — aircraft interior structure must be backface-culled or it paints over the skin). **Damage panels (fixed 2026-07-16):** every player plane's top LOD has a `player_damage_on` group holding `pdp1`–`pdp8` (damage-state panels, `damage1/2.tif` torn-skin textures — start INACTIVE per `player_destruct_reset.json`'s `plane_reset` anim) *and* `pdp2_h`/`pdp3_h` (the matching HEALTHY panels, ACTIVE at reset — real airframe sections: the Bloodhawk's wingtips, the Kestrel's outer wing thirds with the roundels). PlaneBuilder skips `pdpN`/`pcdpN` (digits-only suffix) but renders `pdpN_h`; the sibling `player_damage_off` group (intact duplicates `pdp2i`/`pdp3i`, the original's vehicle-damage-detail-OFF variant) is skipped wholesale. The old code skipped `player_damage_on` entirely, which amputated the `_h` panels (Bloodhawk flew without wingtips, Kestrel without outer wings). Propellers are handled via `PropParts` (below): the default exterior build keeps the still `staticpropN`/`staticrotorN` disc and hides the blur layers; the `spinningProps: true` build (free flight) does the reverse — hides the static disc, keeps the `propN`/`propNb` (+ autogyro `rotorN`/`rotorNb`) blur layers for a `PropAnimator` to spin (`nitropropN` stays hidden either way — no nitro system yet; hiding it in flight is also load-bearing visually — it is a NON-spinning blur disc, so leaving it in overlays a fixed disc on the spinning ones whose edge paints a 1px seam that shimmers as the camera moves). It also passes SceneBuilder a `blendTexture` rule for the blur textures (`*blur*` → `rotorblur`/`zeprotorblur`): those discs are soft sprites whose alpha peaks at ~26%, so the default 1-bit AlphaScissor cutout erased them entirely (looked like a missing/frozen prop) — alpha-blending them (as with the clouds) restores the translucent spinning-disc, clearly visible against bright sky and subtly over dark terrain, as in the original. **Wing-light flares (2026-07-16):** after building, `Build` collects each plane's `wing_flare1`/`wing_flare2` wingtip sprite quads (see `WingLights`), builds them **hidden** (the original's `wing_light.json` RESET_STATE starts them off), and re-skins each glow quad (`oil_liteflare.tif`) with a shared additive, camera-facing **billboard** material tinted the data's warm amber (LIGHT_STATE COLOR 0.88/0.78/0.36) — the source quads are one-sided, so previously the flare only showed from behind. The collected nodes are exposed as `WingFlares` for a `WingLightBlinker` (flight only) to flash; the static viewer leaves them off. Only planes with the nodes get flares — the Bloodhawk and autogyro have none in the data. **Run-2 item 10c/d:** flight builds — and static builds passing the `damagePanels: true` ctor flag (the viewer's `--damage` lab; `_withDamagePanels = spinningProps || damagePanels`) — construct the exterior `pdpN` torn-skin panels **hidden** instead of skipping them (the plain static viewer still skips; `pcdpN` cockpit panels always skipped) and collect them + their `pdpN_h` healthy twins as `DamagePanels` for `DamageVisuals` to flip; `BuildDestroyed(rootName)` builds the plane's `destroyed` wreck-piece subtree (skipped by `Build`) with the accumulated plane-root→destroyed transform chain baked into the returned root — `CrashBreakup` scatters its children on a crash.
- `src/Mech3/PropParts.cs` — classifies a plane's propeller/rotor subnodes by name (`staticpropN`/`staticrotorN`, `nitropropN`, `propN`/`propNb`, `rotorN`/`rotorNb`) and gives each spinning kind its local spin axis + rate. Rates are the `XYZ_ROTATION` values from the original's prop animations — `plane_props.json` (a single shared "warhawk" `spinprops` def that vehicle.json wires to every plane via `spin_props_anim`) and `autogyro.json` (`agyro_rotors`, the autogyro's override): propeller discs spin about local **Z** (the nose axis) — `propN` −220, `propNb` +60 (a fast blur disc + a slower counter-rotating ghost); the autogyro's overhead `rotorN` spins about local **Y** — `rotor1` +165, `rotor1b` −60. Axis choice is corroborated by mesh geometry (prop discs lie in the XY plane, the rotor disc in XZ). Units are undecoded in the source; treated as degrees/second — a visual TUNE (a blur disc reads as spinning at any smooth rate; the real prop turns a slow ~0.6 rev/s, not fast).
- `src/Mech3/ControlSurfaces.cs` — control-surface *mesh*-node classifier + hinge axes (M2-polish item 7). Every player plane names its movable surfaces uniformly in planes.zbd: the deflecting mesh node (`l/r_aileronN`, `l/r_elevatorN`, `l/r_rudderN`, the Fury's `l/r_rudder_rotate`) hangs under a hinge parent group (`lailerN`/`railerN`, `lft_elev`/`rt_elev`/`l_elev`/`r_elev`, `lrudderN`/`rrudderN`, bare `l_rudder`/`r_rudder`, the Peacemaker's `r_rudder1b`) whose transform places/orients the hinge line; the parent names deliberately do NOT classify (rotating both would double the deflection — digits are required on the bare `l_rudder` form for exactly this reason). Hinge axes corroborated against mesh geometry: aileron/elevator meshes are spanwise slabs (wide local X, chord aft +Z, hinge through the node origin) → hinge about local **X**; rudders are vertical fins (flat in X) → local **Y**. No zrdr anim/reader defines deflection — the original drives these procedurally, so angles/rates are TUNE in ControlSurfaceAnimator, not data.
- `src/Mech3/WingLights.cs` — the single source of truth for wingtip nav lights: the flare-node predicate (`wing_flare1`/`wing_flare2`), the glow texture (`oil_liteflare`), the warm-amber flash color (`0.88, 0.78, 0.36` = `wing_light.json`'s LIGHT_STATE COLOR), and the blink period (1.5 s = its LOOP SEQUENCE_OFFSET). PlaneBuilder uses it to hide + re-skin the flares (see PlaneBuilder); `WingLightBlinker` uses it to flash them. Documents that `oil_liteflare` is also used by a few real airframe meshes, so the additive-billboard treatment is scoped to the flare **nodes** by name, not routed through the texture (else those meshes would be wrongly recentered/billboarded).
- `src/Mech3/WorldBuilder.cs` — builds a whole chapter world (fullbright): World children + partition-referenced subtrees; skips `horizon` (built separately, see below), `fvol*` (flight-boundary volumes), `dzpaths` (path ribbons). A shared `IsCloudOrSkyTexture` predicate (`cloud*`/`sky*`) classifies cloud/sky surfaces by **texture** (node names are unreliable; cloud layers appear under generic names like `g27517`), and two callers use it: `collision: true` (passed only when flying) generates static colliders for solid geometry but exempts those surfaces (non-solid), and it is passed to SceneBuilder as the `blendTexture` rule so the clouds alpha-blend instead of scissor. Only cloud1/cloud2 (RGBA) actually blend; the opaque Sky1.tif skydome walls and `cloudlayer` deck have no alpha and stay opaque (which keeps the 2.5× camera-anchored dome depth-writing behind the blended clouds). A narrower `IsCloudSpriteTexture` (`cloud*` but not `cloudlayer`) is passed as SceneBuilder's `billboardTexture` so the soft cloud sprites (cloud1/cloud2 — vertical 2D cards) face the camera, while the horizontal `cloudlayer` deck sheets stay flat. **Cloud deck split:** the `cloudlayer` deck (the opaque overcast sheet — in C1, 144 top-level 1024-unit tiles at y=960 covering the whole map) is collected by `IsCloudLayerDeckNode` (texture `cloudlayer`) into a separate `CloudDeck` node (kept a child of the world root at identity so its tiles keep their world positions) instead of the static world root; PlaneViewer moves it each frame to follow the player. The cloud1/cloud2 sprites stay in the world root (world-fixed). `MeshUsesTexture(node, predicate)` backs both this and `NoCollisionNode`. `BuildHorizon(zone)` builds the original skydome as a separate camera-anchored backdrop node (default `zone2` = night, the sky the original shows at the C1 airfield): never collidable, never casts shadows (it covers the whole sky and would blacken the world). The `moon` quad is rebuilt as a camera-facing billboard (`BillboardKeepScale` — plain billboards ignore the dome's 2.5× scale) with its uniform background (66,73,99) color-keyed to alpha; original screenshots show a round moon from any heading with crater detail and no quad edge, ruling out both a static quad and additive blending. `DisableFog` walks the built dome and sets SceneBuilder's `csky_fog_on` instance uniform to 0 on every MeshInstance3D, opting the dome out of distance fog — **currently disabled by an early `return` (user change with the 2026-07-17 fog remodel): the dome now participates in fog**, which the cylinder model makes correct — high dome fragments stay clear via the FOG_ALTITUDE fade while the horizon band fogs toward the same gray as the terrain fog wall. **Map-edge continuation (Run-2 item 7):** `CreateEdgeExtender(clutter)` (call after `Build`, and after the chapter's ClutterBuilder so the extension grows the same trees) returns a `MapEdgeExtender` — see that module's bullet — which continues the world indefinitely past the map edge; WorldBuilder stores the built World node + its collision flag for it. An earlier same-day static 4-ring mirrored skirt (`BuildBorderExtension`) was superseded the same day by the rolling-window extender after user evidence from the original (video + in-game test — see MapEdgeExtender).
- `src/Mech3/MapEdgeExtender.cs` — **map-edge continuation (Run-2 item 7): a rolling window of repeated border tiles + clutter that follows the camera past the map boundary indefinitely.** The original does this (user video `OriginalScreenshots/C1 IA1 Tile Loading.mp4`: 10+ min of continuous flight past the edge; the fog wall creeps in ~10 s then the loaded grid re-centres and the visible radius jumps back out, with clutter trees on the continued terrain). **What it repeats is the LOCAL BORDER TILE, not the map** — decisive user test 2026-07-18: our first whole-map mirror tiling brought the airport back every ~12 km flying east, which the original never does ("always the same tiles as in the 10-second interval"; one loop = one ~1 km tile crossing at ~135 m/s). `MirrorAxis`: an axis outside the map **clamps to its border cell**, ring parity **alternately reflects** each copy so every seam is a shared mirror plane — heights match exactly (straight repetition would step), the interior is never referenced (no airport), and the continuation stays type-matched to the local edge (sea → sea forever, forest → forest — the user's original grill observation). *Open fidelity question:* the alternating reflection is OUR seam-free construction — the user believes the original does **not** mirror (NOTES.md: plain repetition, possibly sharing the map-edge vertex row); an in-game A/B of a recognizable asymmetric border feature would settle it, and swapping the rule is a one-line change in `MirrorAxis`. `MirrorTransform` builds the per-cell world transform (`Basis.FromScale` negative axis + origin `2·x0+(sx+ix+1)·tile` on flipped axes; plain translation otherwise). **Window:** all cells within `Rings`=5 (TUNE — covers C1 zone2's *raw* fog-far 4000 m ≈ 4 tiles + one margin ring, so the original's visible creep-then-pop never shows and the `fogRangeFactor` TUNE can't expose the edge) of the camera's cell, minus in-map cells; `Update(cameraPos)` (PlaneViewer calls it per frame) is a no-op until a 1024 m cell boundary is crossed, then diffs ~a window row: freed cells `QueueFree`, new cells build. **A cell** = the source cell's ground tiles as bare leaves (`BuildSubtree(node, skip: n ⇒ !ReferenceEquals(n, node))` — own mesh + collider only, no child subtrees ⇒ no buildings; shared SceneBuilder mesh/shape caches) under a mirror-transform holder, plus per-kind `MultiMesh`es of the source cell's clutter sprites at mirrored planted points (the Y-billboard shader re-faces from the instance origin, so mirroring a sprite = mirroring its position; shares the main build's sprite mesh + material via `ClutterBuilder.ExportedKinds`) with a crossed-quad trimesh collider when flying — ground and trees collide exactly when the real world does. **Source scan** (`ScanTiles`, recursive with accumulated ancestor transforms + LOD-nearest + `SkipWorldNode`): all 144 C1 cells have ground tiles (147 — the map-centre airfield tiles hang one level down under group nodes; split half-tile strips and the coastal falls overlay bin alongside their cell's base tile), zero rotated/translated ancestors (transform kept anyway for safety). `IsGroundTile` = Object3d whose own mesh is a single ~0.4–1.35-cell sheet, excluding `cloud*`/`sky*` textures (the cloudlayer deck tiles are cell-sized too). **Verified:** 120 s + 110 s full-throttle flights over the NE corner diagonal (double-flip cells) — continuous terrain + trees, zero errors; scripted dive at +3 km crashes into extension terrain (`g822/col` at (1138,433,−12905), outside both boundaries — mirrored-transform trimesh colliders work, incl. det −1 edge bands); statics at the old airport-repeat spot (none) and 8 km out; C4/C5 clean. Float precision is a non-issue (sub-cm past 100 km — no recentre needed). *Known nit (pre-existing):* ~~in-map beacon point-lights punch through fog as bright dots seen from outside~~ — resolved 2026-07-18 by the light-sprite rework: the lights' own data range (unk68/unk52, 1500–4000 m) now fades them out with distance (see SceneBuilder).
- `src/Mech3/Clutter.cs` (`ClutterBuilder`) — the original's **clutter system**: forest trees on forest-textured hillsides, bushes along the rivers (M2-polish item 5). The gamez has no placed tree nodes — each chapter's boot script (interp.zbd → `support\<chapter>\adjust.gw`) registers clutter **templates** (`AddClutterTemplates terpat02`) that the script `LoadGameGen`s into the gamez as parentless, UNREFERENCED subtree roots (why WorldBuilder's placed-node walk never sees them; they sit among the effect prototypes). A template = a flat ground quad whose **texture names the terrain texture it decorates** (terpat02.tif = C1's forest texture) and whose **size is the tiling period** (512 m for C1 terpat02; the `terpat01-128`-style variants elsewhere are 128 m ones with their own `-128.tif` texture), plus decoration children: single vertical one-sided quads (firtree1/2 17.8–20.9 m, dougfirtree1 22.5 m, bush1/2) each with a local position on the patch. `TemplateNames(interpPath, chapter)` reads the chapter's AddClutterTemplates list from `extracted/interp.json`; `Build(names, collision)` stamps each template across every placed world polygon textured with its ground texture (same walk as WorldBuilder: world children + partition refs, nearest LOD only, same skips). The original's exact alignment is undecoded and the world's UV tiling is wildly non-uniform (256–1280 m/repeat on hillsides), so placement tiles a fixed **world-space X/Z grid** of the template's period instead — authored density everywhere, seam-consistent across polygons (one global grid), each sprite planted at the polygon's barycentric surface height (fan/strip triangulation mirroring SceneBuilder). Slopes steeper than ~75° and degenerate XZ triangles grow nothing; a rounded-position set dedups decal-layered coplanar polys. C1 places 9,303 sprites (~9k firs + river bushes). Rendering: ONE `MultiMeshInstance3D` per decoration kind, a hand-rolled **Y-axis-billboard** shader (upright, spins about the planted point toward the camera — the source cards are one-sided, so the original must face them too), fullbright like the world, alpha-scissor cutout, and the same cylindrical distance-fog term as SceneBuilder's shader (trees fog with the terrain they stand on). Since Run-2 item 6 the tree shader also carries the world's **gamma-space vertex modulate** (an inline copy of `csky_srgb_to_linear`) and the **`csky_world_light`** SUNLIGHT dimming, so the forest darkens/saturates in step with the terrain. Collision (flight only): one static trimesh (`clutter_col`) of two crossed vertical quads per sprite, BackfaceCollision — trees are hittable like the original (`spruce_destroy1/2.json` exists; destruction is dogfight-milestone work). C2/C5's city-block templates parse through the same code but their non-quad decorations are logged + skipped (future work). `ExportedKinds` (filled by Build) exposes each kind's sprite mesh + billboard material (safe to share across MultiMeshes), quad extents, and every planted world position — consumed by `MapEdgeExtender` to grow the same trees on the repeated border tiles past the map edge (mirrored planted points; the originals's continued terrain has clutter too, per the tile-loading video).

- `src/Flight/Weather.cs` — `WeatherState`: per-mission atmosphere from the flown mission's own `weather.json` (same archive as SpawnPoints' ia.json/objectives.json). Parses per-zone distance fog (`FOG_COLOR`, `FOG_RANGES` near/far, `FOG_ALTITUDE` low/high — the fog cylinder's vertical extent: full fog below low, none above high; see SceneBuilder's fog bullet, `CLIP_RANGES`), the per-zone **`SUNLIGHT_*`** world-lighting (item 6, 2026-07-18): `WorldLightFactor` turns `SUNLIGHT_DIFFUSE`/`SUNLIGHT_AMBIENT` into `ZoneFog.WorldLight` = `clamp(AMBIENT + DIFFUSE·SunIncidence, MinWorldLight 0.15, 1)` with `SunIncidence 0.46` (the average up-facing sun incidence, one TUNE calibrated to the C1/IA1 reference) — the per-mission fullbright-world brightness the original applies on top of the baked vertex colours (C1/IA1 0.80, C1B night 0.43, C1C day → clamp 1.0; drives PlaneViewer's `csky_world_light`, see docs/formats/weather.md), the `CLOUD_COVER` whiteout band (TOP/BOTTOM/THICKNESS, plus optional `TOP_COLOR`/`BOTTOM_COLOR` deck tints → `CloudTopColor`/`CloudBottomColor`, decoded now for the item-6 night-brightness calibration, unused this milestone), `WIND` (static + random-gust bounds — drives the ambient cloud-puff drift, see CloudPuffs.cs), and (item 5, 2026-07-18) the **precipitation** block → `Precip` (`PrecipData`: SNOW/RAIN kind, tint COLOR, WIND_DIR/WIND_VEL drift, GRAVITY fall-rate, PARTICLES density, ALPHA_GRADIENT — rendered by `Effects.Precipitation`). The precipitation keys are top-level siblings after `SHADOW_ANGLES`, bare-scalar like CLOUD_COVER/WIND (`"TYPE","SNOW"`, `"WIND_DIR",0.0`), so they're walked raw from `inner` with `StringAfter`/`ScalarAfter`/`ListAfter`/`Vec2After` (the dict would drop a bare-scalar key's value); the keys are unique at `inner`'s top level (FOG_COLOR/SUNLIGHT_* live in the nested zone sub-lists the flat walkers never descend into), and all numbers arrive as `float` (`GetSingle`), so `PARTICLES 100` is `100.0f`. Documented in `docs/formats/weather.md`. **Color triples are dual-encoded** and normalized by `ParseColor`: some are normalized floats (C1 `FOG_COLOR` `[0.69,0.69,0.69]`), others integer 0–255 (C4 `FOG_COLOR` `[192,192,192]`; C5 `[16,16,16]`; every `TOP_COLOR`/`BOTTOM_COLOR`, even in the float-fog night chapters C1B/C3 `[32,56,72]`). `ParseColor` divides by 255 iff any component is strictly >1 — verified unambiguous across every weather.json: the sole `1.0`-bearing colour is a float sky-fog `[0.80,0.84,1.0]` (max exactly 1 → stays float), and no integer colour is all-{0,1} (`[0,0,0]` is black either way). Before this (item 3, 2026-07-18) the int chapters fed `Color(192,192,192)` — saturated, then blown further by PlaneViewer's sRGB→linear (which assumes 0..1) — giving C4's blown-white fog with a hard horizon cut. Now C4's fully-fogged pixels measure exactly 192 gray with a soft ramp; C1's float path is byte-identical (still 176). Documented in `docs/formats/weather.md`. weather.json is one alternating dict, but the `CLOUD_COVER`/`WIND` blocks pair keys with **bare scalars** (`"TOP", 1124`) not lists, so `ZrdrDict.FromAlternating` (which needs list values) can't read them — they're walked as raw key/next-element pairs; the per-zone blocks are all list-valued and go through the normal dict. `Fog(zone)` returns the zone's fog (a no-op fog if absent — near/far so far out nothing fades); `WhiteoutAmount(altitude)` is the 0..1 overlay opacity — a symmetric trapezoid (user-observed in-game): clear sight (0) at BOTTOM and TOP, ramping linearly to a fully-opaque core (1 — the plane vanishes) that is THICKNESS deep and centred on the band midpoint (so THICKNESS is the opaque-core depth, **not** an edge transition; C1/IA1 970–1124 ±30 → total only in 1032–1062). Which zone a mission shows isn't in these readers — the remake picks it via `--sky-zone` (default zone2 = night). PlaneViewer feeds the fog into global shader params and the whiteout into a full-screen overlay (see those bullets).
- `src/Flight/FlightAudio.cs` — own-plane sound loops (non-positional): per-plane engine WAV with throttle-driven pitch 0.6→1.0, overspeed whine (`prop_sound` curves, silent below fd_speed), airframe rattle (`rattle` block, volume 0→1 over 1.0–1.2× fd_speed). Driven per-frame from FlightController (not while crashed) — `Update(dt, …)` takes the frame delta to advance the engine-start envelope. **Prop start/stop one-shots** (`snd_propstart`/`snd_propstop`, both non-looped, no VOLUME → base gain 1.0): `StartEngine()` plays `snd_propstart` and (re)sets a 0→1 gain envelope (`EngineStartRamp` 1.8 s) that the engine loop fades in behind — matching the original's ~1.5–2 s prop-start fade instead of the loop snapping in at full volume. It fires on the initial spawn (`_Ready`) and on every respawn via the loop-restart hook in `Update` (when `_engine` isn't playing, i.e. after a crash stopped it — the "natural hook"). A single `_engine` player means the restart can't double the loop. `OnCrash()` kills the loops and fires one of the game's plane-explosion one-shots (`snd_exp_plane1..4`, random pick). `OnEngineStop()` is the `snd_propstop` capability (plays the wind-down + kills the loops) — **deliberately not called on crash** (the explosion covers that moment; a wind-down under it would read wrong) and wired for a future landing/shutdown flow, which must also stop driving `Update` (like the crash freeze) or the restart hook would re-fire propstart. `--mute` suppresses everything (PlaneViewer never constructs FlightAudio).
- `src/Effects/Puffer.cs` — the original engine's billboard-particle emitter, data-driven from a zrdr `PUFFER_STATE` block. `PufferState.Load(zrdr, file, name)` DFS-searches an effects reader (flame_ball.json, fire.json, pufftrails.json, … same schema) for the fully-defined puffer (has `NUMBER`, not a stop-stub) and parses its params (per-axis random velocity, friction, size/lifetime ranges, growth factor, deviation, and the `TEXTURE_SEQUENCE` flipbook). `Puffer.Create(state, textures)` builds a horizontal atlas from the flipbook PNGs and returns a CPU-simulated emitter drawn as ONE `MultiMeshInstance3D` (per-instance transform + custom data): a small spatial shader billboards each quad toward the camera (hand-rolled billboard_keep_scale, since MultiMesh has no built-in), picks the flipbook column from `INSTANCE_CUSTOM`, and additively blends (`blend_add`, `depth_draw_never`) — the fire frames are alpha-masked with black edges, so additive gives a soft glow and no quad edge. The CPU sim honours the reader exactly: exponential friction, `Lerp(1,growth,age/life)` size growth, and the non-uniform per-frame flipbook timing; a life-fade envelope (`FadeIn`/`FadeOutStart`) is the only render nicety not in the data. `Burst(worldPos)` (sets `TopLevel` so it stays put in world space) emits `Number` sprites per `TimeInterval` for the caller's active window (default 0.3 s = large_fireball's STOP time); `Clear()` wipes all live particles. **Run-2 item 10c/d extensions:** (1) **trail emitters** — states with `DISTANCE_INTERVAL` (dense_firetrail's smoke/fire, black_smoke) are driven via `TrailAdvance(worldPos)` each frame: one sprite per interval of motion with carry across frames, world-anchored (the trail stays behind the plane); `FindInReader` now accepts NUMBER **or** DISTANCE_INTERVAL as "fully defined". `TrailBurnAt(worldPos, dt, speedMps)` (2026-07-19, the damage lab) is the parked-plane variant: it spends `speedMps` of *virtual* motion per second at a fixed point through the same carry/pool/spawn path, so a distance-interval trail reads as a flickering in-place fire (the puffs' own ±0.8 m/s random velocity + growth provide the motion). (2) **static TEXTURES pools** (smoke101–103): each puff picks a random atlas column at spawn and keeps it (vs the flipbook's age-keyed frames). (3) **COLORS age-ramps** (`[lifeFrac, r,g,b, a]`, rgb 0–255 by the weather.json integer rule): evaluated per particle per frame into the MultiMesh instance color; ramp presence ⇒ **blend_mix** (black smoke is invisible additively), no ramp ⇒ blend_add as before (ramp alpha replaces the FadeIn/Out envelope). (4) Two shader fixes for every effect: a **quad-rim fade** (fire_f01 leaks border pixels up to 247 — grown quads painted faint additive rectangles over dark ground) and **soft particles** (`hint_depth_texture` fade over the last 1.5 m of depth gap — billboards tilted by the high chase camera dip into terrain/walls, and the depth test cut them with hard straight lines; very visible on the 12 m wreck fire, diagnosed via crash screenshots).
- `src/Effects/CloudPuffs.cs` — the ambient cloud puffs: a field of very soft, translucent `cloud1`/`cloud2` billboard sprites the plane flies through at altitude (the wisps drifting past in `OriginalScreenshots/C1 IA1 Cloud Puffs and Moon.png`). **Why synthetic, not the world's own sprites:** C1 places ~600 `cloud1`/`cloud2` sprite quads, but they are **clustered near the airfield** (verified — two far map corners at band altitude render bare) and world-fixed, so most of the map has no clouds at altitude. No zrdr defines an ambient emitter (only crash-style `PUFFER_STATE` readers exist), so this is a hand-tuned field parameterized by the data we do have: the `CLOUD_COVER` band anchors the layer's altitude, the weather `WIND` drives a slow drift (every feel constant is TUNE, playtest-calibrated). **Model:** a fixed pool of world-anchored sprites in a cylindrical shell around the camera, **anchored in Y to the cloud band** (world-fixed altitude — you climb up into the layer then out over it, like a real layer) while the field follows the plane in X/Z; a puff the plane flies past horizontally recycles to the leading edge (spawns ahead of the nose so the plane flies into fresh clouds), so the field is endless. Alpha fades to 0 at the shell edge (recycled puffs fade in, never pop) and by vertical distance from the camera (`VertFull`/`VertFade` — clear well below/above the layer, so low-altitude flight has no clouds and climbing above leaves scattered wisps below). Drawn as ONE `MultiMeshInstance3D` (one draw call): a spatial shader billboards each quad toward the camera (hand-rolled keep-scale, like Puffer), applies a per-instance roll (variety), picks cloud1/cloud2 from `INSTANCE_CUSTOM`, and **alpha-blends** (`blend_mix`, `depth_draw_never`, `fog_disabled` — soft translucent clouds, unlike Puffer's additive fire glow). Since Run-2 item 4 the fragment shader also carries SceneBuilder's **cylindrical distance-fog term** (the same `csky_fog_*` globals + `mix` toward the fog colour), so a puff at the shell edge fades into the fog wall like the terrain below it; the `fog_disabled` render mode stays (it only turns off Godot's *built-in* fog — ours is custom). *In practice the visible effect is negligible in the flyable zones:* the 620 m puff shell sits almost entirely inside the fog's clear near-range (`FOG_RANGES.x`/2 ≈ 500 m in C1/C4 zone2 ⇒ shell-edge puffs fog only ~2 %, near puffs unchanged), so it is a correctness/consistency fix (removing the old fog immunity), not a big look change — the "crisp white against the fog wall" was always the world sprites. The cloud textures are fairly opaque (mean α≈0.43, p90≈0.87), so overlaps saturate fast — `BaseAlpha` is kept low (0.06–0.13) so they read as translucent veils not a solid white ring; `Count` 12, `Radius` 620 m. `Create(textures, wind, bandBottom, bandTop)` builds the 2-frame atlas (null if the textures are absent); `Update(dt, cameraPos, cameraForward)` advances the field each frame (self-gates via the vertical fade — safe to call at any altitude). PlaneViewer builds it in `SetupWeather` (only when the mission has a `CLOUD_COVER` band) and drives it in `_Process` from the flight camera. `--fly`, or static `--chapter` + `--sky-zone` for deterministic `--campos` verification.
- `src/Effects/Precipitation.cs` — rain/snow from the mission weather.json's precipitation block (M2-polish Run-2 item 5; `WeatherState.PrecipData` — C4 SNOW, C1C/C2B RAIN, none in C1/C5 IA1). **Model — a camera-following field the plane flies through, entirely GPU-driven.** One `MultiMeshInstance3D` (one draw call) of N small quads; each instance carries a fixed random seed in `INSTANCE_CUSTOM` (base fraction [0,1)³ + a flutter phase), set once. A spatial shader turns that seed into a world position that (a) falls + drifts over `TIME` (`seed·cell + fall_vel·TIME`) and (b) wraps into a box **centred on `CAMERA_POSITION_WORLD`** (`mod(rel + box_half, cell) − box_half`) — so the field is world-anchored (the plane's own motion carries the particles past = correct parallax), infinite, and seamless (dense uniform particles make the per-cell wrap invisible). The whole animation runs from the `TIME` + `CAMERA_POSITION_WORLD` built-ins, so there is **zero per-frame CPU** — `Create` builds it and it plays itself (no `_Process`/`Update`). Because the shader positions everything around the camera far from this node's origin (where the actual identity instance transforms sit), a **world-sized `CustomAabb`** (±40 km) keeps Godot from frustum-culling the whole MultiMesh — the clean alternative to per-frame moving the node. **SNOW** = small camera-billboard flakes (`INV_VIEW_MATRIX` right/up, per-instance size from the seed) with a gentle per-instance horizontal flutter (`sin/cos(TIME·freq + phase)`, so they don't fall in lockstep). **RAIN** = thin streak quads axially billboarded **along the fall direction** (`normalize(fall_vel)` as the long axis, thin axis facing the camera; length ∝ fall speed) — the data's GRAVITY+WIND world velocity, *not* the plane-relative velocity (rain visibly coming at you when flying fast is a nicer look but not what the data says — a documented TUNE follow-up pending the user's A/B). Alpha = `peak_alpha` (ALPHA_GRADIENT.x) × a **near-fade** (particles within `near_fade` ≈3 m of the camera fade in, so a flake on the chase-cam "lens" doesn't blow up into a blob — natural in a cockpit, distracting third-person) × a radial box-edge fade (no hard cubic boundary) × a **cloud-band gate** (`1 − smoothstep(CloudBottom, CloudTop, particleY)` — precip only shows **below** the CLOUD_COVER band, since it falls from the cloud base; none above the overcast — user-requested 2026-07-18; a huge sentinel band disables it when a mission has precip but no cloud band). No distance-fog term: unlike the cloud sprites (km-scale, out to the fog wall), the ~30 m precip box sits entirely inside the fog's clear near-range (`FOG_RANGES.x`/2 ≈ 250–500 m), so a fog mix would provably never fire. `COLOR` is converted **sRGB→linear** for the unshaded ALBEDO (like FOG_COLOR), so the data's byte value renders back correctly. The sprites are **procedural** (a soft radial dot / a soft vertical streak generated in `MakeFlakeTexture`/`MakeStreakTexture`) — the original rendered untextured coloured line/point primitives, which no texture archive carries, so a tiny generated sprite is the faithful, asset-free stand-in; no `TextureArchive` dependency. `Create(precip, cloudBottom, cloudTop)` → null if the mission has no precip. Every data→look scale (FallScale, PoolPerParticle, box halves, streak length, opacity, fades) is a marked **TUNE** constant, pending the user's in-game A/B. **Verified 2026-07-18** via `--fly`/`--chapter`+`--sky-zone` screenshots: C4 snow (dense, visible falling flakes around the plane; the on-lens blob fixed by the near-fade), C1C rain (vertical streaks below the deck over the sea; **absent above the overcast** after the cloud-band gate — was streaking against the clear night sky before), C1 IA1 clean (no TYPE block → no field), and a static-camera jitter-off `--shots=4` burst whose 4 frames all differ (proves the field animates from `TIME` alone); one draw call each, no shader/script errors.
- `src/Flight/FlightModel.cs` — arcade flight dynamics, reworked 2026-07-17 into a **velocity-vector model in arcade clothing** (M2-polish item 6 + the user's "no lift — the plane hovers at 0 mph" report; the standard simple-flight-model decomposition, cf. brihernandez's ArcadeJetFlightExample / Vazgriz's Unity flight sim). Body rates from control torque × reciprocal inertia vs `ang_momentum_damp` (unchanged). Translation (**vector integration, 2026-07-17 second pass**): thrust (along the nose), drag (against the motion) and gravity integrate on the velocity **vector** `v = VelocityDir·Speed`, so the speed can pass **through zero** — a vertical zoom tail-slides out downward instead of freezing mid-air at a clamped 0 (user-reported: plane stopped in the air with the HUD mph creeping back up; the first-pass scalar model clamped `Speed ≥ 0` and re-accelerated along a stale path direction). **Lift fraction** = `min(1,(v/liftSpeed)²) × |planeUp·worldUp|` (wingVert — 1 level *or inverted* (arcade), 0 knife-edge); gravity is split about the path and its **cross-path component is canceled by the lift fraction** — the deficit is the sink: vanishes at full lift, drops the plane when slow or knife-edge. The **nose-chase alignment** (velocity slerps toward the nose) scales with airspeed (controls mush as airflow dies) *and* wingVert (`KnifeAlignFloor` 0.35 — the chase is the lift force turning the velocity, so knife-edge equilibrium sits visibly ~10° below the nose: the sink). **Stall** (below 0.3·fd_speed): the nose is pulled toward **world-down** via a great-circle rotation about nose×down (attitude-independent — works inverted; replaces the old body-frame pitch-rate bias), rate `stall_mag × StallNoseRate × depth` — deep-stall rate exceeds full-elevator authority, so the drop is decisive until airspeed recovers. **While stalled the nose can NOT be raised over the horizon at any bank angle** (original behavior, user-observed 2026-07-17): after the frame's rotations its world elevation is capped at `max(horizon, frame-start elevation)` — pulled up from below it parks at the horizon; caught nose-high by the stall it can only come down (so a low-speed full-pull loop breaks at the top instead of completing). **Drag is a quadratic + linear blend** (`LowSpeedDragBlend` 0.35 TUNE, normalized so drag(fd_speed) = max thrust — the full-throttle equilibrium stays exactly `fd_speed` for any blend): the linear share is the low-speed air-resistance bite (user-reported: idle level flight barely decelerated on the pure-v² tail; now 120 mph idles down to the ~89 mph stall in ~9 s and settles into a natural nose-dropped glide). **Climb retention**: gravity's along-path bleed is scaled `ClimbGravityScale` 0.6 when climbing (full when diving) — an 11° full-throttle Bloodhawk climb holds ≈122 m/s; the exact factor awaits the user's measured original-game climb curve. Verified via segmented `--hold` telemetry runs: vertical zoom → 12 m/s → nose-over → dive recovery (no hover); knife-edge path −10°, −174 m in 15 s; cruise/level regression byte-identical behavior (wingVert 1 → all new factors are exactly 1).
