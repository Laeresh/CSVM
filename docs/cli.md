# CLI reference — every viewer/flight argument

Full per-flag reference for the Godot project's user arguments, passed after `--`:

```
tools/godot/.../Godot_v4.7-stable_mono_win64_console.exe --path CSVM res://scenes/Main.tscn -- --plane=player_bhawk
```

`RunGame.ps1` (play) and `RunDev.ps1` (dev, with console prompts) forward these verbatim.

**Flight is the default (2026-07-20 CLI inversion).** Any content arg builds a *flight* unless
`--viewer` is present: `--plane=player_fury` flies the Fury and `--chapter=C4` flies over C4,
where both used to open a static orbit view. `--viewer` asks for that static inspection view
back, and is where the damage, livery and mesh labs live. A bare launch (no content arg) shows
the launchscreen. CLAUDE.md carries a compact table of the day-to-day subset; this page is the
long tail.

## Flag index

**Every flag below has exactly one bullet under `## Flags`, and that bullet is the description of
record.** Find the flag here, then read only its bullet — one flag is one line, so this returns the
whole thing. **Never read this file whole** — it is ~86 KB.

```
Grep "^- .--collision" docs/cli.md
```

Names only, deliberately: a gloss here would be a second description of the same flag, and that is
exactly how `CLAUDE.md`'s day-to-day table drifted from this page (four contradictions, found
2026-07-25). One flag, one description.

## Flags
- `--viewer` (the static inspection view: the parked-plane orbit, or with `--chapter=` the static world used for deterministic weather/fog/edge-continuation screenshots. Hosts **both labs, always built**: the damage lab on **H** and the livery lab on **L** — no extra flag needed for either (before 2026-07-20 the damage lab only existed when `--damage` was passed, so H silently did nothing in a plain `--viewer` — user-reported). L opens a panel with the squadron stepper (loads that squadron's colours + decals), three RGB colour sliders, the three decal slots, "reset to squadron colours", a random-livery button and a "copy CLI args" button that puts the equivalent `--paint…` arguments on the clipboard. Also hosts the **mesh lab** on **M** (2026-07-20): normal vectors, wireframe + smoothing seams, the collision zone boxes coloured by damage part, steerable lighting (ambient/sun energy, XYZ direction, headlight), and live `cull`/`normal-source` overrides for A/B-ing render decisions. All three labs start hidden, so an unadorned `--viewer` screenshot is byte-identical to the pre-paint viewer (verified by md5, including with the damage lab's hidden torn-skin panels in the model). H toggles the damage lab **as a whole** — slider panel and HUD gauges together — so it is genuinely present or absent; the panel's own checkbox still controls the gauges while it is up. Edits repaint the parked plane live via `PlaneBuilder.Repaint` — a few ms, not a model rebuild. **P** halts the simulation and **`.`** advances one frame here too — what that freezes in a parked view is the damage lab's fire trails and the weapon lab's rounds in flight)
- `--debug-livery[=N]` (`--viewer` only: open the livery panel at launch and, with N, step the pattern N times first — one scripted screenshot then exercises the stepper + repaint + widget sync, not just the layout; same role as `--debug-scoreboard`/`--debug-join`)
- `--debug-mesh[=spec]` (open the **mesh lab** at launch and preset its modes, so one scripted screenshot exercises the overlays instead of an empty panel. In `--viewer` the subject is the parked plane; in `--freecam`/`--anim-lab` it stands in for the M press and attaches to whatever the run selected (pair it with `--debug-select=`), and the panel is hidden in a `--screenshot` run so the capture is about the geometry. Comma-separated tokens, unknown ones reported not ignored: `normals[=corners]`, `color=provenance|direction|winding`, `wire[=seams|seamsonly]`, `boxes`, `enginewire`, `cull=double|single|inverted`, `source=flat|smooth|negated`, `headlight`, `ambient=off`, `sun=<energy>`, `dir=x/y/z` (slashes — commas separate tokens; the direction the light *travels*, so `dir=0/-1/0` is straight down), `cycle=N` (step the normal-source cycler N times at launch — the headless equivalent of clicking it, like `--debug-livery=N`; it exists because a one-shot spec never reaches the *second* `ApplyOverrides` after a mesh swap, which is where the only crash this lab has had lived), `force` (build the override materials even with both cyclers on `AsData` — **the lab's able-to-fail control**: an override that differs only in the thing under test must reproduce the shipped picture, and it does, raw-pixel identical on both a C1 world subtree and the parked plane), `restore` (scoped runs: attach with everything the spec asked for, then detach again on the same frame — the scripted twin of M-on-M-off, and the only way to prove the restore is exact). E.g. `--debug-mesh=ambient=off,sun=3,dir=0/-1/0,source=negated` is the controlled A/B that diagnosed the inverted-normal bug)
- `--collision[=show]` (**build the world's colliders in a mode that otherwise builds none.** Collision is a flight-build product — `--freecam`, `--anim-lab` and `--viewer` build no `StaticBody3D`/`CollisionShape3D` at all (verification rule 72), so any question about what is solid measures an absence in those modes unless this flag is on. `=show` also opens the **C collider-wireframe overlay** at launch; `--debug-colliders` is the same opener *without* forcing the build, which is how the "no collision here" notice is tested. The overlay draws one wireframe per built shape, coloured by owner class — world (blue), water (cyan), buildings (orange), clutter (green), the flown plane's swept airframe boxes (yellow), anything else (magenta) — and prints its per-class counts plus **`switched on N · switched off M` as two numbers, never their difference** (rule 73: killing C2's `gate1` reads `col[off 1, on 8]`, a net of +7 that alone would say death ADDS collision). Each wireframe follows its shape's live `Disabled` flag, so a destructible's death swaps the drawing with it and the log names what flipped. Trimeshes over 2,000 triangles, and everything past a 400k-line budget, draw as bounding boxes instead — reported, not hidden. **Costs startup time**: C2 freecam measured 2,462 → 3,106 ms warm, of which `world` 352 → 865 ms and `clutter` only 47 → 56 ms (the shared-shape clutter build is no longer the term rule 39 measured); C5 3,188 → 4,304 ms. In `--viewer` the flag still builds the colliders but binds no overlay — C there is the mesh lab's cull cycler, and it says so)
- `--plane=` (a comma-separated list gives one plane per splitscreen player — `--plane=player_bhawk,player_fury` — and implies that player count unless `--players=` says otherwise)
- `--rof=` (default `extracted/rof` — the extracted UI archive holding the paint patterns; run `ExtractRof.ps1` to produce it)
- `--paint=<pattern|random|none>` (aircraft livery, 2026-07-20: a pattern name, or `random`, or `none`. **Patterns are per aircraft** — the Fury has FORTUNE/BLCKSWAN/HUGHES/STUDIO, the Balmoral only FORTUNE/BRITISH; naming one the plane lacks logs its actual set and paints decals only. `random` draws from that plane's set. Comma-separated per player like `--plane=`, last covers the rest. **Defaults: `--fly`/`--stunt` randomize a fresh livery per player on every map load; static `--plane`/`--damage` views build unpainted**, so every pre-paint orbit/damage screenshot still renders byte-identically)
- `--paint-color=R,G,B/R,G,B/R,G,B` (override the scheme's three colours — slot 1 body, 2 dark trim, 3 light trim; integer 0–255, fewer than three repeats the last)
- `--paint-decal=nose,tail,wing` (override the three decal indices into the chapter archive's 00–49 set: 00–20 squadron logos, 21–49 nose art)
- `--paint-seed=N` (seed the random-livery RNG directly, overriding the `paint` stream `--seed`/`--det` would derive — pins liveries alone in an otherwise unpinned run)
- `--damage[=part:frac,…]` (**implies `--viewer`, and only decides whether the lab opens at launch** — every `--viewer` session builds one, reachable on H: the damage lab — per-part HP sliders drive the item-10c visuals on the parked plane: `pdpanelN` torn-skin flips, panel fires burning in place, the ≤10% nose smoke/fire pair; raising a slider repairs. The HUD gauge cluster shows too (toggle in the panel): the damage dial mirrors the sliders, decreases blink it like a flight hit (presets don't — deterministic shots). Optional presets, fraction 0–1 or percent >1, e.g. `--damage=leftwing:0.25,nose:40` — combine with `--screenshot` for deterministic damage shots; H hides the sliders; ignored with `--chapter`/`--fly`)
- `--chapter[=C1]` (which chapter world to build — flown by default, or rendered statically with `--viewer`; takes `C1`/`C1B`/`C1C`/`C2`/`C2B`/`C3`/`C4`/`C5` — drives the default gamez to `<chapter>/gamez.zip` and textures to `<chapter>/texture.zip`; the world node name is always `world1`)
- `--stage=empty` (PLAN-testing C25: **replace the chapter world with a synthetic test stage** — a flat, collidable 20 km ground plane under a grid drawn in code (100 m squares; nothing committed, nothing extracted), the default procedural sky and sun, and the plane over the grid origin. **No chapter gamez, no mission setup, no clutter, no animation program, no weather, no skydome, no edge extender** — the aircraft, its HUD/gauges, flight, collision and both weapon paths are all that is built. The stage for flight-model and ballistics runs and for clean effect shots, where a chapter world is 3 s of load and a noisy backdrop. **Measured startup, warm, three runs each:** `--stage=empty` `total=1951/1939/1993 ms` (`world=20 ms`, one `gamez` load of planes.zbd at ~490) against `--chapter=C1` flight's `4536/4474/4547 ms` — the build itself (`total − boot − first_frame`) is 877/821/824 ms vs 3355. Guns and rockets both fire and impact: `impact: wep_40 (40slug) -> Default at (7,0,-780) on ground/col`, and a rocket that reaches RANGE first detonates in mid-air as it does anywhere else. Two limits, both consequences of there being no chapter gamez: **rockets fly without their FLYOUT body model** and pylons carry no mounted ordnance (the prototypes live in the chapter world, and `ProjectilePool` already returns null for them in any world-less mode), and there is **no world-effects runtime**, so an impact draws the spark fallback rather than a named puffer effect. Placement is the usual pair — `--pos`/`--direction` override the default spawn; `--freecam --stage=empty` gives the plane-less grid from `(0,120,300)`. Combines with `--stunt` only nominally (there is no mission, so no danger zones, and it says so). Ignored with a log in `--viewer`/`--anim-lab`/`--node=`, which exist to inspect gamez; an unknown stage name is reported, not guessed)
- `--node=<cs_name>` (PLAN-testing C25: in `--viewer` (the default for this flag) or `--anim-lab`, **build only the named gamez subtree** out of `--chapter=`'s world, camera auto-framed on it — the zeppelin alone, one building, one destructible, with nothing else in the frame or in the anim index. Matching is on the **source name** — the `cs_name` meta, never the Godot node name, which is sanitized (`.` → `_`) and auto-renamed for duplicate siblings — case-insensitively, with the data's `.flt` model suffix optional. The subtree is placed at its **world** transform, accumulated up the parent chain, so a nested node sits where the full world would put it. **Multiple matches are normal** (C1 has seven `rock_zeppelin`s): the whole match list is logged as `name#index`, the **first** is built, and the ambiguity is a warning — `--node=ap_radiotwr` matches `ap_radiotwr#4283` and `ap_radiotwr.flt#4284`. **A name that matches nothing lists the candidates containing it and quits cleanly (exit 0)**, e.g. `--node=zeppelin` → `candidates containing 'zeppelin': rock_zeppelin, tilt_zeppelin, move_zeppelin`; a name nothing contains says so and points at `--debug-names`. What the stage deliberately does NOT do: **the mission's interp setup script is skipped** (nearly every verb names a node that is not here, and the one thing it reliably would do is switch the subject off — C1/IA1 hides `hk_zep`), so the subtree renders in its gamez base state; clutter is skipped; the origin-parked sweep never registers it, so a transformless vehicle stays visible. The animation program still loads and still binds — what a partial world does to the bind is the question this stage exists to answer, and the bind reports it on `[anim] bind …` lines (see `docs/architecture.md` on `AnimRuntime`). Framing: the subject box is measured from the built meshes before the labs join the tree, and `--pos`/`--direction`/`--lookat` still override it)
- `--fly` (**now the default** — free flight: chapter world + skydome + plane + arcade controls — WASD/arrows pitch+roll, Q/E rudder, Shift/Ctrl throttle, R respawn, **P** halt the sim (gamepad Start; the debug screenshot freeze — the chase camera becomes a free orbit around the frozen plane and the engine loops pause), **`.`** advance exactly one sim frame while halted, T node-name labels, Esc quit; or gamepad; defaults to C1, combine with `--chapter=` for another chapter; also builds the crash fireball via `PufferState.Load`/`Puffer.Create` while the texture archive is open, handing it to the FlightController; spawns from the mission's ia.json — see `--mission`/`--scenario`/`--spawn`)
- `--stunt` (stunt-flying mode = `--fly` + the mission's Danger Zones (ia.json `dzones`) as fly-through objectives, spawning from the `stunt_flying` list; the objective marker HUD (item 2, `MarkerHud`) draws the projected marker / screen-edge arrow / `N o'clock` bearing plus the run timer, zones-done, and a one-shot intro line; completing all zones shows the item-3 results scoreboard (per-zone splits + total + persisted best time, R = fresh run / Esc = quit); forces `stunt_flying` unless `--scenario=` is explicit. With `--players=N` it becomes a **race** (item 7): every pilot flies their own copy of the zones with their own marker HUD and clock, a finisher parks at the finish showing their placing while the field flies on, and the last one in raises a full-window ranked board — placing / tag / aircraft / zones / total + gap to the winner, R = rematch (restarts everyone, gated until all are in). Race totals are not persisted as best times)
- `--freecam` (**spectator mode**: the live chapter world — sky, weather, edge continuation and the running animations — with **no aircraft at all**, observed from a free-flying camera. The testing view for animation work: park in front of the train or a hangar door and watch it, instead of scripting a flight past it. Hold the RIGHT mouse button to look (mouse captured only while held), WASD/arrows + Q/E to move, Shift ×6 / Ctrl ÷6, wheel sets the base speed; IJKL and any gamepad work as alternates. No collision — flying through terrain to reach a vantage point is the point. Starts at the mission's spawn position, so the interesting part of the map is already in view; `--pos=`/`--direction=` override, `--chapter=`/`--mission=`/`--scenario=` select the world as usual. **P** halts the simulation and **`.`** advances exactly one frame — the camera keeps flying through the freeze, so you can walk around a stopped world. **Left-click selects** the object under the cursor and **PgUp/PgDn walk its ancestor ladder** (Home/End jump to the ends); **M** puts the mesh lab on that selection and **C** draws the built colliders (with `--collision`) — see "The shared selection" below. Wins outright over `--fly`/`--stunt`/`--viewer`/`--damage`)
- `--anim-lab` (**the animation debugger**, PLAN-anim-debugger Wave 3: the chapter world as a **quiet stage** — mission setup, reset states and the safety net applied, but no ON_STARTUP defs and no startanims — under a **deterministic fixed-dt clock** (exact 1/60 s steps; render rate never changes simulation results) with def-playback transport. **The camera is the freecam** (RMB look, WASD/QE move, Shift boost, wheel speed — the same one `--freecam` uses); **clicking any object selects it and locks the camera onto it** (RMB rotates around it, the wheel zooms, and it stays centred as it moves — terrain is skipped), and **PgUp/PgDn re-aim the follow onto the wider/narrower rung of that selection's ancestor ladder** without re-framing (see "The shared selection" below); WASD/QE releases the lock back to free flight. Because the camera owns WASD/QE, transport is on an **on-screen button panel** — Pause, Step, Restart, Stop, an **Ambient** toggle (starts/stops the skipped ON_STARTUP + startanims — on *and* off), and a **0.1×/0.25×/1×/2×/4×** speed selector — with four key shortcuts kept (they don't clash with the camera): **P** pause/resume · **`.`** step one frame · **R** restart (tear down → re-pin the RNG → re-apply RESET_STATE → replay, visually identical for a seeded run) · **F** toggle the def picker. **M** (mesh lab on the selection) and **C** (collider wireframes) work here too; Esc/F11/F12/T as everywhere. **The picker + timeline (Wave 4):** a filterable list of every def in the program (`anim-name · activation · @anchor` — type to filter, Enter/double-click plays it) and a bottom **timeline** strip drawing, per Initial sequence, the events at their **authored** start times (upper band) against the **actual** dispatch ticks the runtime fires (lower band), with the playhead and any CALL_ANIMATION child def as an indented lane group — so a scheduler bug shows as a slant between an event's authored block and its fired tick (the instrument that would have caught the polish-4 `NextDue` off-by-one). A status line shows playhead seconds/step, speed, seed, ambient state and the played def. The whole lab UI is hidden in `--screenshot` runs (so shots stay byte-identical) unless `--debug-anim-ui` forces it on. `--plane=` parks that aircraft at the mission spawn point as a stage prop (no controller; `--spawn-at`/`--spawn-dir`/`--spawn` place it — the pre-A5 spelling deliberately kept here, since `--pos` places only the camera); the session's texture/sound archives stay open all session so effects can build at any playhead time. In a scripted run (`--screenshot`) wall time is ignored — every frame advances exactly one step at 1×, so `--frames=N --shots=M` captures land on exact step counts, byte-identical run after run. Wins outright over `--fly`/`--stunt`/`--viewer`/`--damage`/`--freecam`. Accepted limits: pause freezes everything the CPU drives — the runtime, texture cycles, puffer particles — but not the GPU: shader-driven UV scroll keeps flowing and audio already playing plays out, so determinism's boundary is still the CPU sim; frame runtime-driven subjects, not water)
- `--play-anim=<name>` (implies `--anim-lab`: resolve the def(s) carrying that ANIMATION_NAME and play them at launch, exactly the way bootstrap pass 3 starts a startanim — anchored defs once per anchor, unanchored ones globally resolved — and auto-frame the orbit camera on the played def's anchor (fallback: its first resolved target node; `--pos`/`--direction` suppress the auto-frame). An unknown name logs and leaves the stage quiet)
- `--seed=N` (**the session's master seed**, PLAN-testing A3: every random draw in the session comes from a named subsystem generator derived from it — `weapons` (`CANNON_SPREAD`), `flightaudio` (the crash explosion pick), `spawn`, `paint`, `anim` (the world runtime's `RANDOM_WEIGHT` dice, `SOUND_GROUPS` picks and crash-debris scatter), `crash` (one stream per player's crash rig), `effects` (the world-effects runtime), `puffer`, `clouds`, `precip`. A subsystem's seed is `splitmix64(master ^ fnv1a(name))`, so the streams are independent: adding a draw in one cannot shift another's sequence. **Default: 1 under `--det`, `--anim-lab` and `--effects-test`; drawn from the clock otherwise**, so a bare `--fly` still gets a random spawn, random liveries and a varying spread — the resolved value is printed as `rng: master seed N`, so an interesting unpinned run can be replayed by passing it back. Measured: same seed → the same crash sound and 8/8 identical gun-impact positions; `--seed=2` → a different crash sound and 25.09 % different pixels on a C4 snow shot. `--paint-seed=N` still overrides the derived paint seed alone. The animation lab re-pins its runtime on every Play/Restart, so a seeded replay rolls the same dice as the launch)
- `--debug-anim-ui` (implies `--anim-lab`: force the lab's def picker + timeline visible in a scripted `--screenshot` — the timeline-verification path, since the whole lab UI is otherwise hidden there to keep shots byte-identical; the same house convention as `--debug-livery`/`--debug-scoreboard`)
- `--det` (**the determinism bundle** — one flag naming the whole set of pins a reproducible run needs, resolved in one place: **fixed-dt sim clock** + **master seed 1** + **`--spawn=0`** + **pinned liveries** + **`--no-pads`** + **`--jitter=0`**. Each constituent is still individually overridable — `--seed=7 --spawn=2 --paint-seed=99 --jitter=0.5` all win over the bundle's default and the announced line reports what won. **Scripted runs imply it**: `--screenshot=`, the `--dump-*` reports (`--dump-markers`, `--dump-weapons`, `--dump-loadout`, `--dump-flight`, `--dump-config`), `--damage-test`, `--effects-test`, `--weapon-test` and `--run-tests` each turn `--det` on by themselves, so noise is opt-in rather than the default; **`--no-det` opts back out** (see below). The membership rule is *a flag that drives and ends the session by itself* — there is no operator at the controls to notice a run that drifted, so it is pinned. **`--dump-session` is the one deliberate exception**, because it reports this bundle and would otherwise report its own effect on it (rule 117). The resolved bundle is announced on one `core` log line — `[core] det clock=fixed dt_ms=16.667 seed=1 spawn=0 livery_seed=… pads=off jitter=0 via=--screenshot` — so a capture or a log documents the conditions it was taken under instead of relying on the reader remembering what `--det` implies; the `via=` field names the flag that asked for it. **The interactive boundary is deliberate and must stay:** with no scripted flag and no `--det`, nothing changes — a bare `--fly` keeps its random spawn, random liveries and live gamepads, because playtest variety is a feature (verified: an interactive `--fly --players=2` logs `player 1 input: keyboard + pad 0` and no `det` line; the same run with `--screenshot` logs `pads=off` and `player 1 input: keyboard`). What each constituent buys:)
- `--det` **constituents in detail** (PLAN-testing A1/A2: put the session's `GameClock` in fixed-step mode — every rendered frame advances the simulation by exactly 1/60 s, wall time ignored — so **sim state at frame N is a function of N alone**, whatever the render rate. Measured: the same scripted `--hold` flight logs identical telemetry at `--max-fps 30` and at 60 fps under `--det` (15 sim seconds for 900 rendered frames either way), where without it 900 frames at 30 fps run the sim twice as far. **Shader time is clock-driven too** (A2): UV scroll, precipitation and the skydome read the `csky_time` global written from the clock, not Godot's wall-time `TIME`, so **pixel output is a function of the frame count** — two `--det --freecam` runs at the same `--frames` over the C1 waterfall are md5-identical raw pixels where the pre-A2 build moved 30 % of the falls between runs. **`--jitter` therefore defaults to 0 under `--det`** (the camera dither exists to defeat bit-identical frames, the property `--det` is for); pass `--jitter=<deg>` explicitly if you want it in a `--det --shots` burst. **And the git-ignored dev tuning file is ignored**: `--det` drops every `res://config.json` override and reports `config=defaults dropped_overrides=N`, so a deterministic capture is a function of the committed tree rather than of whatever someone was tuning locally — the same command gave different pixels in a checkout and a worktree until this landed. Capture with your overrides applied by passing `--no-det`. **And every RNG is pinned** (A3): `--det` sets the master seed to 1, from which gun spread, the crash-sound pick, the spawn choice, liveries, the animation runtimes' dice and every particle field derive — so a `--freecam` world shot is byte-identical run to run, not merely stable where nothing draws. Measured across two runs at the same `--frames`: the C1 waterfall's mist 0.47 % → **0.00 %**, C2B rain 5.44 % → **0.00 %**, C4 snow 25.84 % → **0.00 %**; `--seed=N` picks a different run. **Flight captures are byte-identical too:** the chase camera takes the sim clock's dt while running (it keeps wall time only through a halt, where the point is to fly the camera around a stopped world), so a bare `--screenshot` C1 flight matches at frames 15/120/300 — **0 of 921,600 px** — where before it moved 29.38 % / 3.21 % / 32.70 %)
- `--no-det` (**opt out of the implied bundle** — the one way to ask for wall-clock behaviour, whatever else is on the command line: it beats both the implication (`--screenshot`/`--dump-*`/`--damage-test`) and an explicit `--det`, so `--det --no-det` runs on the wall clock. Use it to measure the thing `--det` hides: frame-rate-dependent behaviour, live randomness, the same-build noise floor. ## The shared selection (`--freecam` / `--anim-lab`)

**Left-click picks the object under the cursor; PgUp/PgDn walk its ancestor ladder.** A breadcrumb
line names every rung leaf-first (`g15 < l5 < healthy < lk_rightengine01 < … < hk_zep`, the current
one in brackets) with the current rung's world-frame box, and a yellow wireframe box outlines that
rung's subtree. Home jumps to the outermost rung, End back to the struck leaf — a real ladder is
deeper than it looks (C1's moored zeppelin is **nine** rungs from a motor's mesh to `hk_zep`).
The selection is session state: the anim lab's camera-follow tracks the current rung, and the
inspect tools being built on it read the same object.

**How the pick works.** Neither mode builds collision at all (verification rule 72), so this is not
a physics raycast: the camera's ray is tested against every visible built mesh's own AABB, nearest
hit wins. Two consequences to carry: it is **AABB-accurate, not triangle-accurate** — a click just
off a thin object can still take it — and meshes whose world-space AABB diagonal exceeds **350 m**
are skipped, which is what stops every click landing on the map-spanning terrain tile. So terrain
is not selectable, and a click that finds nothing else logs
`select miss … tested=N skipped_oversize=M` rather than going quiet.

**Rung names are `cs_name`, never Godot names** (rule 60): the second `box_car.flt` of C1's
cargotrain reads `cs_name=box_car.flt godot=@Node3D@5`, and the first reads `godot=box_car_flt`.
The unnamed wrapper nodes SceneBuilder adds (`mesh`, `lights`, `col`) and our own overlays are not
rungs. Nothing is built until something is selected, so a capture without a click — or without
`--debug-select` — is byte-identical to one from a build without any of this.

**M — the mesh lab on the selection.** M attaches the mesh lab (normals, smoothing-seam wireframe,
cull and normal-source overrides, a steerable light) to **the selected rung's subtree and nothing
else**, and M again puts that subtree back exactly as it was built — as does selecting something
else, or deselecting. Measured on C1's water tower: the overlays moved 1,278 px, every one of them
inside the tower's own 31×81 px screen rect, and toggling back off returned the frame to the
pre-toggle md5. **Only M is bound here** — the lab's viewer shortcuts (G/N/W/B/C/V) are keys the
free camera flies on, so in these modes the panel's buttons are the whole interface. The light
sliders drive the lab's **own** light, never the world's sun: steering that to inspect one building
would re-light everything else on screen. World geometry renders fullbright, so on a world subtree
the panel says so ("target is fullbright (unshaded) — no light reaches it") rather than offering a
control that silently does nothing. Scripted twin: `--debug-mesh=<spec>` (below) in a run that also
picks something.

**C — the collider wireframes.** See `--collision`. In `--viewer` C stays the mesh lab's cull cycler.

## The node lab — `N` (`--freecam` / `--anim-lab`)

**N toggles a panel down the left edge** holding the world's node tree by `cs_name`, a search box,
per-node actions and a dependency readout for whatever the shared selection currently holds. It is
two-way: clicking an object in the world scrolls the tree to that node, clicking a tree row selects
it in the world (and double-clicking frames the camera on it). Buttons: **Frame** (put the camera on
the selection's measured box and orbit it), **Hide/Show** (flip the subtree's `Visible` — nothing is
torn down, so it is reversible; an animation re-showing a node you hid is the data working, and the
panel's live `visible=`/`in_tree=` readout is how you see that), **Deps ⟳** and a **Destructibles**
switch.

**The tree is populated one branch at a time**, on expand — a chapter world is thousands of nodes
(C5: 8,897 named ones, 557 of them directly under the world root). A branch stops at **500 rows**
and says so; the search box is the way past it. A tree row's children are the nearest `cs_name`
descendants, the exact inverse of the ladder's ancestor walk, so both name the same relation.
**The tree reaches what a click cannot** — the pick skips meshes over 350 m across, so terrain is
unselectable by clicking, and selecting `z3terrain` from the tree (or by name, below) works.

**The dependency readout** lists, for the selected node: the anim definitions anchored on it and
those naming it (with activation, HEALTH, source and sequence names); its destructible pools with
live HP, state, damage stage, which one is authoritative, whether it has a `DAMAGE_SEQUENCE` and how
many thresholds; its mesh/surface/material counts with the source texture names; and its colliders.
**When a dependency source is not built in this mode the readout says so instead of showing an empty
list** (verification rules 43/72) — `--freecam`/`--anim-lab` build no collision at all, so the
collider line reads `colliders NOT BUILT IN THIS MODE …` rather than a zero that looks like an
answer. On a `--node=` slice the anim and destructible readouts carry a **PARTIAL WORLD** banner
with the bind census, because the root-name lift is refused there (rule 91).

**The Destructibles view** replaces the tree with one row per `HEALTH>0` definition in the chapter,
each expandable to its bound node groups (camera-jumpable, with live HP), plus two coverage columns:
**root** — does the definition's `ANIMATION_ROOT_NAME` resolve inside each bound group (`2/2`, or
`NONE`) — and **events** — do its sequences use only event kinds the runtime acts on (`19 ok`, else
the missing kinds by name and count). A definition that bound **nothing** is shown loudly (`⚠` on the
name, `UNRESOLVED`), never hidden. The header carries `defs · instances · node groups · unresolved`,
and the instance and node-group totals are the same numbers the `destructible-census` suite asserts
(C1 267/196, C5 568/292).

- `--debug-nodelab[=spec]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and dumps its readouts to the `ui` log
  category on the second frame, once the selection has settled. `spec` is a comma-separated token
  list: `deps` (the dependency readout), `dest` (the destructibles view — also switches the panel to
  it), `open` (show the panel and log nothing more — the perf/capture shape), and
  `node=<cs_name>` (select that node first, through the tree's own `Select` entry: exact match wins,
  else the first substring match, with the candidate list logged). No spec dumps both readouts and
  changes no selection. Example — the C1 water tower's pool and damage script:
  `--freecam --chapter=C1 --debug-nodelab=node=ap_h2otwr1,deps`)

## The world damage lab — `H` (`--freecam` / `--anim-lab`)

**H toggles a panel down the right edge that damages whatever destructible the shared selection is
on** — the interactive twin of `--damage-test`, on any object, in the running world. (In `--viewer`,
H still means the parked aircraft's damage lab; the two never exist in the same session.) Select an
object — click it, walk the ladder, or reach it from the node lab's tree — and the panel lists that
object's live HP pools with a slider, a **Kill** and a **Reset**.

**The unit of control is a pool, not an object, and only one pool per object is reachable.** A node
can carry several `(def, anchor)` pools with independent HP: C1's water tower `ap_h2otwr1` carries
**two**, the compiler's `h2twr_destruction1@ap_h2otwr1` and the reader wildcard's
`h2twr_destruction*@ap_h2otwr*`. A weapon hit resolves to exactly one of them (compiled preferred),
so that one is marked `REACHABLE` and gets the controls; the others are listed with their live HP and
the reason they have none — driving a twin would damage a pool nothing can ever hit and read as a
working feature. Selecting a **child** of a destructible works too: the panel drives the enclosing
pool and names the anchor it found (`a hit here damages: <def> on '<cs_name>'`).

**The slider is absolute HP.** Lowering it spends the difference through `AnimRuntime.DamageAt` — the
same call a rocket makes, so stages, death, swap, debris and audio are the real ones. Raising it runs
`ResetDestructible` and re-damages down to the new value, because the data has no healing: the damage
stage only ever climbs and `RESET_STATE` is the object's own authored way back.

**A kill reports what it did, split the way the traps demand.** The healthy→destroyed swap and the
collider census are read **before** any clock advance (they are synchronous); the debris is
**scheduled** seconds into the death sequence and is counted after (verification rule 75). Collider
counts are printed as **`off=N on=M`, never a net** (rule 73) — a death switches the object's healthy
collision off *and* the wreck's on. Where collision was not built, the line says
`colliders NOT BUILT IN THIS MODE …` instead of a zero that looks like an answer (rule 72).

**Effects render only because the panel asks for them.** `--freecam`/`--anim-lab` build no
world-effects runtime of their own, and the world runtime's puffer factory is torn down after the
build (rule 76), so a death would start its definitions and draw nothing. The first damage action
builds the same runtime `--destroy` uses and wires it to the world runtime — a building's
`great_balls_of_fire` then renders. **It does not cover everything:** that runtime binds a fixed
closure of impact/destruction animation names, and the progressive-damage puffers
(`sputter_black_smoke_obj`, `sputter_fire_smoke_obj`) and a def's own `PUFFER_STATE` sequences are
not in it — those still fire in the log and draw nothing outside flight.

- `--debug-damage[=script]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and runs an **ordered** script against it
  on the second frame, logging every step to the `ui` log category. Steps, comma-separated and
  executed left to right: `node=<cs_name>` (select it, through the node lab's name index, and list
  its pools), `pool=<n>` (aim the following steps at the n-th listed pool — a step aimed at an
  unreachable one is *refused out loud*, which is how the two-pool case is demonstrated), `hp=<value>`
  (drive the pool to that absolute HP), `kill`, `reset`, `tick=<seconds>` (advance the world runtime
  past a scheduled effect — a script runs inside one frame, so without this the debris reads zero and
  looks unimplemented), and `open` (show the panel and do nothing else). **It forces the collision
  build on**, exactly as `--damage-test` does, so the kill's collider census is real rather than an
  empty list. Example — the full damage/kill/reset/re-kill sequence on the C1 water tower:
  `--freecam --chapter=C1 --det --debug-damage=node=ap_h2otwr1,hp=30,kill,tick=3.5,reset,kill`)
