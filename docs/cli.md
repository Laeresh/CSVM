# CLI reference — every viewer/flight argument

Full per-flag reference for the Godot project's user arguments, passed after `--`:

```
tools/godot/.../Godot_v4.7-stable_mono_win64_console.exe --path CSVM res://scenes/Main.tscn -- --plane=player_bhawk
```

`RunGame.ps1` (play) and `RunDev.ps1` (dev, with console prompts) forward these verbatim.

**Flight is the default.** Any content arg builds a *flight* unless
`--viewer` is present: `--plane=player_fury` flies the Fury and `--chapter=C4` flies over C4,
where both used to open a static orbit view. `--viewer` asks for that static inspection view
back, and is where the damage, livery and mesh labs live. A bare launch (no content arg) shows
the launchscreen. PROJECT_CONTEXT.md carries a compact table of the day-to-day subset; this page
is the long tail.

## Flag index

**Every flag below has exactly one bullet under `## Flags`, and that bullet is the description of
record.** Find the flag here, then read only its bullet — one flag is one line, so this returns the
whole thing. **Never read this file whole**.

```
Grep "^- .--collision" docs/cli.md
```

Names only, deliberately: a gloss here would be a second description of the same flag, and that is
exactly how `PROJECT_CONTEXT.md`'s day-to-day table drifted from this page. One flag, one description.

⚠ **A new flag adds its index entry and its `## Flags` bullet in the same edit.** Both are in this
  file so they cannot drift apart. `PROJECT_CONTEXT.md` carries a curated day-to-day *subset*
  whose rows are glosses, never the description of record — a behaviour change edits the bullet
  here.

**Written exceptions to "one flag, one bullet":** `--direction` shares `--pos`'s bullet and
`--spawn-dir` shares `--spawn-at`'s — each pair is one mechanism (a position and the way it faces, or
a legacy alias and the alias it deprecates), and splitting them would either duplicate the per-mode
routing table or separate a `WARN` line from the sibling flag it is contingent on. `Grep` the
partner's name, not the flag's own, to find either bullet. Conversely three flags carry **two**
bullets each, by design: `--det`'s second (its constituents "in detail") is a continuation, not a
competing description; `--debug-nodelab`/`--debug-damage` each get a short opener bullet plus the full
behaviour written out under their lab's own section further down (see "Three flag families…" above).
A parser-flag-count vs. index-vs-bullet-count check therefore reconciles as: **index entries == parser
flags**, and **bullet *lines* == parser flags** once the 2 shared and the 3 doubled are netted out
(currently all 133 — 133 index entries, 133 parser flags, 134 bullet lines − 3 doubled + 2 shared;
last reconciled 2026-08-23, adding `--debug-preset`'s index entry and bullet with the Instant Action
Table of Contents; before that 2026-08-15 on a merge, adding `--debug-waves`/`--debug-wingmen`'s
index entries (landed with bullets but no index entry) alongside `--ia` and `--debug-fps` from the
two branches merged in; before that, `--hitch-inject` and `--wake-turrets`/`--zeppelins`/
`--no-assist`/`--ai-attack`/`--generators` on 2026-08-13, with `--generators`'s reconciliation

## Flags
- `--viewer` (the static inspection view: the parked-plane orbit, or with `--chapter=` the static world used for deterministic weather/fog/edge-continuation screenshots. Hosts **both labs, always built**: the damage lab on **F5** and the livery lab on **L** — no extra flag needed for either. L opens a panel with the squadron stepper (loads that squadron's colours + decals), three RGB colour sliders, the three decal slots, "reset to squadron colours", a random-livery button and a "copy CLI args" button that puts the equivalent `--paint…` arguments on the clipboard. Also hosts the **mesh lab** on **M**: normal vectors, wireframe + smoothing seams, the collision zone boxes coloured by damage part, steerable lighting (ambient/sun energy, XYZ direction, headlight), and live `cull`/`normal-source` overrides for A/B-ing render decisions. All three labs start hidden, so an unadorned `--viewer` screenshot is byte-identical to the pre-paint viewer (verified by md5, including with the damage lab's hidden torn-skin panels in the model). F5 toggles the damage lab **as a whole** — slider panel and HUD gauges together — so it is genuinely present or absent; the panel's own checkbox still controls the gauges while it is up. Edits repaint the parked plane live via `PlaneBuilder.Repaint` — a few ms, not a model rebuild. **P** halts the simulation and **`.`** advances one frame here too — what that freezes in a parked view is the damage lab's fire trails)
- `--debug-livery[=N]` (`--viewer` only: open the livery panel at launch and, with N, step the pattern N times first — one scripted screenshot then exercises the stepper + repaint + widget sync, not just the layout; same role as `--debug-scoreboard`/`--debug-join`)
- `--debug-mesh[=spec]` (open the **mesh lab** at launch and preset its modes, so one scripted screenshot exercises the overlays instead of an empty panel. In `--viewer` the subject is the parked plane; in `--freecam`/`--anim-lab` it stands in for the M press and attaches to whatever the run selected (pair it with `--debug-select=`), and the panel is hidden in a `--screenshot` run so the capture is about the geometry. Comma-separated tokens, unknown ones reported not ignored: `normals[=corners]`, `color=provenance|direction|winding`, `wire[=seams|seamsonly]`, `boxes`, `enginewire`, `cull=double|single|inverted`, `source=flat|smooth|negated`, `headlight`, `ambient=off`, `sun=<energy>`, `dir=x/y/z` (slashes — commas separate tokens; the direction the light *travels*, so `dir=0/-1/0` is straight down), `cycle=N` (step the normal-source cycler N times at launch — the headless equivalent of clicking it, like `--debug-livery=N`; it exists because a one-shot spec never reaches the *second* `ApplyOverrides` after a mesh swap, which is where the only crash this lab has had lived), `force` (build the override materials even with both cyclers on `AsData` — **the lab's able-to-fail control**: an override that differs only in the thing under test must reproduce the shipped picture, and it does, raw-pixel identical on both a C1 world subtree and the parked plane), `restore` (scoped runs: attach with everything the spec asked for, then detach again on the same frame — the scripted twin of M-on-M-off, and the only way to prove the restore is exact). E.g. `--debug-mesh=ambient=off,sun=3,dir=0/-1/0,source=negated` is the controlled A/B that diagnosed the inverted-normal bug)
- `--collision[=show]` (**build the world's colliders in a mode that otherwise builds none.** Collision is a flight-build product — `--freecam`, `--anim-lab` and `--viewer` build no `StaticBody3D`/`CollisionShape3D` at all (verification WORLD-9), so any question about what is solid measures an absence in those modes unless this flag is on. `=show` also opens the **C collider-wireframe overlay** at launch; `--debug-colliders` is the same opener *without* forcing the build, which is how the "no collision here" notice is tested. The overlay draws one wireframe per built shape, coloured by **the surface id that body resolves to** — `0/default` (blue), `1/water` (cyan), `13/dirt` (tan) and a colour per remaining registry id, plus clutter (green), the flown plane's swept airframe boxes (yellow), anything else (magenta). An id whose def this install does not ship draws as `0/default`, because that is the def a touch there plays, and the legend lists only the ids that can be produced; the id is stamped per collider **body**, not per polygon, and the body's `col_water`/`col_buildings` name comes from its texture, so neither the colour nor the name is a picture of the material data — it is what the engine will select (`BL-345`). It prints its per-id counts plus **`switched on N · switched off M` as two numbers, never their difference** (WORLD-10: killing C2's `gate1` reads `col[off 1, on 8]`, a net of +7 that alone would say death ADDS collision). Each wireframe follows its shape's live `Disabled` flag, so a destructible's death swaps the drawing with it and the log names what flipped. Trimeshes over 2,000 triangles, and everything past a 400k-line budget, draw as bounding boxes instead — reported, not hidden. **Costs startup time**: C2 freecam measured 2,462 → 3,106 ms warm, of which `world` 352 → 865 ms and `clutter` only 47 → 56 ms (the shared-shape clutter build is no longer the term PERF-3 measured); C5 3,188 → 4,304 ms. In `--viewer` the flag still builds the colliders but binds no overlay — C there is the mesh lab's cull cycler, and it says so)
- `--debug-colliders` (open the **C** collider-wireframe overlay **without** forcing the collision
  build first — the un-prefixed opener is `--collision=show`, which always builds. This is how the
  "no collision here" notice (verification WORLD-9) gets exercised in `--freecam`/`--anim-lab`, which
  build none on their own; pass an explicit `--collision` alongside it to see the overlay populated
  there instead. In a flight mode, or after `--collision`, colliders already exist and the overlay
  just opens against them. Distinct from `--debug-collision`, which draws the **flown plane's own**
  collision probe, not the world's)
- `--debug-classoverlay` (open the **X** colour-by-class overlay at launch — the scripted twin of
  the X press, in `--freecam`/`--anim-lab`/`--fly`/`--stunt` (the same mode set as the **C** collider
  overlay, unlike the freecam/anim-lab-only labs). Tints every drawn world mesh a flat colour by what
  it IS rather than what it looks like: destructible (red, from the exact `DestructibleRegistry.Resolve`
  climb a weapon hit takes — a door that only *looks* breakable reads as scenery, which is the correct
  finding, not a bug: C2's `sgh_door1`/`sgh_door2` are a HEALTH-0 `OnStartup` open-the-doors
  animation, never registered as destructibles), facade (pink, `SceneBuilder.ClassifyBillboard` on the source
  `GameZMesh`), clutter (green, every `MultiMeshInstance3D` under the world root — trees/bushes and
  C2/C5's instanced city blocks), everything else plain scenery (blue). Rebuilt on every X press
  rather than cached once, so a destructible's death (which swaps its subtree for wreck pieces) never
  tints a freed node. Deliberately NOT keyed on `SceneBuilder.SurfaceMeta` — that tag answers "what
  does a bullet do here", not "what is this object". No gamez world to classify (`--stage=empty`)
  prints the same kind of "nothing to draw" notice as the C overlay's "no collision built", rather
  than a silently empty overlay. Debug-only material swap: mesh/node counts and goldens are
  unaffected)
- `--debug-tilegrid` (open the map-edge tile-grid overlay at launch. Flag-only — no key is bound.
  Built wherever a map-edge continuation exists (`--fly`, `--freecam`, and a `--sky-zone` viewer),
  which is the same thing as "there is a grid to colour". Tints every ground tile at 20 % by how
  it was folded: **in-map** neutral, then one hue per fold parity —
  `copied` (a straight copy of the block), `x-mirrored`, `z-mirrored`, `xz-mirrored` for the corner
  regions folded on both axes. **The width of one colour band is the block depth**, and a per-cell
  light/dark checker inside the band makes the cells countable rather than estimated. Ground only;
  clutter multimeshes are left alone deliberately, since tinting a forest buries the tile boundaries
  the overlay exists to show. ⚠ **Pair it with `--no-fog`** — fog desaturates the parity hue past
  the weather's fog-far (2.4 km on C2 zone1, under one 3-cell band), and the same
  "fog is a thing to switch off, not tolerate" rule the texture-census work established applies
  here. Debug-only shader-parameter mix, exactly as `--debug-classoverlay`: mesh/node counts and
  goldens are unaffected. ⚠ **It paints only the tiles the extender ACCEPTED**, so a piece of ground
  the classifier refused shows up here as unpainted terrain — and past the map edge as the void that
  refusal leaves. Unpainted ground at a border cell is a defect you are looking at;
  `--dump-tilegrid` is the written form that names the node and the reason)
- `--debug-clutterflag` (build the chapter world recoloured by each polygon's
  decoded `no_clutter` flag, so the attribute the clutter placement is about can be flown through
  instead of judged from stills. **The colours: a world polygon carrying the flag is RED, one
  without it is GREEN, and all clutter — the 3D building decorations AND the sprite cards — is
  BLUE.** Blue is not a third state of the flag: a decoration's own polygons are unflagged, so
  without it a whole city block reads as clutter-eligible ground, which is exactly how an earlier
  throwaway probe was misread. `no_clutter` is raw polygon bit `0x800`, decoded as
  `GameZPolygon.NoClutter` — see `docs/formats/gamez.md` and
  `analysis/bl-305-clutter-uv/FINDINGS-noclutter.md`.
  **There is no runtime key toggle, deliberately**: the recolour is written into the vertex colours
  at world-build time (the flag varies *within* a mesh, so no per-instance tint can express it), and
  a toggle would mean rebuilding the world. Launch with it or without it.
  One log line per build — `debug: --debug-clutterflag view — world polygons no_clutter=N (red),
  clear=M (green), over the models built for <chapter>; clutter blue (K multimeshes)` — so a
  screenshot of the view carries its own census. ⚠ **N and M count polygons per BUILT MODEL, not per
  placement**: a model instanced a hundred times is one mesh build and counts once, which is the
  granularity the flag has, and it is why these are smaller than the whole-chapter census in
  `FINDINGS-noclutter.md` (C5: 556/17,696 here against 658 flagged of 22,493 polygons there — the
  difference is the LOD levels and `fvol` volumes the world build never renders).
  Pair it with `--no-clutter` to see the painted ground the decorations stand on, and with
  `--no-fog` so the colours survive to the horizon. Only the fullbright world's depth-biased
  surfaces recolour: cloud sprites and cylindrical facades keep their texture, and the aircraft
  shader never takes the debug variant at all. With the flag absent the generated shader text is
  byte-for-byte what it was — the same `SceneBuilder.TintLine` constant, on the same code path —
  which the 13 golden hashes hold to)
- `--dump-tilegrid[=path]` (build the chapter world, write the **map-edge tile census** and quit —
  the written twin of `--debug-tilegrid`, and strictly more, since the overlay cannot show a
  rejection. JSON to `./.scratch/tilegrid_<chapter>.json` unless a path is given. One row per tile
  candidate — verdict (`Accepted` / `TooSmall` / `TooLarge` / `SkyOrCloud`), footprint in metres and
  in cells, its grid cell, its texture names and surface class — plus a per-cell roll-up carrying
  `coverX`/`coverZ` and a `suspect` flag for a border cell short of ground. **It answers three
  questions at once**: no accepted tile = a missing cell; coverage under 1 = a short cell; an
  adopted strip = a cell whose ground was refused for being thin (16 adoptions on C5, 0 on the
  other seven). Implies `--freecam`, since the extender it reports on is built only there)
- `--map-edge-block=N` (how many border cells deep the repeated block past the map edge is.
  **Default is per chapter** — `MapEdgeExtender.DefaultBlockCells`: **2** on C1/C2/C4, **1** on C5
  and on C1B/C1C/C2B/C3, whose borders were measured to carry only water tiles, which fixes them at
  1 and makes the depth moot there. All eight A/B'd against the original at the controls. An unknown chapter falls back to 1. Clamped to the chapter's grid, at which point
  the continuation repeats the whole map. ⚠ **Do not size this from a video-derived period** — the
  `CAP-17` strip analysis read C2 as ~3.2 cells against the 2 that actually matches, which is what
  a frame-derived measurement does (`docs/verification.md` DET-12))
- `--map-edge-mode=mirror|repeat` (**default `repeat`: translate the block, which is what the
  original does** — A/B'd at the controls on C1/C2/C4/C5, matching exactly with no seam gaps.
  `mirror` alternately reflects it instead, so every seam is a shared mirror plane; that was the
  shipped behaviour until 2026-08-08 and is now kept only to look at. **F16** toggles it live. ⚠
  This reversed what the `CAP-17` strip analysis was read as showing — a second case of a
  frame-derived reading losing to direct comparison (`docs/verification.md` DET-12).
  Repetition that shares the map-edge vertex row is
  deliberately not offered:
  it is mesh surgery rather than a per-cell transform, and plain repeat shows no step at the
  measured block depths anyway)
- `--plane=` (a comma-separated list gives one plane per splitscreen player — `--plane=player_bhawk,player_fury` — and implies that player count unless `--players=` says otherwise)
- `--rof=` (default `extracted/rof` — the extracted UI archive holding the paint patterns; run `ExtractRof.ps1` to produce it)
- `--paint=<pattern|random|none>` (aircraft livery: a pattern name, or `random`, or `none`. **Patterns are per aircraft** — the Fury has FORTUNE/BLCKSWAN/HUGHES/STUDIO, the Balmoral only FORTUNE/BRITISH; naming one the plane lacks logs its actual set and paints decals only. `random` draws from that plane's set. Comma-separated per player like `--plane=`, last covers the rest. **Default everywhere is `player_fortune`**, the Fortune Hunters livery the original's stock planes wear and the only pattern covering all eleven airframes — flight, AI spawns and static `--plane`/`--damage`/`--viewer` views alike. `--paint=none` is how you ask for the bare shipped skins. Instant Action's enemies are the exception: the ace and the waves fly for another militia, so they keep their own shipped skins rather than the player militia's colours)
- `--paint-color=R,G,B/R,G,B/R,G,B` (override the scheme's three colours — slot 1 body, 2 dark trim, 3 light trim; integer 0–255, fewer than three repeats the last)
- `--paint-decal=nose,tail,wing` (override the three decal indices into the chapter archive's 00–49 set: 00–20 squadron logos, 21–49 nose art)
- `--paint-seed=N` (seed the random-livery RNG directly, overriding the `paint` stream `--seed`/`--det` would derive — pins liveries alone in an otherwise unpinned run)
- `--damage[=part:frac,…]` (**only decides whether the lab opens at launch** — every session with an aircraft builds one, reachable on F5. On its own it implies `--viewer` and drives the parked plane: per-part HP sliders play the item-10c visuals — `pdpanelN` torn-skin flips, panel fires burning in place, the ≤10% nose smoke/fire pair; raising a slider repairs. The HUD gauge cluster shows too (toggle in the panel): the damage dial mirrors the sliders, decreases blink it like a flight hit (presets don't — deterministic shots). **With an explicit `--fly`/`--stunt` it stays in flight instead**, where the sliders write the aircraft's real per-part HP: the HUD `DMG` line, the damaged-engine mix and the gauge dial all follow, the panel hangs off the right edge clear of the HUD, and it mirrors hits taken back into the sliders. Optional presets, fraction 0–1 or percent >1, e.g. `--damage=leftwing:0.25,nose:40` — combine with `--screenshot` for deterministic damage shots in either mode; a fraction below 1 lands on a part with armor floored to 0, mirroring the same rule a hand-dragged health slider gets (armor absorbs a hit in full before health takes any of it, so no reachable state has both); F5 hides the sliders; ignored by `--freecam`/`--anim-lab`, which have their own world damage lab. **Splitscreen: P1-only** — the panel is one overlay bound to P1's real `PlaneDamage`, not one per pane; with `--players>1` the other panes fly unaffected, and the log names the binding (`FlightDamageTarget` tags itself `"P1"`))
- `--chapter[=C1]` (which chapter world to build — flown by default, or rendered statically with `--viewer`; takes `C1`/`C1B`/`C1C`/`C2`/`C2B`/`C3`/`C4`/`C5` — drives the default gamez to `<chapter>/gamez.zip` and textures to `<chapter>/texture.zip`; the world node name is always `world1`)
- `--stage=empty` (**replace the chapter world with a synthetic test stage** — a flat, collidable 20 km ground plane under a grid drawn in code (100 m squares; nothing committed, nothing extracted), the default procedural sky and sun, and the plane over the grid origin. **No chapter gamez, no mission setup, no clutter, no animation program, no weather, no skydome, no edge extender** — the aircraft, its HUD/gauges, flight, collision and both weapon paths are all that is built. The stage for flight-model and ballistics runs and for clean effect shots, where a chapter world is 3 s of load and a noisy backdrop. **Measured startup, warm, three runs each:** `--stage=empty` `total=1951/1939/1993 ms` (`world=20 ms`, one `gamez` load of planes.zbd at ~490) against `--chapter=C1` flight's `4536/4474/4547 ms` — the build itself (`total − boot − first_frame`) is 877/821/824 ms vs 3355. Guns and rockets both fire and impact: `impact: wep_40 (40slug) -> Default at (7,0,-780) on ground/col`, and a rocket that reaches RANGE first detonates in mid-air as it does anywhere else. Two limits, both consequences of there being no chapter gamez: **rockets fly without their FLYOUT body model** and pylons carry no mounted ordnance (the prototypes live in the chapter world, and `ProjectilePool` already returns null for them in any world-less mode), and there is **no world-effects runtime**, so an impact draws the spark fallback rather than a named puffer effect. Placement is the usual pair — `--pos`/`--direction` override the default spawn; `--freecam --stage=empty` gives the plane-less grid from `(0,120,300)`. Combines with `--stunt` only nominally (there is no mission, so no danger zones, and it says so). Ignored with a log in `--viewer`/`--anim-lab`/`--node=`, which exist to inspect gamez; an unknown stage name is reported, not guessed)
- `--node=<cs_name>` (in `--viewer` (the default for this flag) or `--anim-lab`, **build only the named gamez subtree** out of `--chapter=`'s world, camera auto-framed on it — the zeppelin alone, one building, one destructible, with nothing else in the frame or in the anim index. Matching is on the **source name** — the `cs_name` meta, never the Godot node name, which is sanitized (`.` → `_`) and auto-renamed for duplicate siblings — case-insensitively, with the data's `.flt` model suffix optional. The subtree is placed at its **world** transform, accumulated up the parent chain, so a nested node sits where the full world would put it. **Multiple matches are normal** (C1 has seven `rock_zeppelin`s): the whole match list is logged as `name#index`, the **first** is built, and the ambiguity is a warning — `--node=ap_radiotwr` matches `ap_radiotwr#4283` and `ap_radiotwr.flt#4284`. **A name that matches nothing lists the candidates containing it and quits cleanly (exit 0)**, e.g. `--node=zeppelin` → `candidates containing 'zeppelin': rock_zeppelin, tilt_zeppelin, move_zeppelin`; a name nothing contains says so and points at `--debug-names`. What the stage deliberately does NOT do: **the mission's interp setup script is skipped** (nearly every verb names a node that is not here, and the one thing it reliably would do is switch the subject off — C1/IA1 hides `hk_zep`), so the subtree renders in its gamez base state; clutter is skipped; the origin-parked sweep never registers it, so a transformless vehicle stays visible. The animation program still loads and still binds — what a partial world does to the bind is the question this stage exists to answer, and the bind reports it on `[anim] bind …` lines (see `docs/architecture.md` on `AnimRuntime`). Framing: the subject box is measured from the built meshes before the labs join the tree, and `--pos`/`--direction`/`--lookat` still override it)

The membership rule is *a flag that drives and ends the session by itself* — there is no operator at the controls to notice a run that drifted, so it is pinned. The resolved bundle is announced on one `core` log line — `[core] det clock=fixed dt_ms=16.667 seed=1 spawn=0 livery_seed=… pads=off jitter=0 via=--screenshot` — so a capture or a log documents the conditions it was taken under instead of relying on the reader remembering what `--det` implies; the `via=` field names the flag that asked for it. **The interactive boundary is deliberate and must stay:** with no scripted flag and no `--det`, nothing changes — a bare `--fly` keeps its random spawn, random liveries and live gamepads, because playtest variety is a feature (verified: an interactive `--fly --players=2` logs `player 1 input: keyboard + pad 0` and no `det` line; the same run with `--screenshot` logs `pads=off` and `player 1 input: keyboard`). - `--det` **constituents in detail** (put the session's `GameClock` in fixed-step mode — every rendered frame advances the simulation by exactly 1/60 s, wall time ignored — so **sim state at frame N is a function of N alone**, whatever the render rate. Measured: the same scripted `--hold` flight logs identical telemetry at `--max-fps 30` and at 60 fps under `--det` (15 sim seconds for 900 rendered frames either way), where without it 900 frames at 30 fps run the sim twice as far. **Shader time is clock-driven too**: UV scroll, precipitation and the skydome read the `csky_time` global written from the clock, not Godot's wall-time `TIME`, so **pixel output is a function of the frame count** — two `--det --freecam` runs at the same `--frames` over the C1 waterfall are md5-identical raw pixels where the pre-A2 build moved 30 % of the falls between runs. **`--jitter` therefore defaults to 0 under `--det`** (the camera dither exists to defeat bit-identical frames, the property `--det` is for); pass `--jitter=<deg>` explicitly if you want it in a `--det --shots` burst. **And the git-ignored dev tuning file is ignored**: `--det` drops every `res://config.json` override and reports `config=defaults dropped_overrides=N`, so a deterministic capture is a function of the committed tree rather than of whatever someone was tuning locally — the same command gave different pixels in a checkout and a worktree until this landed. Capture with your overrides applied by passing `--no-det`. **And every RNG is pinned**: `--det` sets the master seed to 1, from which gun spread, the crash-sound pick, the spawn choice, liveries, the animation runtimes' dice and every particle field derive — so a `--freecam` world shot is byte-identical run to run, not merely stable where nothing draws. Measured across two runs at the same `--frames`: the C1 waterfall's mist 0.47 % → **0.00 %**, C2B rain 5.44 % → **0.00 %**, C4 snow 25.84 % → **0.00 %**; `--seed=N` picks a different run. **Flight captures are byte-identical too:** the chase camera takes the sim clock's dt while running (it keeps wall time only through a halt, where the point is to fly the camera around a stopped world), so a bare `--screenshot` C1 flight matches at frames 15/120/300 — **0 of 921,600 px** — where before it moved 29.38 % / 3.21 % / 32.70 %)

Use it to measure the thing `--det` hides: frame-rate-dependent behaviour, live randomness, the same-build noise floor. It announces itself too — `[core] no-det: --screenshot would run deterministically — wall-clock sim clock, unpinned randomness seed=…` — and prints nothing at all when there was no implication to cancel. Measured on the C1 waterfall pose: two `--screenshot` runs are md5-identical, the same pair under `--no-det` differ by 0.47 % of pixels, max delta 77)

- `--perf` (log the frame-cost split **once per 60 rendered frames** — the headless stand-in for the editor profiler, which needs the GUI. A frame count, not a wall second, because under `--det` one rendered frame is exactly one sim step, so a window is a fixed amount of *simulation* and two runs of a scenario yield the same number of samples; at 60 fps it is still one report a second. One line, flat `key=value`, parsed by `RunTests.ps1 -Perf`: `[perf] window sim_frame= frames= wall_ms= fps= frame_ms= script_ms= render_cpu_ms= gpu_ms= physics_ms= draws= prims= nodes= mem_mb= max_ms= p95_ms=`. Every term through `mem_mb` is a mean over the window; `max_ms`/`p95_ms` are the worst and 95th-percentile *unaveraged* per-frame wall cost in that same window, so a single hitch that a 60-frame mean buries by about 0.5 ms shows up there instead. No `p99_ms`: nearest-rank p99 over 60 samples is the single worst sample, identical to `max_ms` by construction. **Read `render_cpu_ms`, `gpu_ms` and the three counts**; `draws`/`prims`/`nodes` are exact and have no timing noise in them at all, which makes them the sharpest of the set. **Do not read `fps`/`frame_ms`** (paced — floors, PERF-2), **`script_ms`** (`TIME_PROCESS`, ~2.2× real per PERF-1, and it collapses onto the frame cap when the loop is paced) or **`physics_ms`** (`--det` makes the clock parent-driven, so `_PhysicsProcess` consumers no-op and the term is empty by construction) — verification PERF-9…PERF-11. `max_ms`/`p95_ms` are recorded but not yet a verdict metric or an awareness metric in `analysis/perf/scenarios.json`)

The camera sits at the **chase camera's own dynamic distance** — the aircraft's shipped `camparam.json` `dist` (Bloodhawk 18.5 m, Kestrel 14.5 m, Balmoral 25 m; 13 m for the four airframes with no block of their own) plus the `dist_factor` speed term and the measured throttle transient (BL-248 — see [`formats/camparam.md`](formats/camparam.md)), shared with the chase camera so a snap changes the angle and nothing else — the radius at a given sim frame is still deterministic under `--det` — along a direction expressed in the **plane's frame**, aimed back at the plane, so every view banks and rolls with the aircraft: view 8 of a banked plane shows a level aircraft against a tilted horizon. The snap is instant and unsmoothed — a scripted capture must not depend on how many frames of catch-up it waited for. The layout is the numpad's own geometry, with **5 unbound** (the middle of the pad is where the chase camera already is); an out-of-range digit or 5 warns and falls back to the chase camera:

  | Key | Where the camera sits | Sees |
  |---|---|---|
  | `1` / `3` | 45° up from the underside, left / right | belly + one flank |
  | `2` | straight underside | the belly, nose up in frame |
  | `4` / `6` | level left / right flank | the profile, nose to the left / right |
  | `7` / `9` | 45° above the flank, left / right | top + one flank |
  | `8` | ahead of the nose, looking back | head-on |

  Interactively the same eight perspectives are held on **numpad 1–9** (`Kp*` keycodes, so the top-row digits stay free; **NumLock must be on**, or Windows sends the navigation keycodes instead). Release returns to the chase camera. There is one keyboard, so a **held key is player 1's alone** in splitscreen, and there is no gamepad binding — the D-pad is taken by the two weapon selectors. `--view=` is scripted, so it pins **every** pane (verified: `--players=2 --view=6` gives both planes their right flank). A held key beats `--view=`, so a pinned run can still be explored at the controls.

  **The three named values select a view MODE instead** (`chase` · `cockpit` · `nose`), which is a different thing from a held digit: a numpad digit is a momentary pose that lasts while the key is down, a mode is the view the pilot flies in until something changes it. `--view=cockpit` and `--view=nose` are the scripted twins of the **F8** cycle key (**F6** selects the chase view back); the original accepts exactly these three and nothing else (`docs/org/cameraViews.md`, "Only three views are player-selectable"). A held numpad key still overrides the mode for as long as it is down and releasing returns to it, the same precedence a held key has over a pinned digit. The mode is named on the same `view n=…` breadcrumb the held views log (`view n=cockpit …`), so a scripted capture reads back which view it framed. Outside `--fly`/`--stunt` it warns and falls back to the chase camera, like a digit does. **Cockpit and Nose do not yet render differently from the chase camera** — the mode seam is A1's; the `cockpit_camera` placement (A2), the per-mode FOV (A3) and the interior (B11) are their own items in `docs/PLAN-cockpit-view.md`.

  What it is for: flight captures were chase-cam-only, so nothing that lives under the wings or on a flank could be photographed in the air. `--det --view=2 --screenshot` composes with `--tex-override`/`--tex-census` — overriding `blo_fusalagebottom` and counting magenta gives **19,509 px from view 2 against 127 px from the chase camera** on the same C1 pose.

  **⚠ TUNE: the distance, the 45° elevations and the instant snap are recalled from the original, not measured out of it.** The *layout* is settled (it matches the numpad's spatial geometry); the magnitudes wait on the user's A/B against the original game — see `backlog.md`)
- `--campos=x,y,z` (**deprecated** — the pre-A5 camera-only spelling of `--pos`; logs `WARN [core] deprecated flag=--campos use=--pos` once per run, then behaves identically. It never placed the plane and still does not, so it is not simply a rename of `--pos` in `--fly`. Where both reach the same camera (`--freecam`, `--anim-lab`), `--pos` wins)
- `--screenshot=<path>` (render a few frames, save PNG, quit — used for automated visual verification. Launches **non-focus-stealing**: implies `--no-focus` so a capture doesn't yank foreground off your editor. Rendering is unaffected — a hidden window still renders, though a *minimized* one does not (SHOT-16). **Also implies `--det`** (the determinism bundle), so a bare `--screenshot` is reproducible with no other flags — `--no-det` opts out. Every capture also prints `[core] shot pixmd5=<md5> size=<WxH> gpu=<adapter / api>` — the md5 of the **raw pixel buffer**, not of the saved PNG (SHOT-6), which is what the golden-image tripwire compares. Copying that value into `analysis/goldens/manifest.json` is all it takes to turn a shot into a golden; see `analysis/goldens/README.md`).
- `--export-gltf=<path>` (export the viewer plane's mesh to a glTF file, then quit — the parked model wearing its **currently selected livery texture** with its **current damage state baked in** (hidden torn/healthy panel twins and off wing-flares are pruned; the point-sprite lights are dropped). The custom `ShaderMaterial` skins are converted to `StandardMaterial3D` — painted `albedo_tex` as the albedo map plus vertex colour as albedo — so the baked in-engine shading survives; the live particle emitters (smoke/fire/exhaust trails) are **not** part of the model and are excluded, matching "no animation". Format follows the path extension: `.glb` writes one self-contained binary (textures embedded), `.gltf` writes JSON + external buffer/PNGs; anything else defaults to `.glb`. Reads the live scene through a throwaway `Duplicate()`, so the on-screen plane — and any golden screenshot in the same run — is untouched. **Implies `--det`** (a reproducible livery/spawn); works under `--headless` since it reads the scene graph, not the framebuffer. Interactive twin: **F10** in the viewer writes a timestamped `.glb` to the git-ignored `Exports/` folder)
- `--frames=N` (warm-up frames rendered before the shot — default 15. **Under `--det`, which `--screenshot` implies, this is exactly sim frame N**: the fixed clock advances one 1/60 s step per rendered frame, so the capture always lands on the same simulated moment and `--frames=N` is a *sim* coordinate, not a wall-clock delay. The saved-shot log line carries it — `screenshot saved: … sim_frame=120 sim_time=2` under `--det` versus `sim_frame=15 sim_time=0.435` for the same `--frames=15` under `--no-det`. Two runs at the same N are md5-identical; different Ns genuinely differ (C1 waterfall, frame 15 vs 120: 2.24 % of pixels), so a shot's frame number is part of what it shows)
- `--shots=N` (after the `--frames` warm-up, capture N **consecutive** frames — one per `_Process` — then quit; default 1 = the single-shot behavior at the verbatim path; N>1 writes zero-padded indexed files `foo.png`→`foo_00.png`/`foo_01.png`/… via `IndexedShotPath`, for **z-fighting debugging** since the flicker is only visible across frames)
- `--jitter=<deg>` (per-frame camera dither during a `--shots` burst — micro-orbits the eye around the framed point (`_orbit.OrbitCenter`) so a dead-still camera doesn't render bit-identical frames; default 0.15° when `--shots>1` else 0, **and 0 under `--det`** whatever `--shots` is, since the dither exists to break the bit-identity `--det` wants; `0` disables; static mode only — in `--fly` the FlightController owns the camera and the plane's motion already surfaces the fight; file `_00` is the un-jittered baseline)

## The shared selection (`--freecam` / `--anim-lab`)

**Left-click picks the object under the cursor; PgUp/PgDn walk its ancestor ladder.** A breadcrumb
line names every rung leaf-first (`g15 < l5 < healthy < lk_rightengine01 < … < hk_zep`, the current
one in brackets) with the current rung's world-frame box, and a yellow wireframe box outlines that
rung's subtree. Home jumps to the outermost rung, End back to the struck leaf — a real ladder is
deeper than it looks (C1's moored zeppelin is **nine** rungs from a motor's mesh to `hk_zep`).
The selection is session state: the anim lab's camera-follow tracks the current rung, and the
inspect tools being built on it read the same object.

**How the pick works.** Neither mode builds collision at all (verification WORLD-9), so this is not
a physics raycast: the camera's ray is tested against every visible built mesh's own AABB, nearest
hit wins. Two consequences to carry: it is **AABB-accurate, not triangle-accurate** — a click just
off a thin object can still take it — and meshes whose world-space AABB diagonal exceeds **350 m**
are skipped, which is what stops every click landing on the map-spanning terrain tile. So terrain
is not selectable, and a click that finds nothing else logs
`select miss … tested=N skipped_oversize=M` rather than going quiet.

**Rung names are `cs_name`, never Godot names** (WORLD-8): the second `box_car.flt` of C1's
cargotrain reads `cs_name=box_car.flt godot=@Node3D@5`, and the first reads `godot=box_car_flt`.
The unnamed wrapper nodes SceneBuilder adds (`mesh`, `lights`, `col`) and our own overlays are not
rungs. Nothing is built until something is selected, so a capture without a click — or without
`--debug-select` — is byte-identical to one from a build without any of this.

**M — the mesh lab on the selection.** M attaches the mesh lab (normals, smoothing-seam wireframe,
cull and normal-source overrides, a steerable light) to **the selected rung's subtree and nothing
else**, and M again puts that subtree back exactly as it was built — as does selecting something
else, or deselecting. Measured on C1's water tower: the overlays moved 1,278 px, every one of them
inside the tower's own 31×81 px screen rect, and toggling back off returned the frame to the
pre-toggle md5. **Only M is bound here** — the lab's viewer shortcuts (G/N/W/B/C/V) are keys the
free camera flies on, so in these modes the panel's buttons are the whole interface. The light
sliders drive the lab's **own** light, never the world's sun: steering that to inspect one building
would re-light everything else on screen. World geometry renders fullbright, so on a world subtree
the panel says so ("target is fullbright (unshaded) — no light reaches it") rather than offering a
control that silently does nothing. Scripted twin: `--debug-mesh=<spec>` (below) in a run that also
picks something.

**C — the collider wireframes.** See `--collision`. In `--viewer` C stays the mesh lab's cull cycler.

## The node lab — `N` (`--freecam` / `--anim-lab`)

**N toggles a panel down the left edge** holding the world's node tree by `cs_name`, a search box,
per-node actions and a dependency readout for whatever the shared selection currently holds. It is
two-way: clicking an object in the world scrolls the tree to that node, clicking a tree row selects
it in the world (and double-clicking frames the camera on it). Buttons: **Frame** (put the camera on
the selection's measured box and orbit it), **Hide/Show** (flip the subtree's `Visible` — nothing is
torn down, so it is reversible; an animation re-showing a node you hid is the data working, and the
panel's live `visible=`/`in_tree=` readout is how you see that), **Deps ⟳** and a **Destructibles**
switch.

**The tree is populated one branch at a time**, on expand — a chapter world is thousands of nodes
(C5: 8,897 named ones, 557 of them directly under the world root). A branch stops at **500 rows**
and says so; the search box is the way past it. A tree row's children are the nearest `cs_name`
descendants, the exact inverse of the ladder's ancestor walk, so both name the same relation.
**The tree reaches what a click cannot** — the pick skips meshes over 350 m across, so terrain is
unselectable by clicking, and selecting `z3terrain` from the tree (or by name, below) works.

**The dependency readout** lists, for the selected node: the anim definitions anchored on it and
those naming it (with activation, HEALTH, source and sequence names); its destructible pools with
live HP, state, damage stage, which one is authoritative, whether it has a `DAMAGE_SEQUENCE` and how
many thresholds; its mesh/surface/material counts with the source texture names; and its colliders.
**When a dependency source is not built in this mode the readout says so instead of showing an empty
list** (verification LOG-1/WORLD-9) — `--freecam`/`--anim-lab` build no collision at all, so the
collider line reads `colliders NOT BUILT IN THIS MODE …` rather than a zero that looks like an
answer. On a `--node=` slice the anim and destructible readouts carry a **PARTIAL WORLD** banner
with the bind census, because the root-name lift is refused there (WORLD-13).

**The Destructibles view** replaces the tree with one row per `HEALTH>0` definition in the chapter,
each expandable to its bound node groups (camera-jumpable, with live HP), plus two coverage columns:
**root** — does the definition's `ANIMATION_ROOT_NAME` resolve inside each bound group (`2/2`, or
`NONE`) — and **events** — do its sequences use only event kinds the runtime acts on (`19 ok`, else
the missing kinds by name and count). A definition that bound **nothing** is shown loudly (`⚠` on the
name, `UNRESOLVED`), never hidden. The header carries `defs · instances · node groups · unresolved`,
and the instance and node-group totals are the same numbers the `destructible-census` suite asserts
(C1 267/196, C5 568/292).

- `--debug-nodelab[=spec]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and dumps its readouts to the `ui` log
  category on the second frame, once the selection has settled. `spec` is a comma-separated token
  list: `deps` (the dependency readout), `dest` (the destructibles view — also switches the panel to
  it), `open` (show the panel and log nothing more — the perf/capture shape), and
  `node=<cs_name>` (select that node first, through the tree's own `Select` entry: exact match wins,
  else the first substring match, with the candidate list logged). No spec dumps both readouts and
  changes no selection. Example — the C1 water tower's pool and damage script:
  `--freecam --chapter=C1 --debug-nodelab=node=ap_h2otwr1,deps`)

## The world damage lab — `F5` (`--freecam` / `--anim-lab`)

**F5 toggles a panel down the right edge that damages whatever destructible the shared selection is
on** — the interactive twin of `--damage-test`, on any object, in the running world. (Elsewhere F5
means the aircraft's own damage lab; the two never exist in the same session.) Select an
object — click it, walk the ladder, or reach it from the node lab's tree — and the panel lists that
object's live HP pools with a slider, a **Kill** and a **Reset**.

**The unit of control is a pool, not an object, and only one pool per object is reachable.** A node
can carry several `(def, anchor)` pools with independent HP: C1's water tower `ap_h2otwr1` carries
**two**, the compiler's `h2twr_destruction1@ap_h2otwr1` and the reader wildcard's
`h2twr_destruction*@ap_h2otwr*`. A weapon hit resolves to exactly one of them (compiled preferred),
so that one is marked `REACHABLE` and gets the controls; the others are listed with their live HP and
the reason they have none — driving a twin would damage a pool nothing can ever hit and read as a
working feature. Selecting a **child** of a destructible works too: the panel drives the enclosing
pool and names the anchor it found (`a hit here damages: <def> on '<cs_name>'`).

**The slider is absolute HP.** Lowering it spends the difference through `AnimRuntime.DamageAt` — the
same call a rocket makes, so stages, death, swap, debris and audio are the real ones. Raising it runs
`ResetDestructible` and re-damages down to the new value, because the data has no healing: the damage
stage only ever climbs and `RESET_STATE` is the object's own authored way back.

**A kill reports what it did, split the way the traps demand.** The healthy→destroyed swap and the
collider census are read **before** any clock advance (they are synchronous); the debris is
**scheduled** seconds into the death sequence and is counted after (verification WORLD-11). Collider
counts are printed as **`off=N on=M`, never a net** (WORLD-10) — a death switches the object's healthy
collision off *and* the wreck's on. Where collision was not built, the line says
`colliders NOT BUILT IN THIS MODE …` instead of a zero that looks like an answer (WORLD-9).

**Effects render only because the panel asks for them.** `--freecam`/`--anim-lab` build no
world-effects runtime of their own, and the world runtime's puffer factory is torn down after the
build (WORLD-12), so a death would start its definitions and draw nothing. The first damage action
builds the same runtime `--destroy` uses and wires it to the world runtime — a building's
`great_balls_of_fire` then renders, as do the progressive-damage puffers (`sputter_black_smoke_obj`,
`sputter_fire_smoke_obj`, bound since BL-021 landed). **It does not cover everything:** that runtime
binds a fixed closure of impact/destruction animation names, and a def's own `PUFFER_STATE`
sequences (and any death-effect name outside the closure, BL-046) still fire in the log and draw
nothing.

- `--debug-damage[=script]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and runs an **ordered** script against it
  on the second frame, logging every step to the `ui` log category. Steps, comma-separated and
  executed left to right: `node=<cs_name>` (select it, through the node lab's name index, and list
  its pools), `pool=<n>` (aim the following steps at the n-th listed pool — a step aimed at an
  unreachable one is *refused out loud*, which is how the two-pool case is demonstrated), `hp=<value>`
  (drive the pool to that absolute HP), `kill`, `reset`, `tick=<seconds>` (advance the world runtime
  past a scheduled effect — a script runs inside one frame, so without this the debris reads zero and
  looks unimplemented), and `open` (show the panel and do nothing else). **It forces the collision
  build on**, exactly as `--damage-test` does, so the kill's collider census is real rather than an
  empty list. Example — the full damage/kill/reset/re-kill sequence on the C1 water tower:
  `--freecam --chapter=C1 --det --debug-damage=node=ap_h2otwr1,hp=30,kill,tick=3.5,reset,kill`)
