# CLI reference — every viewer/flight argument

Full per-flag reference for the Godot project's user arguments, passed after `--`:

```
tools/godot/.../Godot_v4.7-stable_mono_win64_console.exe --path CSVM res://scenes/Main.tscn -- --plane=player_bhawk
```

`RunGame.ps1` (play) and `RunDev.ps1` (dev, with console prompts) forward these verbatim.

**Flight is the default.** Any content arg builds a *flight* unless
`--viewer` is present: `--plane=player_fury` flies the Fury and `--chapter=C4` flies over C4,
where both used to open a static orbit view. `--viewer` asks for that static inspection view
back, and is where the damage, livery and mesh labs live. A bare launch (no content arg) shows
the launchscreen. PROJECT_CONTEXT.md carries a compact table of the day-to-day subset; this page
is the long tail.

## Flag index

**Every flag below has exactly one bullet under `## Flags`, and that bullet is the description of
record.** Find the flag here, then read only its bullet — one flag is one line, so this returns the
whole thing. **Never read this file whole**.

```
Grep "^- .--collision" docs/cli.md
```

Names only, deliberately: a gloss here would be a second description of the same flag, and that is
exactly how `PROJECT_CONTEXT.md`'s day-to-day table drifted from this page. One flag, one description.

## Flags
- `--viewer` (the static inspection view: the parked-plane orbit, or with `--chapter=` the static world for deterministic weather, fog and edge screenshots. It hosts three labs, always built and needing no extra flag: the damage lab on **F5**, the livery lab on **L** and the mesh lab on **M**. All three start hidden, so an unadorned `--viewer` screenshot matches the pre-paint viewer. F5 toggles the damage lab as a whole, slider panel and HUD gauges together; the panel's own checkbox controls the gauges while it is up. **P** halts the simulation and **`.`** advances one frame)
- `--debug-livery[=N]` (`--viewer` only: open the livery panel at launch and, with N, step the pattern N times first — one scripted screenshot then exercises the stepper + repaint + widget sync, not just the layout; same role as `--debug-scoreboard`/`--debug-join`)
- `--debug-mesh[=spec]` (open the **mesh lab** at launch with its modes preset. The subject is the parked plane in `--viewer` and the run's selection elsewhere, where it stands in for the M press; the panel is hidden in a `--screenshot` run. Comma-separated tokens, unknown ones reported: `normals[=corners]`, `color=provenance|direction|winding`, `wire[=seams|seamsonly]`, `boxes`, `enginewire`, `cull=double|single|inverted`, `source=flat|smooth|negated`, `headlight`, `ambient=off`, `sun=<energy>`, `dir=x/y/z` (slashes; the direction the light travels), `cycle=N`, `force`, `restore`)
- `--collision[=show]` (**build the world's colliders in a mode that otherwise builds none**: `--freecam`, `--anim-lab` and `--viewer` build no `StaticBody3D` at all, so what is solid there is unmeasurable without it (WORLD-9). `=show` also opens the **C** collider-wireframe overlay, colouring each wireframe by the surface id its body resolves to. The id is per body, not per polygon: the colour is what the engine selects. It prints per-id counts and the on and off transitions separately (WORLD-10). In `--viewer` it builds colliders but binds no overlay (C is the mesh lab's cull cycler))
- `--debug-colliders` (open the **C** collider-wireframe overlay **without** forcing the collision
  build first; the opener that always builds is `--collision=show`. This is how the "no collision
  here" notice (WORLD-9) is exercised in `--freecam`/`--anim-lab`, which build none on their own;
  pass `--collision` alongside it to populate the overlay there. In a flight mode, or after
  `--collision`, the colliders already exist and the overlay just opens against them. Distinct from
  `--debug-collision`, which draws the flown plane's own probe, not the world's)
- `--debug-classoverlay` (open the **X** colour-by-class overlay at launch, in
  `--freecam`/`--anim-lab`/`--fly`/`--stunt`. It tints every world mesh by what it is rather than what it looks like: destructible red, from the `DestructibleRegistry.Resolve` climb a weapon hit takes, so a door that only looks breakable
  reads as scenery; facade pink; clutter green;
  everything else scenery blue. It is rebuilt on every X press, so a death never tints a freed node, and it is not keyed on `SceneBuilder.SurfaceMeta`, which answers what a bullet does here. Debug-only: goldens are unaffected)
- `--debug-tilegrid` (open the map-edge tile-grid overlay at launch. Flag-only, and built wherever a map-edge continuation exists (`--fly`, `--freecam`, a `--sky-zone` viewer). It
  tints every ground tile at 20 % by how it was folded, neutral in-map and one hue per fold parity
  (`copied`, `x-mirrored`, `z-mirrored`, `xz-mirrored`); one colour band is one block depth. Ground only. Pair it with `--no-fog` (SHOT-14). It paints only the tiles the extender accepted, so refused
  ground shows as unpainted terrain; `--dump-tilegrid` names the node and the reason)
- `--debug-clutterflag` (build the chapter world recoloured by each polygon's decoded `no_clutter`
  flag. A polygon carrying the flag is RED, one without it GREEN, and all clutter BLUE. A decoration's own polygons are unflagged, so
  without it a whole city block reads as clutter-eligible ground. The flag is polygon bit `0x800`, `GameZPolygon.NoClutter` (`docs/formats/gamez.md`). There is no runtime toggle: the recolour is written into the vertex colours at build time. One log line
  per build carries the census, which counts polygons per built model, not per placement)
- `--dump-tilegrid[=path]` (build the chapter world, write the **map-edge tile census** and quit —
  the written twin of `--debug-tilegrid`, and strictly more, since the overlay cannot show a
  rejection. JSON to `./.scratch/tilegrid_<chapter>.json` unless a path is given. One row per tile
  candidate — verdict (`Accepted` / `TooSmall` / `TooLarge` / `SkyOrCloud`), footprint in metres and
  in cells, its grid cell, its texture names and surface class — plus a per-cell roll-up carrying
  `coverX`/`coverZ` and a `suspect` flag for a border cell short of ground. **It answers three
  questions at once**: no accepted tile = a missing cell; coverage under 1 = a short cell; an
  adopted strip = a cell whose ground was refused for being thin (16 adoptions on C5, 0 on the
  other seven). Implies `--freecam`, since the extender it reports on is built only there)
- `--map-edge-block=N` (how many border cells deep the repeated block past the map edge is.
  **Default is per chapter** — `MapEdgeExtender.DefaultBlockCells`: **2** on C1/C2/C4, **1** on C5
  and on C1B/C1C/C2B/C3, whose borders were measured to carry only water tiles, which fixes them at
  1 and makes the depth moot there. All eight A/B'd against the original at the controls. An unknown chapter falls back to 1. Clamped to the chapter's grid, at which point
  the continuation repeats the whole map. ⚠ **Do not size this from a video-derived period** — the
  `CAP-17` strip analysis read C2 as ~3.2 cells against the 2 that actually matches, which is what
  a frame-derived measurement does (`docs/verification.md` DET-12))
- `--map-edge-mode=mirror|repeat` (**default `repeat`: translate the block, which is what the
  original does** — A/B'd at the controls on C1/C2/C4/C5, matching exactly with no seam gaps.
  `mirror` alternately reflects it instead, so every seam is a shared mirror plane; that was the
  shipped behaviour until 2026-08-08 and is now kept only to look at. **F16** toggles it live. ⚠
  This reversed what the `CAP-17` strip analysis was read as showing — a second case of a
  frame-derived reading losing to direct comparison (`docs/verification.md` DET-12).
  Repetition that shares the map-edge vertex row is
  deliberately not offered:
  it is mesh surgery rather than a per-cell transform, and plain repeat shows no step at the
  measured block depths anyway)
- `--plane=` (a comma-separated list gives one plane per splitscreen player — `--plane=player_bhawk,player_fury` — and implies that player count unless `--players=` says otherwise)
- `--rof=` (default `extracted/rof` — the extracted UI archive holding the paint patterns; run `ExtractRof.ps1` to produce it)
- `--paint=<pattern|random|none>` (aircraft livery: a pattern name, `random`, or `none`. **Patterns are per aircraft**, and naming one the plane lacks logs its actual set and paints decals only; `random` draws from that plane's set. Comma-separated per player like `--plane=`, the last covering the rest. **The default everywhere is `player_fortune`**, the only pattern covering all eleven airframes; `--paint=none` asks for the bare shipped skins. Instant Action's enemies keep their own militia skins rather than the player militia's colours)
- `--paint-color=R,G,B/R,G,B/R,G,B` (override the scheme's three colours — slot 1 body, 2 dark trim, 3 light trim; integer 0–255, fewer than three repeats the last)
- `--paint-decal=nose,tail,wing` (override the three decal indices into the chapter archive's 00–49 set: 00–20 squadron logos, 21–49 nose art)
- `--paint-seed=N` (seed the random-livery RNG directly, overriding the `paint` stream `--seed`/`--det` would derive — pins liveries alone in an otherwise unpinned run)
- `--damage[=part:frac,...]` (**decide whether the damage lab opens at launch**; every session with an aircraft builds one, reachable on **F5**. On its own it implies `--viewer` and drives the parked plane, whose per-part HP sliders play the torn-skin flips, panel fires and nose smoke. With an explicit `--fly`/`--stunt` it stays in flight, where the sliders write the aircraft's real per-part HP. Presets take a fraction of 0-1 or a percent above 1 (`--damage=leftwing:0.25,nose:40`). Ignored by `--freecam`/`--anim-lab`, which have their own world damage lab. Splitscreen: P1-only)
- `--chapter[=C1]` (which chapter world to build — flown by default, or rendered statically with `--viewer`; takes `C1`/`C1B`/`C1C`/`C2`/`C2B`/`C3`/`C4`/`C5` — drives the default gamez to `<chapter>/gamez.zip` and textures to `<chapter>/texture.zip`; the world node name is always `world1`)
- `--stage=empty` (**replace the chapter world with a synthetic test stage**: a flat, collidable 20 km ground plane under a code-drawn 100 m grid, the default sky and sun, with the plane over the grid origin. No chapter gamez, mission setup, clutter, animation program, weather, skydome or edge extender is built, leaving the aircraft, its HUD, flight, collision and both weapon paths. With no chapter gamez, rockets fly without their FLYOUT body, pylons carry no mounted ordnance, and an impact draws the spark fallback rather than an authored effect. An unknown stage name is reported, not guessed)
- `--node=<cs_name>` (in `--viewer`, the default for this flag, or `--anim-lab`, **build only the named gamez subtree** out of `--chapter=`'s world, with the camera auto-framed on it. Matching is on the source `cs_name` meta, never the sanitized Godot node name. Multiple matches are normal: the first is built, and the ambiguity is a warning. A name matching nothing lists the candidates containing it and quits cleanly (exit 0). The mission's interp script and the clutter are skipped, but the animation program still loads and binds. `--pos`/`--direction`/`--lookat` override the framing)
- `--fly` (**the default**: free flight, a chapter world with skydome, plane and arcade controls. WASD or the arrows pitch and roll, Q/E rudder, Shift/Ctrl throttle, R respawns, **P** (or Esc, or gamepad Start) halts the sim and opens the pause board's Resume, Restart and Exit menu, where the chase camera becomes a free orbit around the frozen plane, **`.`** advances one sim frame while halted, and T draws node-name labels. It defaults to C1; combine it with `--chapter=` for another. It spawns from the mission's `ia.json`, so see `--mission`/`--scenario`/`--spawn`)
- `--stunt` (`--fly` plus the mission's Danger Zones (`ia.json` `dzones`) as fly-through objectives, spawning from the `stunt_flying` list, which it forces unless `--scenario=` is explicit. The objective marker HUD draws the marker, edge arrow and bearing with the run timer; completing every zone raises the results scoreboard, which halts the sim (**R** restarts). CLI only: the launchscreen's stunt row attaches an Instant Action mission instead. With `--players=N` it is a race, each pilot flying their own zones and clock, ending on a ranked board; race totals are not persisted)
- `--vs` (**"Dogfight" mode**: splitscreen free-for-all deathmatch, `--fly` plus the `dogfight_ace`
  spawn list unless `--scenario=` is explicit. It **beats `--stunt` by fixed precedence** rather
  than last-flag-wins, dropping stunt mode with a warning when both are given.
  `--vs-kills=`/`--vs-time=` set the match rules. The menu requires two joined pilots before it
  starts a match and this flag does not, so `--vs --players=1` parses and runs with a warning. The
  match bookkeeping, HUD and win/lose flow are not built, so the session flies the `dogfight_ace`
  spawns with nothing scoring)
- `--vs-kills=N` (with `--vs`, the kill target that ends a match early once a player reaches it.
  Default 5; `0` disables the kill limit, so the match runs to `--vs-time=` alone)
- `--vs-time=N` (with `--vs`, the match time limit **in minutes**. Default 5; `0` disables the time
  limit, so the match runs to `--vs-kills=` alone. Both limits at `0` is a match with no end
  condition — accepted, not guarded against, since the mode's win/lose flow is a later item)
- `--coop` (plain splitscreen free flight defaults to **FFA** — every
  human on their own team (`AimAssist.TeamOfPilot`), so aim assist, world turrets and AI gunners
  treat the other humans as hostile. `--coop` opts a plain `--fly`/`--stunt` session into one
  shared human team instead, the same team Instant Action puts its wingmen on
  (`AimAssist.PlayerTeam`). Has no effect with `--vs` — Dogfight's FFA is explicit and outranks it,
  logged as a warning if both are given)
- `--freecam` (**spectator mode**: the live chapter world with **no aircraft at all**, seen from a free-flying camera. RMB looks, WASD and Q/E move, Shift and Ctrl scale the speed, the wheel sets the base. There is no collision. It starts at the mission's spawn position, which `--pos=`/`--direction=` override. **P** halts the simulation and **`.`** advances one frame. Left-click selects, **PgUp**/**PgDn** walk the ancestor ladder, **M** opens the mesh lab and **C** the collider wireframes. Wins over `--fly`/`--stunt`/`--viewer`/`--damage`)
- `--anim-lab` (**the animation debugger**: the chapter world as a quiet stage (no ON_STARTUP defs, no startanims) under a deterministic fixed-dt clock. The camera is the freecam, and clicking an object locks the camera onto it. Transport is an on-screen panel with **P** pause, **`.`** step, **R** restart and **F** the def picker; **M** and **C** work here too. The picker lists every def; the timeline draws authored start times against the ticks the runtime fired. The lab UI is hidden in a `--screenshot` run unless `--debug-anim-ui` forces it. Wins over the other modes)
- `--play-anim=<name>` (implies `--anim-lab`: resolve the def(s) carrying that ANIMATION_NAME and play them at launch, exactly the way bootstrap pass 3 starts a startanim — anchored defs once per anchor, unanchored ones globally resolved — and auto-frame the orbit camera on the played def's anchor (fallback: its first resolved target node; `--pos`/`--direction` suppress the auto-frame). An unknown name logs and leaves the stage quiet)
- `--seed=N` (**the session's master seed**: every random draw comes from a named subsystem stream derived from it as `splitmix64(master ^ fnv1a(name))`. **Default 1 under `--det`, `--anim-lab` and `--effects-test`, drawn from the clock otherwise**, so a bare `--fly` gets a random spawn, liveries and spread; the resolved value prints as `rng: master seed N`, and passing it back replays the run. An unpinned session advances its master per flight, so flying again is a new draw. Weather zones, wave composition and terrain placement do not vary. `--paint-seed=N` overrides the paint stream alone)
- `--debug-anim-ui` (implies `--anim-lab`: force the lab's def picker + timeline visible in a scripted `--screenshot` — the timeline-verification path, since the whole lab UI is otherwise hidden there to keep shots byte-identical; the same house convention as `--debug-livery`/`--debug-scoreboard`)
- `--det` (**the determinism bundle**, one flag naming the pins a reproducible run needs: a fixed-dt sim clock (one 1/60 s step per rendered frame), master seed 1, `--spawn=0`, pinned liveries, `--no-pads` and `--jitter=0`. Shader time is clock-driven too, so pixel output is a function of the frame count, and `config.json` overrides are dropped (DET-8). Each constituent is overridable, and the `[core] det ... via=` line names what won. `--screenshot=`, the `--dump-*` reports, `--damage-test`, `--effects-test`, `--weapon-test` and `--run-tests` each imply the bundle; `--no-det` opts back out)
- `--no-det` (**opt out of the implied bundle**, the one way to ask for wall-clock behaviour whatever else is on the command line: it beats both the implication (`--screenshot`, the `--dump-*` reports, `--damage-test`) and an explicit `--det`, so `--det --no-det` runs on the wall clock. Use it to measure what `--det` hides: frame-rate-dependent behaviour, live randomness, the same-build noise floor. It announces itself as `[core] no-det: --screenshot would run deterministically ...` and prints nothing at all when there was no implication to cancel)
- `--no-pads` (ignore every gamepad — debug/verification aid: a connected pad with stick drift steers the free camera and nudges the flight model, quietly making a scripted screenshot non-deterministic; SDL's own hints don't disable pads in Godot 4.7, so this is our own switch. **Part of the `--det` bundle**, so a scripted run already has it)
- `--perf` (log the frame-cost split **once per 60 rendered frames** — the headless stand-in for the editor profiler, which needs the GUI. A frame count, not a wall second, because under `--det` one rendered frame is exactly one sim step, so a window is a fixed amount of *simulation* and two runs of a scenario yield the same number of samples; at 60 fps it is still one report a second. One line, flat `key=value`, parsed by `RunTests.ps1 -Perf`: `[perf] window sim_frame= frames= wall_ms= fps= frame_ms= script_ms= render_cpu_ms= gpu_ms= physics_ms= phys_tick_ms= phys_tick_max_ms= phys_hz= draws= prims= nodes= mem_mb= max_ms= p95_ms=`. Every term through `mem_mb` is a mean over the window, except the three `phys_*` terms, which are drained from the physics-tick bracket rather than sampled per frame: `phys_tick_ms` is the mean measured wall cost of one whole Godot physics tick, `phys_tick_max_ms` the worst single tick in the window, and `phys_hz` the ticks the window actually got per wall second, which on a realtime clock is sim seconds per wall second, since one tick is one 1/60 sim step; `max_ms`/`p95_ms` are the worst and 95th-percentile *unaveraged* per-frame wall cost in that same window, so a single hitch that a 60-frame mean buries by about 0.5 ms shows up there instead. No `p99_ms`: nearest-rank p99 over 60 samples is the single worst sample, identical to `max_ms` by construction. **Read `render_cpu_ms`, `gpu_ms` and the three counts**; `draws`/`prims`/`nodes` are exact and have no timing noise in them at all, which makes them the sharpest of the set. **Do not read `fps`/`frame_ms`** (paced — floors, PERF-2), **`script_ms`** (`TIME_PROCESS`, ~2.2× real per PERF-1, and it collapses onto the frame cap when the loop is paced) or **`physics_ms`** (Godot's `TIME_PHYSICS_PROCESS`, which holds the WORST single physics tick of the last wall second and refreshes about 1 Hz, so it is neither a per-frame cost nor a mean and can exceed `max_ms` in the same window, verification PERF-21; on top of that `--det` makes the clock parent-driven, so `_PhysicsProcess` consumers no-op and the term is empty by construction). `phys_tick_ms`/`phys_hz` are the honest replacements and are emptied by `--det` the same way, so they are numbers for a `--no-det` run. Verification PERF-9…PERF-11, PERF-21. `max_ms`/`p95_ms` are recorded but not yet a verdict metric or an awareness metric in `analysis/perf/scenarios.json`)
- `--no-vsync` (**a measurement flag, not a display one**: it uncaps the frame loop (vsync disabled,
  `Engine.MaxFps` 0) so `--perf`'s frame timings stop sitting pinned at the refresh rate. It is safe
  to combine with `--det` precisely because that clock advances one sim step per *rendered* frame:
  the simulation is identical frame for frame and only the wall time it takes changes. Also
  settable as the `display.vsync` config key (default `true`, so no `config.json` reproduces stock
  behaviour), which the flag beats when both are given; `RunGame.ps1`/`RunDev.ps1` do not pass it)
- `--debug-anim` (log every live animation motion's target node, world position **and rotation** once a second — rotation because a spinning prop (`OBJECT_MOTION`) turns in place, so a position-only line reads identically every second whether or not it is running — headless verification that the train/doors/vehicles actually move, and by how much, without flying a camera at them; also prints each `If`/`Elseif` condition the first time it is evaluated and thereafter only when its verdict flips, which is how "the player came within 25 m and the rearm door fired" shows up; and every ambient `SOUND_NODE` emitter's host / position / distance / range / playing state, since audio cannot be screenshot-verified and this is what tells "silent because its host is deactivated" apart from "silent because the host never resolved". Each block opens with the session's 3D audio listeners and their positions — one per splitscreen pane — and the `dist` column is the range to the **nearest** of them, naming that pane (`dist 1488 m (P3)`), because that is the pane whose volume wins the engine's mix. It is a range, not a level: the attenuation curve sits between it and loudness)

- `--tex-census[=<name>[,<name>…]]` (**texture drop-in** — *every* texture resolves to its own flat colour, turning a frame into a map of which texture painted which pixel. The colour is a pure hash of the name (`TextureDropIn.ColorForName`), so one texture wears one colour in every chapter and every run — verified 167/167 shared names identical between a C1 and a C4 map. The map lands in `.scratch/tex_census.json`: one entry per texture the session resolved, with `color`, `rgb`, and the `nearest`/`nearest_dist` columns naming its closest neighbour in the space the readback measures. A `--screenshot=` run additionally counts the saved frame into `.scratch/tex_census_<shot>.json`. The optional value lists **extra** texture names to include in that count report even when this chapter's archive has none of them — the able-to-fail control for "texture X is visible here" (quote it in PowerShell, SHELL-18). `TextureCycler` freezes under either drop-in flag, or a flipbook surface would wear a different frame's colour every few frames.

  **Reading the count report, and its measured limits.** `px` is a **lower bound** per texture and `px + contested` an upper one. The world shader multiplies the flat by a *per-channel* vertex colour and the mission's `SUNLIGHT`, so nothing lands on its exact colour (`exact` reads 0 on every world shot measured) and pixels are classified by **chromaticity** — the linear-space colour normalised to its brightest channel, which a scalar dim leaves untouched. A pixel counts for a texture when the nearest census chromaticity is within `tolerance` **0.045** and the runner-up is at least `separation` **0.03** further; otherwise it is reported `contested` (with the rival named) or `unmatched`, never credited. **Both numbers are measured, not chosen:** at a C1/M04 pose with 397 textures resolved, a sweep against a ground truth of 113,947 px (the `--tex-override` count above) and 60 textures that exist only in C4/C5 gave 0.045/0.03 → **75 % recall** with a worst-case **575 px** credited to a texture that cannot be on screen; an absolute separation beat a ratio margin outright (a pixel sitting exactly on a flat has a winning distance of ~0, which passes any ratio test however close the rival). So: **treat a confident count under ~1,000 px as "not shown"**, and use `--tex-override` when you need the exact figure. `collisions` in the map counts textures that hash to the same byte colour (8 bits a channel leave ~200k reachable colours; 4 of C1's 882 textures collide, each warned by name) — those two textures are one number and can never be told apart.

  **Run census shots with `--no-fog`.** Fog mixes every flat toward grey and destroys the ratios the classifier reads. Measured at the same pose: confident classification **374,491 px fog-off vs 129,210 px fog-on**, unmatched **19.4 % vs 58.8 %**. The tolerance exists for the residual per-vertex tint, not for fog — fog is not a thing to tolerate, it is a thing to switch off)

## The shared selection (`--freecam` / `--anim-lab`)

**Left-click picks the object under the cursor; PgUp/PgDn walk its ancestor ladder.** A breadcrumb
line names every rung leaf-first (`g15 < l5 < healthy < lk_rightengine01 < … < hk_zep`, the current
one in brackets) with the current rung's world-frame box, and a yellow wireframe box outlines that
rung's subtree. Home jumps to the outermost rung, End back to the struck leaf — a real ladder is
deeper than it looks (C1's moored zeppelin is **nine** rungs from a motor's mesh to `hk_zep`).
The selection is session state: the anim lab's camera-follow tracks the current rung, and the
inspect tools being built on it read the same object.

**How the pick works.** Neither mode builds collision at all (verification WORLD-9), so this is not
a physics raycast: the camera's ray is tested against every visible built mesh's own AABB, nearest
hit wins. Two consequences to carry: it is **AABB-accurate, not triangle-accurate** — a click just
off a thin object can still take it — and meshes whose world-space AABB diagonal exceeds **350 m**
are skipped, which is what stops every click landing on the map-spanning terrain tile. So terrain
is not selectable, and a click that finds nothing else logs
`select miss … tested=N skipped_oversize=M` rather than going quiet.

**Rung names are `cs_name`, never Godot names** (WORLD-8): the second `box_car.flt` of C1's
cargotrain reads `cs_name=box_car.flt godot=@Node3D@5`, and the first reads `godot=box_car_flt`.
The unnamed wrapper nodes SceneBuilder adds (`mesh`, `lights`, `col`) and our own overlays are not
rungs. Nothing is built until something is selected, so a capture without a click — or without
`--debug-select` — is byte-identical to one from a build without any of this.

**M — the mesh lab on the selection.** M attaches the mesh lab (normals, smoothing-seam wireframe,
cull and normal-source overrides, a steerable light) to **the selected rung's subtree and nothing
else**, and M again puts that subtree back exactly as it was built — as does selecting something
else, or deselecting. Measured on C1's water tower: the overlays moved 1,278 px, every one of them
inside the tower's own 31×81 px screen rect, and toggling back off returned the frame to the
pre-toggle md5. **Only M is bound here** — the lab's viewer shortcuts (G/N/W/B/C/V) are keys the
free camera flies on, so in these modes the panel's buttons are the whole interface. The light
sliders drive the lab's **own** light, never the world's sun: steering that to inspect one building
would re-light everything else on screen. World geometry renders fullbright, so on a world subtree
the panel says so ("target is fullbright (unshaded) — no light reaches it") rather than offering a
control that silently does nothing. Scripted twin: `--debug-mesh=<spec>` (below) in a run that also
picks something.

**C — the collider wireframes.** See `--collision`. In `--viewer` C stays the mesh lab's cull cycler.

## The node lab — `N` (`--freecam` / `--anim-lab`)

**N toggles a panel down the left edge** holding the world's node tree by `cs_name`, a search box,
per-node actions and a dependency readout for whatever the shared selection currently holds. It is
two-way: clicking an object in the world scrolls the tree to that node, clicking a tree row selects
it in the world (and double-clicking frames the camera on it). Buttons: **Frame** (put the camera on
the selection's measured box and orbit it), **Hide/Show** (flip the subtree's `Visible` — nothing is
torn down, so it is reversible; an animation re-showing a node you hid is the data working, and the
panel's live `visible=`/`in_tree=` readout is how you see that), **Deps ⟳** and a **Destructibles**
switch.

**The tree is populated one branch at a time**, on expand — a chapter world is thousands of nodes
(C5: 8,897 named ones, 557 of them directly under the world root). A branch stops at **500 rows**
and says so; the search box is the way past it. A tree row's children are the nearest `cs_name`
descendants, the exact inverse of the ladder's ancestor walk, so both name the same relation.
**The tree reaches what a click cannot** — the pick skips meshes over 350 m across, so terrain is
unselectable by clicking, and selecting `z3terrain` from the tree (or by name, below) works.

**The dependency readout** lists, for the selected node: the anim definitions anchored on it and
those naming it (with activation, HEALTH, source and sequence names); its destructible pools with
live HP, state, damage stage, which one is authoritative, whether it has a `DAMAGE_SEQUENCE` and how
many thresholds; its mesh/surface/material counts with the source texture names; and its colliders.
**When a dependency source is not built in this mode the readout says so instead of showing an empty
list** (verification LOG-1/WORLD-9) — `--freecam`/`--anim-lab` build no collision at all, so the
collider line reads `colliders NOT BUILT IN THIS MODE …` rather than a zero that looks like an
answer. On a `--node=` slice the anim and destructible readouts carry a **PARTIAL WORLD** banner
with the bind census, because the root-name lift is refused there (WORLD-9).

**The Destructibles view** replaces the tree with one row per `HEALTH>0` definition in the chapter,
each expandable to its bound node groups (camera-jumpable, with live HP), plus two coverage columns:
**root** — does the definition's `ANIMATION_ROOT_NAME` resolve inside each bound group (`2/2`, or
`NONE`) — and **events** — do its sequences use only event kinds the runtime acts on (`19 ok`, else
the missing kinds by name and count). A definition that bound **nothing** is shown loudly (`⚠` on the
name, `UNRESOLVED`), never hidden. The header carries `defs · instances · node groups · unresolved`,
and the instance and node-group totals are the same numbers the `destructible-census` suite asserts
(C1 267/196, C5 568/292).

- `--debug-nodelab[=spec]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and dumps its readouts to the `ui` log
  category on the second frame, once the selection has settled. `spec` is a comma-separated token
  list: `deps` (the dependency readout), `dest` (the destructibles view — also switches the panel to
  it), `open` (show the panel and log nothing more — the perf/capture shape), and
  `node=<cs_name>` (select that node first, through the tree's own `Select` entry: exact match wins,
  else the first substring match, with the candidate list logged). No spec dumps both readouts and
  changes no selection. Example — the C1 water tower's pool and damage script:
  `--freecam --chapter=C1 --debug-nodelab=node=ap_h2otwr1,deps`)

## The world damage lab — `F5` (`--freecam` / `--anim-lab`)

**F5 toggles a panel down the right edge that damages whatever destructible the shared selection is
on** — the interactive twin of `--damage-test`, on any object, in the running world. (Elsewhere F5
means the aircraft's own damage lab; the two never exist in the same session.) Select an
object — click it, walk the ladder, or reach it from the node lab's tree — and the panel lists that
object's live HP pools with a slider, a **Kill** and a **Reset**.

**The unit of control is a pool, not an object, and only one pool per object is reachable.** A node
can carry several `(def, anchor)` pools with independent HP: C1's water tower `ap_h2otwr1` carries
**two**, the compiler's `h2twr_destruction1@ap_h2otwr1` and the reader wildcard's
`h2twr_destruction*@ap_h2otwr*`. A weapon hit resolves to exactly one of them (compiled preferred),
so that one is marked `REACHABLE` and gets the controls; the others are listed with their live HP and
the reason they have none — driving a twin would damage a pool nothing can ever hit and read as a
working feature. Selecting a **child** of a destructible works too: the panel drives the enclosing
pool and names the anchor it found (`a hit here damages: <def> on '<cs_name>'`).

**The slider is absolute HP.** Lowering it spends the difference through `AnimRuntime.DamageAt` — the
same call a rocket makes, so stages, death, swap, debris and audio are the real ones. Raising it runs
`ResetDestructible` and re-damages down to the new value, because the data has no healing: the damage
stage only ever climbs and `RESET_STATE` is the object's own authored way back.

**A kill reports what it did, split the way the traps demand.** The healthy→destroyed swap and the
collider census are read **before** any clock advance (they are synchronous); the debris is
**scheduled** seconds into the death sequence and is counted after (verification WORLD-11). Collider
counts are printed as **`off=N on=M`, never a net** (WORLD-10) — a death switches the object's healthy
collision off *and* the wreck's on. Where collision was not built, the line says
`colliders NOT BUILT IN THIS MODE …` instead of a zero that looks like an answer (WORLD-9).

**Effects render only because the panel asks for them.** `--freecam`/`--anim-lab` build no
world-effects runtime of their own, and the world runtime's puffer factory is torn down after the
build (WORLD-12), so a death would start its definitions and draw nothing. The first damage action
builds the same runtime `--destroy` uses and wires it to the world runtime — a building's
`great_balls_of_fire` then renders, as do the progressive-damage puffers (`sputter_black_smoke_obj`,
`sputter_fire_smoke_obj`, bound since BL-021 landed). **It does not cover everything:** that runtime
binds a fixed closure of impact/destruction animation names, and a def's own `PUFFER_STATE`
sequences (and any death-effect name outside the closure, BL-046) still fire in the log and draw
nothing.

- `--debug-damage[=script]` (`--freecam`/`--anim-lab` only — the scripted twin, since live keys and
  mouse are not scriptable here. Opens the panel at launch and runs an **ordered** script against it
  on the second frame, logging every step to the `ui` log category. Steps, comma-separated and
  executed left to right: `node=<cs_name>` (select it, through the node lab's name index, and list
  its pools), `pool=<n>` (aim the following steps at the n-th listed pool — a step aimed at an
  unreachable one is *refused out loud*, which is how the two-pool case is demonstrated), `hp=<value>`
  (drive the pool to that absolute HP), `kill`, `reset`, `tick=<seconds>` (advance the world runtime
  past a scheduled effect — a script runs inside one frame, so without this the debris reads zero and
  looks unimplemented), and `open` (show the panel and do nothing else). **It forces the collision
  build on**, exactly as `--damage-test` does, so the kill's collider census is real rather than an
  empty list. Example — the full damage/kill/reset/re-kill sequence on the C1 water tower:
  `--freecam --chapter=C1 --det --debug-damage=node=ap_h2otwr1,hp=30,kill,tick=3.5,reset,kill`)
