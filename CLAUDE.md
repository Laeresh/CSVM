## Project Description

An XWVM-style remake of **Crimson Skies** (2000, Zipper Interactive, Microsoft): a modern engine that plays the original game using the player's own legally-owned game files. Nothing like this exists yet for Crimson Skies — this is a first-of-its-kind effort.

Charter decided 2026-07-14 (full detail in Claude's project memory):

- **Milestone 1** — complete asset extraction: fill the Crimson Skies gaps in mech3ax (`planes.zbd`, `gamez.zbd`).
- **Milestone 2** — vertical slice: free flight only. One plane, one map (candidate: C1 instant-action arena), arcade controls, original sounds. No AI, objectives, or weapons.
- Long-term direction (not commitment): full campaign remake.

## 🚫 Hard rule: no game assets in version control — ever

Public open-source project under the **XWVM legal model**: the repo ships **code and format documentation only**. Game files, extracted assets, ZBD contents, screenshots of hexdumps containing bulk asset data — none of it gets committed or published. The importer reads the player's own install at runtime. `.gitignore` enforces this for `CrimsonSkiesGame/`, `extracted/`, and `tools/`; keep it that way when adding directories.

When generating temporary artifacts — probe images, screenshots, rendered

## Architecture & key decisions

- **Engine:** Godot 4 .NET (C#). Consumes extraction output via mech3ax / Mech3DotNet (strongly-typed C# wrapper).
- **Format reverse engineering:** happens in a fork of [mech3ax](https://github.com/TerranMechworks/mech3ax) (Rust), PR'd upstream to TerranMechworks. Their byte-identical round-trip test harness (extract→repack) is the correctness standard.
- **Flight model:** data-driven approximation — parameterized by plane stats from extracted zrdr reader files, hand-tuned against the original game. No exe decompilation.
- **Division of labor:** Claude writes the Rust parsers, Godot code, and docs; the user reviews, playtests flight feel, and owns upstream/community communication.
- **Git: commit to `main`.** This is a single-developer repo with no PR workflow, so **do not create a branch** when asked to commit — commit straight to `main`. The user will say so explicitly if a particular change should go on its own branch. Pushing is still never automatic: commit when asked, push only when asked.

## Repo layout

- `CrimsonSkies/` — the Godot 4 .NET project (the actual remake; committed). See "Godot project" below.
- `CrimsonSkiesGame/` — the user's retail game install (git-ignored). ZBD archives in `CrimsonSkiesGame/ZBD/` organized as campaign chapters `C1`–`C5`, each with instant action (`IA1`), story missions (`M0x`), multiplayer maps (`MP1`–`3`). Cutscenes are plain MPGs in `CrimsonSkiesGame/GOSDATA/ASSETS/GRAPHICS/MPG/`.
- `extracted/` — extraction output workdir (git-ignored). Populated by `ExtractAssets.ps1` (below), which mirrors the game's ZBD folder structure: top-level `planes.zip` (unzbd of planes.zbd), `zrdr.zip`, `soundsh.zip`/`soundsl.zip`, `interp.json`, `rimage.zip`, plus per-chapter `C1/gamez.zip`, `C1/texture.zip`, `C1/rtexture*.zip`, `C1/zrdr.zip`, and per-mission `C1/IA1/zrdr.zip` etc. The viewer's defaults read `planes.zip`, `C1/gamez.zip`, `C1/texture.zip`, `zrdr.zip`, `soundsh.zip` — but for each default it **prefers the unpacked sibling folder when present** (e.g. reads `extracted/C1/texture/` over `C1/texture.zip`), so running `ExtractAssets.ps1 -Unzip` (or unzipping just the archives you want to grep in the editor) makes the viewer load loose files and skip zip decompression. All four loaders (`GameZ`, `TextureArchive`, `Zrdr`, `SoundArchive`) accept a zip or a directory; an explicit `--gamez=`/`--textures=`/`--zrdr=`/`--sounds=` is used verbatim. **The `rtexture*`/`rimage` archives are NOT loaded, by design (verified Run-2 item 2):** each `rtextureN.zip` is a **downscaled quality tier** of the same texture set, not a hi-res replacement — measured across all 896 C5 textures, `texture` == `rtexture14` (both max-res), `rtexture2` = ¼, `rtexture4/6/8` = ½, and no rtexture file ever exceeds `texture`; so the base `texture.zip` the viewer loads is already the highest resolution. `rimage.zip` is the UI/HUD image set (crosshairs, buttons, cursor, menu splash, briefing thumbnails), no world geometry textures. **`extracted/rof/`** is produced by the separate `ExtractRof.ps1` (not `ExtractAssets.ps1`) and holds the unpacked `.rof` UI archives + `ui_strings.json`; nothing in the Godot project loads it yet.
- `ExtractAssets.ps1` (repo root) — bulk extractor: walks `CrimsonSkiesGame/ZBD`, runs `unzbd cs <mode>` on every ZBD with the right mode for its type (interp→interp/.json; planes+gamez→gamez; soundsh/soundsl→sounds; zrdr→reader; rimage/texture/rtexture*→textures), and writes the output to the mirrored relative path under `extracted/` (basename kept, extension → `.zip`, or `.json` for interp). **Extracts with the fork build since 2026-07-21** (`tools/mech3ax/target/release/unzbd.exe`; plan item 13) — `-Unzbd <path>` overrides it, e.g. back to the pinned `tools/mech3ax-v0.6.1-.../unzbd.exe`, which needs **no code change** because the Godot loaders read either extraction shape (see the `GameZ.cs` bullet). `cam_anim.zbd`/`mis_anim.zbd` are still reported+skipped — the fork round-trips them byte-identically, but nothing in the Godot project consumes them until plan item 7. Idempotent (skips outputs newer than their source unless `-Force`); `-Unzip` also expands each `.zip` into a sibling folder; `-Source`/`-Dest` override the roots. unzbd's stderr is captured and judged by exit code (PowerShell 5.1 turns a native exe's stderr into terminating errors under `$ErrorActionPreference = "Stop"`); upstream mech3ax's `object3d transform fail` notes — one per node whose euler angles don't recompose to the stored matrix bit-for-bit, informational since the matrix itself is preserved and preferred — are counted and summarized, not printed (155 on a full run). **`messages.json` is not produced by this script** (it comes from `unzbd cs messages CrimsonSkiesGame/strings.dll`).
- `ExtractRof.ps1` (repo root) — extractor for the **non-ZBD** half of the install (2026-07-20): the `.rof` UI resource archives (`GOSDATA/ASSETS/crimson.rof` + the `crimptch.rof` patch overlay) and the `langui.dll`/`language.dll` Win32 string tables, into `extracted/rof/`. Writes every archive member at its archive path, decodes each custom `.BM` texture to `<name>.png` (greyscale shading map) + `<name>_mask.png` (**the paint region masks** — R/G/B = paint slots 1/2/3), and emits `ui_strings.json` (every UI string joined to its `RESOURCE.H` symbol — this is where the aircraft names + description text live). `-Raw` skips the decoding and the string table, `-Force` re-runs an up-to-date extraction, `-Source`/`-Dest` override the roots. The decode work is an inline C# type (`Add-Type`), so a full run is ~1.5 s. Formats: `docs/formats/rof.md`, `docs/formats/strings.md`.
- `RunDev.ps1` (repo root) — **dev** build + launch helper (console prompts): `dotnet build`, then Godot with the forwarded viewer args. No args = interactive **console** menus (plane roster + chapter), then `--fly`; `--fly`/extra flight flags prompt for whatever's missing; bare `--plane=X` / `--chapter[=X]` static views pass through promptless; `--damage[=…]` is its own static flow — prompts only for the plane, never adds `--fly`/`--chapter` (combined with an explicit `--fly`/`--chapter` it passes through verbatim and the viewer ignores it with a note).
- `RunGame.ps1` (repo root) — **play** entry point (M2.5 item 4): `dotnet build`, then Godot with **no user args**, so the in-game launchscreen (Mode → Chapter → Plane; see `src/UI/LaunchMenu.cs`) shows. Any args you pass are forwarded verbatim, so an explicit content arg (`--fly`/`--stunt`/`--plane=`/`--chapter=`/`--screenshot=`) bypasses the launchscreen and builds directly. No console prompts (unlike RunDev.ps1). **Both Run scripts set `SDL_JOYSTICK_DIRECTINPUT=0`** (respecting a pre-set value) — the controller-disconnect freeze workaround (2026-07-19, see backlog "Drop the SDL_JOYSTICK_DIRECTINPUT=0 workaround"): Godot's bundled SDL hangs the main thread forever when a >255-button DirectInput device (the 8BitDo Ultimate 2 dongle) disconnects; disabling the dinput backend removes those phantom views, real pads keep working via XInput/HIDAPI. ## Godot project (`CrimsonSkies/`)

Godot 4.7 .NET, C# / net8.0. Build & run:

```
dotnet build CrimsonSkies/CrimsonSkies.sln
tools/godot/.../Godot_v4.7-stable_mono_win64_console.exe --path CrimsonSkies res://scenes/Main.tscn -- --plane=player_bhawk
```

(First time only: run with `--headless --import` once before running scenes.)

Compact module index — **deep implementation notes, verified diagnoses, and dead ends for every module live in `docs/architecture.md`; read that module's bullet before changing it.**

- `src/Mech3/GameZ.cs` — loads a mech3ax GameZ extraction (zip or unpacked dir): nodes/models/materials/textures JSON → plain C# objects. **`GameZMesh.ModelType`/`FacadeMode`/`TextureScroll` (2026-07-21):** unified-shape-only fields (null/zero on a legacy tree — no crash, SceneBuilder falls back to its texture-name heuristic). `ModelType=="Facade"` is the original's own billboard-sprite flag; `FacadeMode` (`SphericalY`/`CylindricalY`/`CylindricalX`) names the rotation axis — see the SceneBuilder bullet. `TextureScroll` (u/v units/second) is **rendered since 2026-07-22** — 5 models in this install carry it (the daytime skydome's sky layer, an oil-dock conveyor, three boat wake fronts), and the interp boot scripts set 68 more at load time (`Object3DSetScroll`, the C1/C4 waterfalls), both reaching one path in SceneBuilder; the material cache is keyed by the rate as well, since two models can share a material at different rates. **Reads two extraction shapes (2026-07-21, plan item 13):** the pinned v0.6.1 binary's ("legacy") and the fork's ("unified") — same data, different spelling (`{"Object3d":{…}}` → flat node with the variant under `data`; `mesh_index`→`model_index`, `children`→`child_indices`, `transformation`→`transform` whose no-transform case is the string `"Initial"` and whose stored matrix moved `matrix.a…i`→`original.r00…r22`; `meshes.json`→`models.json`, polygon `unk04`→`priority` / `triangle_strip`→`tri_strip`, mesh light `extra`→`vertices`; materials carry `texture_index` into `textures.json` instead of an inline `texture` name; partition cells `nodes[].index`→`values[].node_index`). Reading both is what makes the v0.6.1 rollback a data-only operation. **Two traps:** the unified shape's own `index` field is 1-based and duplicated (v0.6.1's `node_index` renamed) — `child_indices` are NOT in that space, they are flat list positions as before; and unified `scale` is unit everywhere measured, so it is deliberately ignored. Also parses World partition refs, per-corner vertex colors, mesh `lights` arrays, per-polygon draw priority (`unk04`/`priority`, both keys), each node's flat `Index` (= original draw order), and the World's `area` ground-plane bounds + partition-grid dims (for WorldBuilder's map-edge continuation). `WorldTransformOf(node)` accumulates a node's world transform up its parent chain (used to resolve the stunt `dzN` marker positions without building the skipped marker nodes).
- `src/Mech3/TextureArchive.cs` — texture lookup (zip or dir), handles the name quirks (fixed-width 20-char truncation → prefix match; v0.6.1's `.-N` duplicate renames; and **a trailing doubled period** — `bldhwk_cowling..tif`, which only the fork's tree exposes since v0.6.1 hid those 35 entries behind `.-N` renames, plan item 13); classifies alpha per texture (`LastHadAlpha`/`LastAlphaIsSoft` — soft alpha must blend, scissor destroys it). Missing names logged once (plain lines, never `GD.PushWarning`); known-absent-from-game-data textures (`pir_spinner`, `barngrill`) render neutral gray, so magenta = our bug.
- `src/Mech3/SceneBuilder.cs` — **UV scroll (2026-07-22):** a model's texture animation (waterfall sheets, boat wake fronts, the oil-dock conveyor, the daytime sky layer) is `UV + scroll_rate * TIME`, from the model's own `TextureScroll` or the caller's per-model override (where `MissionSetup`'s boot-script rates arrive) via `EffectiveScroll`. The **material cache key includes the rate** — a scrolling model can share a material with static geometry (C1B's oil dock) or with a model at a different rate (the three wakefronts) — and the shader line is emitted only for scrolling variants, so every other material's shader text is unchanged. Shared GameZ-subtree → MeshInstance3D builder (`textureSubstitute` hook: every material's resolved texture passes through it, which is how PlanePainter swaps in a recoloured skin or a decal per aircraft — `Find` still runs, since it is what sets the alpha classification the blend/scissor choice reads): n-gon triangulation, nearest LOD, one surface per (material, priority). Replicates the original's coplanar layering as scale-invariant depth bias (priority × 2e-4 + within-mesh surface rank × 2e-6 + node index × 5e-8 as an `instance uniform` — needs Forward+; `project.godot` raises the global-shader-variable buffer to 262144 for C4/C5 instance counts). Soft-alpha textures auto-blend, others scissor; `billboardTexture` predicate for cloud sprites (recentered on quad centroid; own billboard `ShaderMaterial` that shares the distance fog — item 4); mesh point-lights as camera-facing soft glow sprites (own point shader: gaussian falloff, ×1.6 gain, distance-sized 3–30 px; per-light decoded size/range params — range fade keeps beacons inside the fog, skydome stars exempt via `csky_light_fade`). **Billboard classification is now data-driven off the gamez model itself (2026-07-21), not texture-name heuristics:** `IsGlowSpriteMesh` gates on `ModelType=="Facade"` first — the real discriminator (a multi-poly `flare_green` "string" carries a stale `FacadeMode` but `ModelType=="Default"` and correctly stays static instead of billboarding as one sprite around a shared centroid) — then `FacadeMode=="SphericalY"` (minus cloud-textured meshes, still routed through the existing `billboardTexture` path) is a full camera-facing glow flare (lamp/beacon/muzzle-flash/ammo-tip sprites), while `CylindricalY`/`CylindricalX` is a NEW single-axis billboard (`GetCylindricalMaterial`/`GetCylindricalShader`, Clutter's proven tree-billboard vertex technique generalized to either axis) — trees/lampposts/cables/flame stay upright and spin only around their fixed axis instead of tipping fully toward the camera like a light glow. Axis-billboarded materials still read the texture's own alpha classification (scissor for hard-edge cutouts like trees, blend for soft ones like flame) and dim with `csky_world_light` UNLESS the texture is a light source (the same `glowTexture` delegate the legacy fallback uses — see the WorldBuilder bullet for the 2026-07-21 widening that catches the refinery's `fire101.tif` flame, previously rendered fully static since it isn't `*flare*`-named). **Cylindrical facades are NOT recentered on their quad centroid (2026-07-21)** — camera-*facing* sprites (clouds up to ~650 m off origin, spherical glow flares) still are, but a single-axis facade spins about its model origin, so a quad offset perpendicular to that axis **orbits** it, and that orbit is the authored effect: it is how C1's lighthouse beam sweeps (`litehsflare`, a 19 m quad centred 6 m off the tower axis, so the lamp reads as lit from every direction — user-reported), how the hangar/street lamps hang off their poles (`fireflare1`, 2.58–3.6 m) and how a muzzle flash sits at the barrel tip instead of the gun's pivot (`nosegun1`, 2.4 m). Recentering collapsed all three to a sprite spinning in place, leaving the lighthouse glow visibly detached beside the tower when viewed off-axis. Surveyed across all 8 chapters: exactly those three families are affected (83 of 436 cylindrical facades); the other 353 have a zero or purely on-axis offset, so nothing else moves. A legacy v0.6.1 extraction (no `ModelType` data) falls back to the original single-polygon + flare-texture-name heuristic for the spherical case only — no cylindrical fallback existed before, so nothing regresses. Non-sprite geometry: optional trimesh collision + `collisionSkip`; `cullBackfaces` honors SHOW_BACKFACE via `cull_front`; cylindrical distance fog (horizontal distance × altitude fade) via global `csky_fog_*` params + per-instance `csky_fog_on` opt-out. **Fullbright world brightness (item 6):** the `!shaded` branch multiplies texture × vertex colour in **gamma (sRGB) space** (linearises COLOR first via `SrgbToLinearFn` — matches the original DX7 `D3DTOP_MODULATE`, fixes washed-yellow → saturated-green terrain) and dims ALBEDO by the global `csky_world_light` scalar (the mission's SUNLIGHT brightness, before the fog mix). Planes (shaded) keep raw COLOR + full brightness. Same two fixes in the cloud-billboard + Clutter shaders. **Shaded (aircraft) surfaces negate the normal in the vertex stage** (`NORMAL = -normalize(...)`, 2026-07-20) to cancel Godot's back-face normal flip, which `cull_front` makes universal on aircraft — see the `cull_front` entry under "Format gotchas". Fullbright emits the identical shader text it always did.
- `src/Mech3/PlaneBuilder.cs` — builds one aircraft (shaded, `cullBackfaces: true`); `Repaint(scheme)` re-liveries an already-built aircraft in place (fresh painter + `SceneBuilder.Repaint` over the recorded textured materials) for the livery lab's sliders: skips cockpit/destroyed/shadow/`*_hook` subtrees, `pcdpN` cockpit panels + `player_damage_off` (keeps the healthy `pdpN_h` panels — skipping them amputates wingtips). Flight builds — and `damagePanels: true` static builds (the `--damage` lab) — construct the exterior `pdpN` torn-skin panels hidden (`DamagePanels`, flipped by DamageVisuals — item 10c); the plain static viewer skips them. `BuildDestroyed` builds the `destroyed` wreck-piece subtree for CrashBreakup (item 10d). `spinningProps` toggles static disc vs blur layers; `*blur*` textures alpha-blend (scissor erases them). Wing flares built hidden, re-skinned as additive amber billboards, exposed as `WingFlares`.
- `src/Mech3/PaintScheme.cs` — one aircraft livery (2026-07-20): pattern name + three colours + three decal indices, the `paint_*` record from a vehicle.json def. `LoadCatalog(zrdr)` parses the **12 shipped patterns** out of vehicle.json (deduped by name; `player_fortune` ships colourless — the engine holds its colours — so it is filled with the paint UI's Fortune Hunters red). `Random()` draws a livery the way the shipped twelve are shaped — slot 1 an identity colour (half the time an actual squadron colour), slots 2/3 a dark and a light trim, mostly neutrals — because three independent random RGBs give clown planes. Decals: nose from the 21–49 nose-art range, tail/wing from the 00–20 squadron logos.
- `src/Mech3/PatternLibrary.cs` — the original's paint patterns, read from the extracted UI archive (`extracted/rof/ASSETS/GRAPHICS/<PATTERN>/`, produced by `ExtractRof.ps1`; format in `docs/formats/rof.md`). `PaintBitmap.Load` decodes one `.BM` — u16 height then u16 width, then w×h×10 bytes of planes: RGB shading map, three 8-bit per-slot weight masks summing to 255, and a 32bpp overlay. **A pattern is per aircraft:** `FORTUNE` covers all eleven, every other one covers one to three, so `PatternsFor(prefix)` is exactly the list the original's paint UI offers for that plane (the Fury's four match the user's four Fury reference screenshots). Missing extraction = empty library + one line saying to run `ExtractRof.ps1`; aircraft then build unpainted rather than failing.
- `src/Mech3/PlanePainter.cs` — applies a scheme to one aircraft (2026-07-20): paints its skins from the pattern's own region masks and swaps the three decal placeholders. Built per plane instance, so two players in the same aircraft wear different liveries; **never mutates the shared TextureArchive cache**. Composite is the original's: `shading × (w1·c1 + w2·c2 + w3·c3) / 255` with the overlay over the top. - `src/Mech3/AnimRuntime.cs` — **the animation engine** (replaces the old start-state-only `MissionState`, whose node resolution and INACTIVE semantics it keeps verbatim). Bootstrap is the same four passes (anchored RESET_STATEs → `ON_STARTUP` defs → the mission's `startanims` in order → the logged safety net hiding uncovered `*destroyed*` subtrees), but passes 2–3 now **run** rather than posing an end state: a def becomes a live instance with a clock. Sequences of one def run **concurrently** (the C1 train drives its four cars from four sibling sequences); event scheduling follows `start.offset` ∈ Animation/Sequence/Event with an absent `start` meaning "when the previous event completes" (which is what makes the train's `[SiScript, Loop{-1}]` a 327 s loop instead of a tight spin). Handlers are a **dispatch table**: active/translate/rotate/scale states, `ObjectMotionFromTo` tweens, `ObjectMotionSiScript` playback, and the control flow (`Loop`/`If`/`Elseif`/`Else`/`Endif`/`CallSequence`/`CallAnimation`/`StopAnimation`); every other kind is counted and reported once, never fatal — that is what lets the rest land incrementally. **`CallAnimation` honours its target node (2026-07-21):** a call may name another node to run the callee on (`WITH_NODE` 29,633 / `AT_NODE` 7,640 / `OPERAND_NODE` 179 sites), which is the data's **template-instancing** mechanism — one generic def serving many sites, and how the effect templates get placed. Resolved by `CallTargetAnchor` in the *caller's* namespace; an unresolvable target falls back to the caller's anchor (the pre-change behaviour, so a skipped node can't delete an effect) and is counted. The `IsLive` guard uses the **resolved** anchor, or a second site would be swallowed as a duplicate of the first. Reported as `anim: N call(s) retargeted onto a named node`; `--debug-anim` names each distinct (callee, target, caller) triple once. **One motion per node, last registration wins** (C1/IA1's startanims deliberately drive the same hangar doors twice). **`SpinMotion` is live (2026-07-22):** `OBJECT_MOTION`'s rotation half — a steady spin about the node's own axes, which turns the zeppelin nacelle props (`spin`/`counterspin`, ∓40°/+30°/s counter-rotating) and the rotating signage. Endless unless the event gives a `RUN_TIME` (580 of 590 do not), and re-assertion is **idempotent** — these live inside `Loop{-1}` sequences, so rebuilding per frame would restart the clock and leave the prop nearly still while logging as perfectly driven. `OBJECT_MOTION`'s *other* halves — ballistic debris (gravity/bounce) and a scale ramp — are counted, not implemented: both are reachable only from `OnCall`/`WeaponHit`, and no chapter dispatches a single one. **`If`/`Elseif` conditions are evaluated (2026-07-21, follow-up plan item 1)** — all ten kinds the data uses, via `EvaluateCondition` + a per-open-IF branch-taken stack in `SequenceRunner` (a pure skip-to-`Endif` cannot express "the ELSE runs when the IF didn't"): `AnimationLod` is answered by the project's own `QualityLod` (`--anim-lod=N`, default 2 = the only tier the data asks for, so every LOD-gated branch runs), `PlayerRange` compares squared distance from `PlayerPosition` (P1's camera), `RandomWeight` rolls dice, `NodeActive`/`NodeBelowAlt` read live scene state, `AnimHealth`/`AnimHealthRange` are false at an undamaged object's full health, `HwRender` true, `PlayerFirstPerson` false, `NodeUndercover` stubbed false (needs an occlusion probe; all 473 uses are `ON_CALL`). Per-kind true/false tallies are logged after the bootstrap and `--debug-anim` prints every verdict FLIP. Evaluating conditions is also what made the data's **poll idiom** live (`If <cond> → CallAnimation; Endif; Loop{-1}`, e.g. C1/MP1's rearm-bay door firing when the player closes to 25 m), so `CallAnimation` no longer restarts an animation already running on the same anchor — restarting pinned that 2 s door at frame 0 for as long as you hovered. `CallAnimation` chains are depth-capped (the data can cycle). **`LightState`/`LightAnimation` are live (2026-07-21):** the world's point lights, keyed `(light name, anchor)` and applied as **partial updates** — a fire's flicker is a stream of `{name, range}` events that must not reset position/colour/active state. Delivered to the renderer through `WorldLights`. The host node's resolution is **cached per light**: these fire ~2,700×/s on C1 (each flicker re-issues its full event, `AT_NODE` included), and resolving that name per event drove ~1,740 full-world scans/second and ~7 ms/frame on its own. **`PufferState` is live (2026-07-21):** one emitter per (puffer name, host node) attached at the event's `at_node`, built through a `PufferFactory` the caller supplies — a puffer bakes its texture atlas at construction and the session `TextureArchive` is disposed when the build ends, so the factory is cleared afterwards and a later request is reported rather than faulting. Re-assertion is **idempotent** (definitions re-assert their puffers on every loop iteration), and a payload carrying no textures is an adjust/stop stub referencing a puffer defined elsewhere, skipped by name. `--debug-anim` logs every live motion's pose **and whether it is visible in tree** once a second for headless verification — a correctly-animated node inside a deactivated subtree moves perfectly and renders nothing, which is worth being able to tell apart.

### Format gotchas (the ones that bite constantly)

- `nodes.json` `children`/`parent` are **flat list positions**, NOT the `node_index` field (node_index has duplicates).
- Euler `transformation.rotation` composes **R = Ry(y)·Rx(x)·Rz(z)** = Godot's `EulerOrder.Yxz`; when `matrix` is present it wins and is stored **transposed**.
- Coordinates are right-handed Y-up with the nose at **−Z** — Godot's frame exactly; no mirroring, no UV V-flip.
- `meshes.json` has `null` entries — keep them to preserve `mesh_index` alignment.
- Texture name quirks: fixed-width 20-char truncation (prefix-match) and mech3ax duplicate renames (strip `.-N` suffix). Plane skin pixels are in each chapter's `texture.zbd`, not planes.zbd.
- **Plane skins ship UNPAINTED** — they are shading maps carrying paint-region keys, which the engine recolours with the scheme's `paint_color1..3` at load time. Rendering them raw gives the desaturated blue-gray Bloodhawk instead of the original's red. **Implemented 2026-07-20** (`PlanePainter`); the region keys are NOT palette index ranges (that earlier reading is corrected in `docs/formats/paint.md` — the palettes are plain luminance-sorted quantizer output). The remake currently substitutes a hand-authored per-aircraft hue-window table — **superseded but not yet reworked:** the original's real region masks were found 2026-07-20 in `crimson.rof` (per-pattern, per-skin, three per-pixel weight masks summing to 255; `docs/formats/rof.md`), extracted by `ExtractRof.ps1`. Rework is deliberately a separate session. Likewise `*_noselogo`/`*_taillogo`/`*_winglogo` are 16×16 **placeholders**, not artwork — the real decal is one of the numbered 00–49 textures picked by `paint_decalN` (not every plane has all three: no `fir_noselogo`).
- Per-corner `vertex_colors` = **baked lighting** (really an AO/shadow mask — 70% pure white, 30% darker): the world renders fullbright (texture × vertex color); shaded comes out murky-dark. Some polys are baked pure black on purpose (painted shadows). **The multiply is gamma-space (item 6):** the original DX7 engine multiplied texture × vertex color in sRGB space; our linear-space multiply washes out the baked-dark corners, so the fullbright shaders linearise the vertex color first (`SrgbToLinearFn`). On top of the vertex colors the original applies the mission's **SUNLIGHT** (weather.json) as a per-mission brightness — the remake's `csky_world_light` (item 6).
- Polygons carry a signed **draw priority** (v0.6.1 `unk04`, upstream `priority`); equal priorities resolve by **draw order, later wins** (polygon list order within a mesh, flat nodes.json order across nodes). Ignoring either z-fights every decal — SceneBuilder maps both to depth bias.
- Polygon flag `unk2` (upstream `SHOW_BACKFACE`, bit 0) = double-sided; without it the original backface-culls. The visible side is the CCW loop = Godot's *back* face → `cull_front`.
- **That `cull_front` inverts aircraft lighting unless you cancel it (2026-07-20).** Because the visible side is Godot's back face, *every* visible aircraft fragment is back-facing — and Godot negates `NORMAL` on back faces. The file's normals are correct (measured: 0 of 1827 Fury triangles disagree with their winding, no mirrored nodes), but they arrive at the light calculation pointing into the airframe, so every upward surface shades as if lit from below. SceneBuilder's **shaded** path therefore emits `NORMAL = -normalize(...)`; the fullbright world never reads NORMAL and is untouched. Don't "simplify" that minus away.

Full validated format documentation lives in `docs/formats/` (13 pages; **`README.md` is the index + shared reader conventions** — start there): `gamez.md` (GameZ/planes.zbd structure, aircraft trees, damage states, node kinds), `world-structure.md` (chapter worlds, skydome zones, point-sprite lights), `zrdr.md` (the reader archives: three scopes + per-family index), `vehicle.md` (vehicle defs: dynamics/engines, destroyable_parts/injure_anims damage model, the 6-point collision block), `spawns.md` (ia/PLAYER_INIT + campaign mission↔folder map), `missions.md` (stunt `dzones` Danger Zones, targets.json node→string keys, the messages.json string table), `sounds.md` (SETS, player curves, MS-ADPCM), `weather.md` (weather.json blocks, dual color encoding, SUNLIGHT), `anim-definitions.md` (ANIMATION_DEFINITION schema + cam_anim survey), `effects.md` (PUFFER_STATE schema + effects survey), `clutter.md` (interp.json templates), `hud.md` (compass tape + cockpit gauges), `paint.md` (paint schemes/colours/decals — why shipped skins are unpainted key textures), `rof.md` (the `.rof` UI resource archives + the `.BM` texture format carrying the paint region masks), `strings.md` (the `langui.dll` UI string table — aircraft names + descriptions). **Rule: new decodes land with their docs page in the same change.**
