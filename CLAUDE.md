## Project Description

An XWVM-style remake of **Crimson Skies** (2000, Zipper Interactive, Microsoft): a modern engine that plays the original game using the player's own legally-owned game files. Nothing like this exists yet for Crimson Skies — this is a first-of-its-kind effort.

Charter decided 2026-07-14 (full detail in Claude's project memory):

- **Milestone 1** — complete asset extraction: fill the Crimson Skies gaps in mech3ax (`planes.zbd`, `gamez.zbd`).
- **Milestone 2** — vertical slice: free flight only. One plane, one map (candidate: C1 instant-action arena), arcade controls, original sounds. No AI, objectives, or weapons.
- Long-term direction (not commitment): full campaign remake.

## 🚫 Hard rule: no game assets in version control — ever

Public open-source project under the **XWVM legal model**: the repo ships **code and format documentation only**. Game files, extracted assets, ZBD contents, screenshots of hexdumps containing bulk asset data — none of it gets committed or published. The importer reads the player's own install at runtime. `.gitignore` enforces this for `CrimsonSkiesGame/`, `extracted/`, and `tools/`; keep it that way when adding directories.

## Scratch / probe output

When generating temporary artifacts — probe images, screenshots, rendered
previews, debug dumps, golden-test captures, etc. — always write them into
`./.scratch/` inside this workspace. Create the folder if it doesn't exist.

- Do NOT write scratch output to the OS temp directory
  (e.g. AppData\Local\Temp\claude\...). Files there aren't reachable from
  VS Code's Explorer and clickable links to them don't resolve.
- Use descriptive filenames (e.g. `probe_full.png`, `zbd_texture_dump_01.png`)
  rather than UUIDs, so they're easy to find in the sidebar.
- When you produce such a file, print its workspace-relative path
  (e.g. `./.scratch/probe_full.png`) so it can be opened directly.

## Architecture & key decisions

- **Engine:** Godot 4 .NET (C#). Consumes extraction output via mech3ax / Mech3DotNet (strongly-typed C# wrapper).
- **Format reverse engineering:** happens in a fork of [mech3ax](https://github.com/TerranMechworks/mech3ax) (Rust), PR'd upstream to TerranMechworks. Their byte-identical round-trip test harness (extract→repack) is the correctness standard.
- **Flight model:** data-driven approximation — parameterized by plane stats from extracted zrdr reader files, hand-tuned against the original game. No exe decompilation.
- **Division of labor:** Claude writes the Rust parsers, Godot code, and docs; the user reviews, playtests flight feel, and owns upstream/community communication.

## Repo layout

- `CrimsonSkies/` — the Godot 4 .NET project (the actual remake; committed). See "Godot project" below.
- `CrimsonSkiesGame/` — the user's retail game install (git-ignored). ZBD archives in `CrimsonSkiesGame/ZBD/` organized as campaign chapters `C1`–`C5`, each with instant action (`IA1`), story missions (`M0x`), multiplayer maps (`MP1`–`3`). Cutscenes are plain MPGs in `CrimsonSkiesGame/GOSDATA/ASSETS/GRAPHICS/MPG/`.
- `extracted/` — extraction output workdir (git-ignored). Populated by `ExtractAssets.ps1` (below), which mirrors the game's ZBD folder structure: top-level `planes.zip` (unzbd of planes.zbd), `zrdr.zip`, `soundsh.zip`/`soundsl.zip`, `interp.json`, `rimage.zip`, plus per-chapter `C1/gamez.zip`, `C1/texture.zip`, `C1/rtexture*.zip`, `C1/zrdr.zip`, and per-mission `C1/IA1/zrdr.zip` etc. The viewer's defaults read `planes.zip`, `C1/gamez.zip`, `C1/texture.zip`, `zrdr.zip`, `soundsh.zip` — but for each default it **prefers the unpacked sibling folder when present** (e.g. reads `extracted/C1/texture/` over `C1/texture.zip`), so running `ExtractAssets.ps1 -Unzip` (or unzipping just the archives you want to grep in the editor) makes the viewer load loose files and skip zip decompression. All four loaders (`GameZ`, `TextureArchive`, `Zrdr`, `SoundArchive`) accept a zip or a directory; an explicit `--gamez=`/`--textures=`/`--zrdr=`/`--sounds=` is used verbatim. **The `rtexture*`/`rimage` archives are NOT loaded, by design (verified Run-2 item 2):** each `rtextureN.zip` is a **downscaled quality tier** of the same texture set, not a hi-res replacement — measured across all 896 C5 textures, `texture` == `rtexture14` (both max-res), `rtexture2` = ¼, `rtexture4/6/8` = ½, and no rtexture file ever exceeds `texture`; so the base `texture.zip` the viewer loads is already the highest resolution. `rimage.zip` is the UI/HUD image set (crosshairs, buttons, cursor, menu splash, briefing thumbnails), no world geometry textures. **`extracted/rof/`** is produced by the separate `ExtractRof.ps1` (not `ExtractAssets.ps1`) and holds the unpacked `.rof` UI archives + `ui_strings.json`; nothing in the Godot project loads it yet.
- `ExtractAssets.ps1` (repo root) — bulk extractor: walks `CrimsonSkiesGame/ZBD`, runs `unzbd cs <mode>` on every ZBD with the right mode for its type (interp→interp/.json; planes+gamez→gamez; soundsh/soundsl→sounds; zrdr→reader; rimage/texture/rtexture*→textures), and writes the output to the mirrored relative path under `extracted/` (basename kept, extension → `.zip`, or `.json` for interp). `cam_anim.zbd`/`mis_anim.zbd` are reported+skipped (mech3ax has no CS anim support). Idempotent (skips outputs newer than their source unless `-Force`); `-Unzip` also expands each `.zip` into a sibling folder; `-Source`/`-Dest` override the roots.
- `ExtractRof.ps1` (repo root) — extractor for the **non-ZBD** half of the install (2026-07-20): the `.rof` UI resource archives (`GOSDATA/ASSETS/crimson.rof` + the `crimptch.rof` patch overlay) and the `langui.dll`/`language.dll` Win32 string tables, into `extracted/rof/`. Writes every archive member at its archive path, decodes each custom `.BM` texture to `<name>.png` (greyscale shading map) + `<name>_mask.png` (**the paint region masks** — R/G/B = paint slots 1/2/3), and emits `ui_strings.json` (every UI string joined to its `RESOURCE.H` symbol — this is where the aircraft names + description text live). `-Raw` skips the decoding and the string table, `-Force` re-runs an up-to-date extraction, `-Source`/`-Dest` override the roots. The decode work is an inline C# type (`Add-Type`), so a full run is ~1.5 s. Formats: `docs/formats/rof.md`, `docs/formats/strings.md`.
- `RunDev.ps1` (repo root) — **dev** build + launch helper (console prompts): `dotnet build`, then Godot with the forwarded viewer args. No args = interactive **console** menus (plane roster + chapter), then `--fly`; `--fly`/extra flight flags prompt for whatever's missing; bare `--plane=X` / `--chapter[=X]` static views pass through promptless; `--damage[=…]` is its own static flow — prompts only for the plane, never adds `--fly`/`--chapter` (combined with an explicit `--fly`/`--chapter` it passes through verbatim and the viewer ignores it with a note).
- `RunGame.ps1` (repo root) — **play** entry point (M2.5 item 4): `dotnet build`, then Godot with **no user args**, so the in-game launchscreen (Mode → Chapter → Plane; see `src/UI/LaunchMenu.cs`) shows. Any args you pass are forwarded verbatim, so an explicit content arg (`--fly`/`--stunt`/`--plane=`/`--chapter=`/`--screenshot=`) bypasses the launchscreen and builds directly. No console prompts (unlike RunDev.ps1). **Both Run scripts set `SDL_JOYSTICK_DIRECTINPUT=0`** (respecting a pre-set value) — the controller-disconnect freeze workaround (2026-07-19, see backlog "Drop the SDL_JOYSTICK_DIRECTINPUT=0 workaround"): Godot's bundled SDL hangs the main thread forever when a >255-button DirectInput device (the 8BitDo Ultimate 2 dongle) disconnects; disabling the dinput backend removes those phantom views, real pads keep working via XInput/HIDAPI. Direct editor/exe launches don't get the workaround.

## Godot project (`CrimsonSkies/`)

Godot 4.7 .NET, C# / net8.0. Build & run:

```
dotnet build CrimsonSkies/CrimsonSkies.sln
tools/godot/.../Godot_v4.7-stable_mono_win64_console.exe --path CrimsonSkies res://scenes/Main.tscn -- --plane=player_bhawk
```

(First time only: run with `--headless --import` once before running scenes.)

Compact module index — **deep implementation notes, verified diagnoses, and dead ends for every module live in `docs/architecture.md`; read that module's bullet before changing it.**

- `src/Mech3/GameZ.cs` — loads a mech3ax GameZ extraction (zip or unpacked dir): nodes/meshes/materials JSON → plain C# objects, incl. World partition refs, per-corner vertex colors, mesh `lights` arrays, per-polygon draw priority (`unk04`/`priority`, both keys), each node's flat `Index` (= original draw order), and the World's `area` ground-plane bounds + partition-grid dims (for WorldBuilder's map-edge continuation). `WorldTransformOf(node)` accumulates a node's world transform up its parent chain (used to resolve the stunt `dzN` marker positions without building the skipped marker nodes).
- `src/Mech3/TextureArchive.cs` — texture lookup (zip or dir), handles the two name quirks; classifies alpha per texture (`LastHadAlpha`/`LastAlphaIsSoft` — soft alpha must blend, scissor destroys it). Missing names logged once (plain lines, never `GD.PushWarning`); known-absent-from-game-data textures (`pir_spinner`, `barngrill`) render neutral gray, so magenta = our bug.
- `src/Mech3/SceneBuilder.cs` — shared GameZ-subtree → MeshInstance3D builder (`textureSubstitute` hook: every material's resolved texture passes through it, which is how PlanePainter swaps in a recoloured skin or a decal per aircraft — `Find` still runs, since it is what sets the alpha classification the blend/scissor choice reads): n-gon triangulation, nearest LOD, one surface per (material, priority). Replicates the original's coplanar layering as scale-invariant depth bias (priority × 2e-4 + within-mesh surface rank × 2e-6 + node index × 5e-8 as an `instance uniform` — needs Forward+; `project.godot` raises the global-shader-variable buffer to 262144 for C4/C5 instance counts). Soft-alpha textures auto-blend, others scissor; `billboardTexture` predicate for cloud sprites (recentered on quad centroid; own billboard `ShaderMaterial` that shares the distance fog — item 4); mesh point-lights as camera-facing soft glow sprites (own point shader: gaussian falloff, ×1.6 gain, distance-sized 3–30 px; per-light decoded size/range params — range fade keeps beacons inside the fog, skydome stars exempt via `csky_light_fade`); `glowTexture` predicate → the world's single-quad `*flare*` lamp meshes (refinery/pier/lighthouse) billboard via a glow shader variant (always blend, no night dim, non-collidable — flare polys inside regular geometry and multi-poly flare strings stay static); optional trimesh collision + `collisionSkip`; `cullBackfaces` honors SHOW_BACKFACE via `cull_front`; cylindrical distance fog (horizontal distance × altitude fade) via global `csky_fog_*` params + per-instance `csky_fog_on` opt-out. **Fullbright world brightness (item 6):** the `!shaded` branch multiplies texture × vertex colour in **gamma (sRGB) space** (linearises COLOR first via `SrgbToLinearFn` — matches the original DX7 `D3DTOP_MODULATE`, fixes washed-yellow → saturated-green terrain) and dims ALBEDO by the global `csky_world_light` scalar (the mission's SUNLIGHT brightness, before the fog mix). Planes (shaded) keep raw COLOR + full brightness. Same two fixes in the cloud-billboard + Clutter shaders. **Shaded (aircraft) surfaces negate the normal in the vertex stage** (`NORMAL = -normalize(...)`, 2026-07-20) to cancel Godot's back-face normal flip, which `cull_front` makes universal on aircraft — see the `cull_front` entry under "Format gotchas". Fullbright emits the identical shader text it always did.
- `src/Mech3/PlaneBuilder.cs` — builds one aircraft (shaded, `cullBackfaces: true`); `Repaint(scheme)` re-liveries an already-built aircraft in place (fresh painter + `SceneBuilder.Repaint` over the recorded textured materials) for the livery lab's sliders: skips cockpit/destroyed/shadow/`*_hook` subtrees, `pcdpN` cockpit panels + `player_damage_off` (keeps the healthy `pdpN_h` panels — skipping them amputates wingtips). Flight builds — and `damagePanels: true` static builds (the `--damage` lab) — construct the exterior `pdpN` torn-skin panels hidden (`DamagePanels`, flipped by DamageVisuals — item 10c); the plain static viewer skips them. `BuildDestroyed` builds the `destroyed` wreck-piece subtree for CrashBreakup (item 10d). `spinningProps` toggles static disc vs blur layers; `*blur*` textures alpha-blend (scissor erases them). Wing flares built hidden, re-skinned as additive amber billboards, exposed as `WingFlares`.
- `src/Mech3/PaintScheme.cs` — one aircraft livery (2026-07-20): pattern name + three colours + three decal indices, the `paint_*` record from a vehicle.json def. `LoadCatalog(zrdr)` parses the **12 shipped patterns** out of vehicle.json (deduped by name; `player_fortune` ships colourless — the engine holds its colours — so it is filled with the paint UI's Fortune Hunters red). `Random()` draws a livery the way the shipped twelve are shaped — slot 1 an identity colour (half the time an actual squadron colour), slots 2/3 a dark and a light trim, mostly neutrals — because three independent random RGBs give clown planes. Decals: nose from the 21–49 nose-art range, tail/wing from the 00–20 squadron logos.
- `src/Mech3/PatternLibrary.cs` — the original's paint patterns, read from the extracted UI archive (`extracted/rof/ASSETS/GRAPHICS/<PATTERN>/`, produced by `ExtractRof.ps1`; format in `docs/formats/rof.md`). `PaintBitmap.Load` decodes one `.BM` — u16 height then u16 width, then w×h×10 bytes of planes: RGB shading map, three 8-bit per-slot weight masks summing to 255, and a 32bpp overlay. **A pattern is per aircraft:** `FORTUNE` covers all eleven, every other one covers one to three, so `PatternsFor(prefix)` is exactly the list the original's paint UI offers for that plane (the Fury's four match the user's four Fury reference screenshots). Missing extraction = empty library + one line saying to run `ExtractRof.ps1`; aircraft then build unpainted rather than failing.
- `src/Mech3/PlanePainter.cs` — applies a scheme to one aircraft (2026-07-20): paints its skins from the pattern's own region masks and swaps the three decal placeholders. Built per plane instance, so two players in the same aircraft wear different liveries; **never mutates the shared TextureArchive cache**. Composite is the original's: `shading × (w1·c1 + w2·c2 + w3·c3) / 255` with the overlay over the top. Two load-bearing details: the shading map is the **`.BM`'s own base plane, not the ZBD skin** of the same name (different images), and **`.BM` rows are stored bottom-up** so every source row is read from `h-1-y` — without that every livery is mirrored along V (user-reported: "the stripes are on the wrong sides of the wings and tail"; settled by edge-correlation across all 55 same-sized FORTUNE/ZBD pairs, flipV 24:3 among the discriminating ones). Parts a pattern ships no `.BM` for keep the ZBD texture; the ZBD alpha is carried onto the composite where dimensions agree, so SceneBuilder's blend/scissor choice stays valid. `PrefixFor` reads the aircraft's skin prefix off its own `*_noselogo`/`*_taillogo`/`*_winglogo` materials — **any of the three**, the Firebrand ships no `fir_noselogo`. Replaced a hand-authored hue-window table written when the region data was believed absent; that version could not paint colourless regions or the Fury at all, guessed slot order, and was slower (per-texel HSV + percentile vs a flat multiply-add).
- `src/Mech3/PropParts.cs` — classifies prop/rotor nodes by name; spin axis + rate from the original anims (props local Z, −220/+60; autogyro rotor local Y, +165/−60; treated as deg/s, TUNE).
- `src/Mech3/ControlSurfaces.cs` — classifies aileron/elevator/rudder mesh nodes (deflecting child under hinge-parent group; parents must NOT classify) + hinge axes (local X ailerons/elevators, local Y rudders). No deflection data exists — angles/rates are TUNE in the animator.
- `src/Mech3/WingLights.cs` — single source of truth for wingtip nav lights: flare node names, `oil_liteflare` glow texture, warm-amber color, 1.5 s blink period. Treatment scoped by node name, not texture (texture is shared with airframe meshes).
- `src/Mech3/WorldBuilder.cs` — builds a chapter world (fullbright): World children + partition-referenced subtrees; skips `horizon`/`fvol*`/`dzpaths`. Cloud/sky classified by **texture** (blend + billboard the sprites, exempt from collision); the opaque `cloudlayer` deck split into a separate `CloudDeck` node for the player-follow. `BuildHorizon(zone)` = camera-anchored skydome (zone2 night default; billboarded color-keyed moon; participates in fog since the 2026-07-17 cylinder remodel — `DisableFog` is disabled by an early return). `CreateEdgeExtender(clutter)` (after Build) returns the item-7 `MapEdgeExtender`. `BuildDzPaths()` builds the skipped `dzpaths` route ribbons for `--debug-dzpaths` only.
- `src/Mech3/MapEdgeExtender.cs` — **map-edge continuation (item 7):** a rolling window of repeated border tiles + clutter following the camera past the map boundary indefinitely, like the original's tile-reload grid (user video + in-game tests). Each axis outside the map **clamps to its border cell**, repeated forever and **alternately reflected** (every seam a shared mirror plane — heights match exactly; the interior never repeats, so no phantom airport; sea edge → sea forever, forest → forest). The reflection is our seam-free construction, likely NOT what the original does (user: plain repetition — open fidelity question, NOTES.md; one-line swap in `MirrorAxis`). Window = cells within `Rings`=5 of the camera cell (covers raw fog-far + a margin ring so the original's visible reload pop never shows), re-diffed only on 1024 m cell crossings; cells = bare ground leaves (no buildings) + the source cell's clutter sprites at mirrored positions, both collidable in flight. Active in `--fly` and static `--sky-zone` views; off for plain orbit viewing. `Update` takes a **list** of focus points (one per player camera, M2.5 item 5) and builds the union of their ring neighbourhoods, so one window serves every splitscreen pane.
- `src/Mech3/Clutter.cs` — the original's clutter system: interp.json `AddClutterTemplates` templates (ground quad whose texture names the terrain it decorates, size = tiling period) stamped across matching-textured world polygons on a fixed world-space grid (C1: 9,303 tree/bush sprites). One Y-billboard MultiMesh per decoration kind, fullbright + fogged (+ item-6 gamma-space vertex modulate + `csky_world_light` SUNLIGHT dimming, like the world); crossed-quad trimesh colliders in flight. C2/C5 non-quad city-block templates logged + skipped. `ExportedKinds` feeds MapEdgeExtender (same trees on the repeated border tiles).
- `src/Mech3/Zrdr.cs` — zrdr extraction reader (zip or dir) + `ZrdrDict` view over alternating key/[values…] lists (collapses duplicate keys — anim defs walk raw lists instead); `LoadMatchingFiles` enumerates an archive's readers by content sniff.
- `src/Mech3/Messages.cs` — the game's localized string table (M2.5 item 1). **Not a zrdr** — a single top-level `messages.json` object (`{entries:[{key,id,value}]}`, plain JSON); `Get(key)` → value or the raw key if unknown. Resolves the `MSG_*` keys targets.json references. See `docs/formats/missions.md`.
- `src/Mech3/AnimDefs.cs` — ANIMATION_DEFINITION loader (item 8): parses every def in a zrdr archive (name/root/activation, RESET_STATE, sequences) keeping only the four *state* op kinds (active/translate/rotate/motion-end-pose); playback ops recorded + skipped (part 2). Schema: `docs/formats/anim-definitions.md`.
- `src/Mech3/MissionState.cs` — mission start-state applier (item 8): at world build applies anchored defs' RESET_STATEs (healthy ACTIVE / destroyed INACTIVE — the coplanar-flicker fix), ON_STARTUP sequences (zepstate.json — C1/IA1 hides `dliner1`/`cargotrain`), startanims.json NEW_GAME_START end-states in order (hangar 3 doors end open), then a logged safety net hiding uncovered `*destroyed*` subtrees (name-contains only — a `*_dest` suffix rule wrongly hid `ref_tank_dest`, the healthy harbor tank GROUP; reverted). INACTIVE = hidden + colliders disabled. Anchors by wildcard NAME (`*`/`**`/`#`, `.flt` optional) or ANIMATION_ROOT_NAME→parent lift capped at 16 matches (generic `healthy` roots = per-object anims, never world-anchored); resolves via the `cs_name` meta (original gamez names — Godot mangles duplicates). Runs in every world build (fly + static). Scenarios don't change world state (analysis in the format page).
- `src/Mech3/WavFile.cs` — pure-C# WAV parser + MS ADPCM→PCM16 decoder (the game's format; Godot can't load it).
- `src/Mech3/SoundArchive.cs` — WAV lookup over a sounds extraction → cached `AudioStreamWav` (forward loop when LOOPED).
- `src/Mech3/SoundDefs.cs` — sounds.json SETS parser: `snd_*` → `SoundDef` (wav, flags, range, volume).
- `src/Flight/PlaneStats.cs` — typed per-plane flight stats from vehicle.json (`kind_of` chain) + engines.json + player.json globals, incl. engine-sound def + volume/pitch curves, `destroyable_parts` (per-part HP/flags/injure thresholds) and the def-level injure anims (item 10b; see `docs/formats/vehicle.md`).
- `src/Flight/SpawnPoints.cs` — flight spawns from the **mission's own zrdr**: `LoadIa` (ia.json `spawn_points`, random pick) with `LoadPlayerInit` (objectives.json PLAYER_INIT) as story-mission fallback.
- `src/Flight/MissionTargets.cs` — mission `targets.json` loader (M2.5 item 1): world-node NAME → objective display keys (`description`/`category_label`/`help_label`). A **list of `[key,value]` pairs**, not the flat-alternating reader shape (walked as pairs). Generic across mission types; resolve keys via `Messages`. Schema: `docs/formats/missions.md`.
- `src/Flight/StuntMission.cs` — the Stunt Flying mode state (M2.5 items 1–3). `Load(worldGamez, missionZrdr, messages)` builds the zone list from ia.json `dzones` (drives off the **list**, not every `dzN` — numbering is non-contiguous; C1's gamez `dz6` isn't an objective), resolving each `dzN` world position via `GameZ.WorldTransformOf` + strings via MissionTargets/Messages. `Update(planePos)` (each physics frame) completes a zone within `DzRadius` (30 m TUNE), order-free, auto-advances the active target, fires `RunCompleted`/`AllComplete`. `MarkerText` = "Danger Zone [Fly Through] - <name>". Item 2 added `Tick(dt)` (advances the `Elapsed` run clock each physics frame — through the crash freeze, stops at `AllComplete`), `CycleTarget()` (points the HUD at the next incomplete zone, wrapping), and `IntroLine` (the resolved run-start banner). Item 3 (scoring): `Complete` stamps each zone's `CompletedAt`/`CompletionOrder`, `InCompletionOrder()` yields the flown order for the scoreboard's splits, `Reset()` starts a fresh run (clock + zones cleared — used by the scoreboard's R), `FormatTime` is the shared `m:ss.t` formatter (InvariantCulture → period; MarkerHud delegates to it), `DebugCompleteAll()` force-completes for a screenshot. ### Format gotchas (the ones that bite constantly)

- `nodes.json` `children`/`parent` are **flat list positions**, NOT the `node_index` field (node_index has duplicates).
- Euler `transformation.rotation` composes **R = Ry(y)·Rx(x)·Rz(z)** = Godot's `EulerOrder.Yxz`; when `matrix` is present it wins and is stored **transposed**.
- Coordinates are right-handed Y-up with the nose at **−Z** — Godot's frame exactly; no mirroring, no UV V-flip.
- `meshes.json` has `null` entries — keep them to preserve `mesh_index` alignment.
- Texture name quirks: fixed-width 20-char truncation (prefix-match) and mech3ax duplicate renames (strip `.-N` suffix). Plane skin pixels are in each chapter's `texture.zbd`, not planes.zbd.
- **Plane skins ship UNPAINTED** — they are shading maps carrying paint-region keys, which the engine recolours with the scheme's `paint_color1..3` at load time. Rendering them raw gives the desaturated blue-gray Bloodhawk instead of the original's red. **Implemented 2026-07-20** (`PlanePainter`); the region keys are NOT palette index ranges (that earlier reading is corrected in `docs/formats/paint.md` — the palettes are plain luminance-sorted quantizer output). The remake currently substitutes a hand-authored per-aircraft hue-window table — **superseded but not yet reworked:** the original's real region masks were found 2026-07-20 in `crimson.rof` (per-pattern, per-skin, three per-pixel weight masks summing to 255; `docs/formats/rof.md`), extracted by `ExtractRof.ps1`. Rework is deliberately a separate session. Likewise `*_noselogo`/`*_taillogo`/`*_winglogo` are 16×16 **placeholders**, not artwork — the real decal is one of the numbered 00–49 textures picked by `paint_decalN` (not every plane has all three: no `fir_noselogo`).
- Per-corner `vertex_colors` = **baked lighting** (really an AO/shadow mask — 70% pure white, 30% darker): the world renders fullbright (texture × vertex color); shaded comes out murky-dark. Some polys are baked pure black on purpose (painted shadows). **The multiply is gamma-space (item 6):** the original DX7 engine multiplied texture × vertex color in sRGB space; our linear-space multiply washes out the baked-dark corners, so the fullbright shaders linearise the vertex color first (`SrgbToLinearFn`). On top of the vertex colors the original applies the mission's **SUNLIGHT** (weather.json) as a per-mission brightness — the remake's `csky_world_light` (item 6).
- Polygons carry a signed **draw priority** (v0.6.1 `unk04`, upstream `priority`); equal priorities resolve by **draw order, later wins** (polygon list order within a mesh, flat nodes.json order across nodes). Ignoring either z-fights every decal — SceneBuilder maps both to depth bias.
- Polygon flag `unk2` (upstream `SHOW_BACKFACE`, bit 0) = double-sided; without it the original backface-culls. The visible side is the CCW loop = Godot's *back* face → `cull_front`.
- **That `cull_front` inverts aircraft lighting unless you cancel it (2026-07-20).** Because the visible side is Godot's back face, *every* visible aircraft fragment is back-facing — and Godot negates `NORMAL` on back faces. The file's normals are correct (measured: 0 of 1827 Fury triangles disagree with their winding, no mirrored nodes), but they arrive at the light calculation pointing into the airframe, so every upward surface shades as if lit from below. SceneBuilder's **shaded** path therefore emits `NORMAL = -normalize(...)`; the fullbright world never reads NORMAL and is untouched. Don't "simplify" that minus away.

Full validated format documentation lives in `docs/formats/` (13 pages; **`README.md` is the index + shared reader conventions** — start there): `gamez.md` (GameZ/planes.zbd structure, aircraft trees, damage states, node kinds), `world-structure.md` (chapter worlds, skydome zones, point-sprite lights), `zrdr.md` (the reader archives: three scopes + per-family index), `vehicle.md` (vehicle defs: dynamics/engines, destroyable_parts/injure_anims damage model, the 6-point collision block), `spawns.md` (ia/PLAYER_INIT + campaign mission↔folder map), `missions.md` (stunt `dzones` Danger Zones, targets.json node→string keys, the messages.json string table), `sounds.md` (SETS, player curves, MS-ADPCM), `weather.md` (weather.json blocks, dual color encoding, SUNLIGHT), `anim-definitions.md` (ANIMATION_DEFINITION schema + cam_anim survey), `effects.md` (PUFFER_STATE schema + effects survey), `clutter.md` (interp.json templates), `hud.md` (compass tape + cockpit gauges), `paint.md` (paint schemes/colours/decals — why shipped skins are unpainted key textures), `rof.md` (the `.rof` UI resource archives + the `.BM` texture format carrying the paint region masks), `strings.md` (the `langui.dll` UI string table — aircraft names + descriptions). **Rule: new decodes land with their docs page in the same change.**
